渲染器只认识两样东西：DrawItem 列表和 LightDesc 列表。它不知道"实体"、不知道玩法、不知道场景文件。这条边界由一个 9 方法的 rhi::Device 接口守住，也是未来接第二个后端的唯一入口。

把 key light 拆成独立目标不是洁癖：阴影只在合成阶段乘一次，避免"直射项被重复加"的经典错误。关掉 DXR 时把 mask 清成 1，结果与纯光栅路径逐像素一致——不需要第二条渲染路径，也就不会出现"两条路径各自漂移"。

DXR 静态阴影

逐像素从深度重建世界坐标，发射一条硬阴影光线，把 0/1 可见性写进 R16_FLOAT 贴图。范围就是这么多：一条光线、二值可见性、静态几何。

项实现
着色器shaders/rt_shadows.hlsl：raygen / miss / closest-hit
编译DXC 1.9.2609 → lib_6_5 DXIL，内嵌进可执行文件
管线RTPSO（DXIL library + hit group + shader config + pipeline config + global root signature）
SBT192 字节 Shader Binding Table
加速结构单位方盒 BLAS 复用；TLAS 从当前帧刚体变换重建（本机 33 实例）
开关F10 · --rt-shadows on|off
回退mask 清 1，与纯光栅逐像素一致

报告字段刻意拆开：probeAvailable、dxcAvailable、requested、enabled、rtpsoCreated、sbtCreated、effectImplemented、fallbackUsed、shadowTextureBytes、dispatchedFrames、fallbackFrames、dispatchFailures、gpuRtMs、tlasInstances、tlasRebuilds。能力查询成功不等于效果完成，所以 capabilities.implemented.raytracing 只在本次运行真的派发过光线时才为 true。

Mesh Shader

AS + MS + PS 三阶段，stream PSO，单位方盒切成 6 个面 meshlet。顶点路径完整保留，F11 或 --mesh-shaders on|off 切换。

放大剔除当前禁用

meshlet 的放大剔除（amplification）因为 payload 一致性要求暂时关闭，并在报告里如实写 false。关闭不等于失败——但把它说成"已实现"就是失败。

纹理与槽位

材质表是 8 槽有界表：0 号为缺材质默认槽（品红棋盘），1–3 常驻，4–7 可分配，带代际计数与复用。越界或过期句柄返回诊断，不静默采样到错误纹理。

SM 6.6 的 ResourceDescriptorHeap[32..35] 直接堆索引已经验证与描述符表逐位一致（maxDelta = 0），但材质主路径仍走有界表——报告里写 bounded-table，不写"已迁移"。

Compute 队列

独立的 COMPUTE 队列，跨队列 fence 同步，cs_6_6 探针 240 帧派发 240 次、等待 240 次。当前计算结果尚未进入画面——它是管线能力的证据，不是效果。

边界

  • 只有一个后端；Device 不含资源/管线/多队列/绑定模型。
  • TLAS 每帧按刚体变换重建，不含蒙皮角色（dynamicBlas=false）。
  • 阴影无软阴影、无降噪、无透明投影、无点光源投影。
  • 没有 HZB、没有 GPU 剔除、没有 visibility buffer、没有 TAA。
  • 没有运行时 glTF 导入；网格来自内置方盒与离线导入的角色。
