玩法运行时是数据驱动的：C++ 提供组件与系统，行为写在 Lua 5.4.9 里，两者通过一份共享的字段契约连接。新增一把钥匙、一扇门、一个开关，不需要改 C++——但也不能偷偷绕过契约。

组件模型

assets/gameplay/components.json 是组件字段契约。原生 Registry、场景工具和 AI 共用它；未知类型或未知字段会被拒绝，不会静默丢弃。

{
  "components": {
    "interactable": { "range": 2.5, "prompt": "打开门" },
    "behavior": {
      "instances": [
        { "id": "lock", "script": "gameplay/locked_door",
          "properties": { "requiredItem": "silver_key" } }
      ]
    }
  }
}

同一脚本的多个实例各自拥有 properties / state / RNG；行为 ID 在同一实体上唯一。第二把钥匙和第二扇门不需要写第二份 C++。

实体身份

实体使用持久 ID；原生高频访问使用 index + generation 的 Handle。销毁后的 ID 不允许重新分配，旧句柄立即失效。查询按实体 ID 排序，保证遍历顺序确定。

行为描述文件

assets/scripts/<name>.behavior.json 声明：apiVersion: 1、正整数 version、properties / state 的字段 schema。持续更新的行为还要声明 update: true。

{
  "apiVersion": 1,
  "version": 3,
  "update": false,
  "dependencies": ["gameplay/common"],
  "properties": {
    "type": "object",
    "required": ["requiredItem"],
    "properties": { "requiredItem": { "type": "string" } }
  },
  "state": {
    "type": "object",
    "properties": { "opened": { "type": "boolean", "default": false } }
  }
}

schema 支持 object / array / boolean / string / integer / number、oneOf、required、default、enum、范围和数量上限，默认严格拒绝未知字段。dependencies 声明行为资源依赖，引擎与打包工具递归解析并拒绝循环——它不是 Lua 的 require。

Lua 回调

return {
  on_start = function(ctx)
    ctx:timer("pulse", 120, "pulse", {}, 120)
  end,
  on_event = function(ctx, event)
    if event.name == "pulse" then
      ctx.state.count = ctx.state.count + 1
    end
  end
}

生命周期：on_start、on_update、on_interact、on_trigger_enter、on_trigger_exit、on_event、on_destroy、on_reload。

每次回调都是新环境

全局变量和闭包局部变量不会跨回调保留。影响未来模拟的数据必须写进已声明的 ctx.state。这是刻意的：隐式状态会让存档、回放和确定性全部失效。

脚本 API

API用途
ctx.entity / properties / state / tick / dt / input当前实例、配置、状态与模拟输入
ctx:get(id, component)组件副本；修改副本必须再提交
ctx:query(component)按 ID 排序的实体列表
ctx:set(id, component, value)替换组件，补全 schema 默认值
ctx:remove(id, component)移除组件
ctx:spawn(id, components) / destroy(id)在结构提交阶段创建 / 销毁实体
ctx:emit(target, name, payload)下一 tick 的事件；空目标为广播
ctx:timer(id, delay, name, payload, interval)整数 tick 计时器；interval = 0 为一次
ctx:cancel_timer(id)取消本实例的同名计时器
ctx:random(name, bound)独立命名随机流，整数 [0, bound)
ctx:hud(actor, text, ticks)设置 HUD 文本状态
ctx:play(id, clip)请求原生动画蒙太奇
ctx:presentation(name, payload)表现请求，不能反馈进模拟
ctx:keys(table) / ctx:array()排序键列表 / 明确标记的空数组

set 是替换而不是合并：省略的字段会恢复默认值。要保留旧字段，先 get，改完再 set。

沙箱

默认不开放：文件、系统时间、动态加载、debug、协程、无序 pairs / next、进程随机数、pcall / xpcall。排序遍历用 query / keys / ipairs。

随机使用有状态整数 LCG，每个「实体 + 行为 + 名字」独立派生；其状态进入快照与摘要，失败回调不消耗随机流。

调度

Input → Events → Behaviors → Simulation → Collect → Commit

系统名唯一，依赖必须存在且不能逆阶段；循环依赖拒绝执行。原生 Game 的角色/物理/动画保持在既有固定步长路径，适配层同步组件状态。

脚本创建的 transform / collider / rigidbody / renderable 实体自动获得方盒显示与原生物理生命周期；移除或禁用碰撞体会停用对应物理体；修改尺寸/质量会重算惯量。玩家 transform 位置修改按传送处理。

事件按 due tick、递增序号排序。碰撞/触发采集产生下一 tick 的事件，避免同步递归。计时器身份是「实体 ID + 行为 ID + timer ID」，同名设置替换旧计时器。

预算与失败隔离

项上限
每回调 Lua 指令100,000
Lua 堆4 MiB
每回调命令128
回调结果展开节点32,768
字符串 / 键总字节1 MiB
事件 / 计时器各 4,096
结构请求1,024

每次回调先生成状态、RNG 和命令副本，全部校验通过后才提交。失败会禁用该实例并记录实体、行为、tick、错误码，其他实例继续运行。创建/销毁延迟提交，销毁时执行受限的 on_destroy 并清除该实体计时器。

这是单实例隔离，不是进程级不可信代码隔离。宿主 C++ 故障不在承诺范围内。

热重载

候选模块编译、字段验证及所有受影响实例迁移都成功，才在 tick 边界一起替换；失败保留旧模块和实例状态。

状态 version 改变时，候选模块可提供 migrate(ctx, event)（event.oldVersion 为旧版本），迁移后按新 schema 检查。相同版本直接保留登记状态。on_reload 用于无世界副作用的修整。迁移和 reload 回调不允许提交世界命令。

完整快照包含：组件、实例状态、RNG、事件、计时器、触发重叠、待提交结构、待处理输入边沿、固定步累积余量、车辆、刚体内部状态、破坏状态、动画过渡与蒙太奇状态。派生物理接触缓存不保存，下一步重建。

快照用版本化 JSON + 校验和 + 临时文件 + 原子替换。恢复先在候选状态上验证；场景/脚本/组件/动画内容不匹配直接拒绝。磁盘旧版本存档明确拒绝——目前没有跨版本游戏进度升级器。
