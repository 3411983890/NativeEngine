内容寻址几何包

node tools/offline/geometry-package.mjs build --in assets/gltf --out outputs/geometry

包由 manifest + 二进制块组成。manifest 记录源文件哈希、cluster 数量、LOD 层级、材质句柄与能力标记；二进制里是顶点、索引与 cluster 记录。同一个输入重复构建，字节与摘要完全一致——篡改任何一段，读取时都会被发现。

v2 新增字段

struct ClusterRecord {      // 48 B，16 B 对齐
  float    lodError;        // 实测简化误差（不是 AABB 对角线估算）
  uint32_t flags;
  uint32_t materialHandle;  // 32 位：索引 + 代际
  ...
};

lodError 是 v1 到 v2 最重要的改动。v1 用 diagonal / maxLod 当误差，那只是包围盒代理误差，对植被和曲面网格会严重低估；v2 要求离线算出真实的简化误差，运行时才能用屏幕误差选 LOD。

GeometryClass 路由

不是所有东西都值得进 cluster 管线。场景里每个绘制项先被分类：

类别判定绘制路径
Simple三角形少、无变形顶点/索引直绘，或 Mesh Shader
Deformable蒙皮、每帧变形的顶点VS 蒙皮路径
Cluster三角形多、静态cluster 管线（尚未启用）

小院基线：17 个实体 = 16 Simple + 1 Deformable + 0 Cluster。这是正确结果——12 个三角形的方盒进 cluster 只会更慢。分类器存在，不代表一定要用。

glTF 2.0 子集

只支持一个刻意做窄的子集，超出范围明确拒绝，不做"尽力而为"的解析。

支持不支持
.gltf JSON，buffer 为 base64 或同目录 .binGLB、扩展、压缩（Draco/Meshopt）、稀疏 accessor、morph target
一个 scene、一个 identity 根 mesh 节点、一个 skin多 scene、多 mesh、节点变换动画之外的复杂层级
一个 indexed TRIANGLES primitive其他 primitive 模式、多 primitive
POSITION / NORMAL 必需，UV 可选切线、顶点色（自动推导或忽略）
JOINTS_0 为 U8/U16，WEIGHTS_0 为 FLOAT 或归一化整数每顶点超过四权重
TRS 节点、正的均匀 scale、LINEAR/STEP 轨道非均匀/负 scale、CUBICSPLINE

参考 Khronos glTF 2.0 规范 的 skin、动画采样、JOINTS/WEIGHTS、inverse bind 语义。导入只写显式 --out，不修改源文件、不下载内容。

离线窄带 SDF 烘焙

node tools/offline/sdf-bake.mjs --in outputs/geometry/mesh.bin --out outputs/sdf

为未来的软件光追与 GI 准备距离场：窄带存储、远场钳制、float32 量化、分块哈希。surface cache metadata 只是占用统计，不是表面缓存。

可见性缓冲（设计冻结，未实现）

架构文档冻结了 GPU 工作队列与可见性缓冲的数据契约：InstanceRef / ClusterRef、48 B cluster 记录、32 位材质句柄。这层设计的价值在于先定契约再写代码——队列格式一旦上线就很难改。
