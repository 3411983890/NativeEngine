粒子与场不是"特效贴图"，而是一条完整的仿真链：GPU 粒子在 compute 队列上积分，用整数原子加把密度和热量写进 96³ 体积，再由欧拉求解器解出速度场，最后全屏 ray march 合成。

确定性边界

两部分要分开说

splat 源项是确定的：整数原子加满足结合律与交换律，线程调度顺序不影响结果。求解器不是确定的：单精度浮点 + 迭代顺序依赖，不承诺逐位一致。文档里必须分开写，否则"确定性"会变成一个不成立的宣传词。

命令行

build/NativeGPU.exe --scene assets/campfire.scene.json --particles on --fire
build/NativeGPU.exe --scene assets/campfire.scene.json --particles on --explode-at 90
参数作用
--particles on|off总开关；关闭时走原渲染路径
--particle-colliders on|off粒子与场景 AABB 求交
--particle-emitter <x,y,z>覆盖发射器位置
--fire篝火预设：更小发射半径、更高浮力、更强消光
--explode-at N第 N 个粒子帧起爆
--particle-temporal on|off时域重建

--fire 做了什么

它不只是"调几个参数"：把场的包围盒从 16 m 收缩到 6 m。同样 96³ 网格，体素从 16.7 cm 变成 6.25 cm——火焰第一次有形状。这是"域是效果的属性"的第一步：先让域跟着效果走，再谈域内的稀疏分配。

--explode-at 做了什么

项倍数
源半径×9
外抛速度×7
温度×3.5

同时向速度场注入一次径向冲击（CSBuoyancy 里的 blast 项），把已经存在的烟整体推开。只放大发射而不动速度场，看起来像"喷了一下"，不像"炸了"。

与场景碰撞

场景 AABB 从场景图上上传到 compute 着色器。粒子穿入后沿最浅轴推出并施加阻尼反弹。因为场景实体没有旋转，AABB 是精确的——这条限制在这里变成了优势。

粒子不与刚体双向耦合：爆炸不会推开箱子，箱子也不会扰动烟。

通道租约

六个场通道（density / heat / velocity / pressure / divergence / curl）以引用计数 + 一致性等级（strong / eventual / stale）出租。模拟在创建时持有全部六个；体积渲染每帧临时租用 density / heat，绘制后归还。

求解器先检查租约完整性，缺任何一个通道就跳过该帧并把 leaseStalls 加一。租约是合同，不是记账——报告里逐通道输出 refs / level / acquisitions。

爆炸的场景后果

宿主每帧轮询 Renderer::particleBurst()，爆发强度超过 0.5 时，把火塘 4.5 m 内的实体按距离衰减焦化（scorched=14）。这是纯视觉后果：场景文件不被修改，重新加载即恢复。

边界

  • 求解器单精度，不承诺确定性；只有 splat 源项是确定的。
  • 碰撞只对轴对齐盒生效；不与刚体双向耦合。
  • 火的形态是浮力 + 涡量 + 投影 + 冲击的结果，不是燃烧化学模型。
  • 没有稀疏砖块、没有 LEF→WF 提升/降级；场固定 96³ 全域分配。
  • 体积渲染是单次散射近似，没有多次散射。
