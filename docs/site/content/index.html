NativeGPU 是一个 Windows / D3D12 原生游戏引擎样板，核心不是"又一个渲染器"，而是把 场景事务、确定性模拟、渲染证据 三件事做成同一条可重放、可审计的闭环——让 AI Agent 和人类编辑器共用一套入口。

v0.11.0 部分系统实现中 2026-10-21 · Windows 11 x64 · D3D12

它解决什么问题

大多数引擎的"AI 接入"停在对话框：模型生成一段代码或一段配置，人再手工搬进工程。这条路径无法验证、无法回退、无法复现。NativeGPU 反过来做——先把改动变成可校验的事务，再让 Agent 只通过事务说话。

读取场景 → 预览事务 → 原子提交 → 运行中的原生窗口热重载 → 冒烟测试 → 可审计报告

这条链路上每一步都有失败路径和错误码，没有"静默成功"。同一个场景、同一个种子、同一个构建，跑两次得到的摘要逐字节相同；渲染开关、窗口分辨率、调试视图都不允许改变它。

五条设计原则

这些原则写在 .developmentAgent/core/STATUS.md 的"维护约束"里，也约束着本份文档本身。

  1. 证据优先。 implemented、effectImplemented、性能数字只能来自实际运行写出的报告，不能手写。文档里出现的每个数字都应该能在 reports/ 里找到来源。
  2. 边界写清楚。 每个系统都有"明确未实现"清单。不做的事写出来，比含糊其辞更省时间。
  3. 确定性是产品特性。 模拟代码禁止进程级随机源、禁止读墙上时钟；随机必须命名。
  4. 可回退。 高级图形能力必须"可运行 + 可回退 + 有报告"才能标记为完成。
  5. 工具复用。 编辑器、CLI、MCP 走同一套事务实现，不存在"编辑器专用写盘路径"。

不要这样理解

本引擎不是 UE5 的替代品，也没有 Nanite、Lumen、World Partition、蓝图、网络同步或音频。它是一个刻意做小的引擎，用"能验证"换取"能长大"。把它的架构当成一套可复用的纪律，比当成功能清单更有价值。
