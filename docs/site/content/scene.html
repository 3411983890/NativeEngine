场景是引擎唯一的数据模型，也是 AI 与人类编辑器的唯一写入接口。它不是"运行时状态转储"，而是一份带 revision 的、可原子提交的文档——改一次，revision 加一，历史留痕。

已完成 Schema: assets/scene.schema.json · 实现: engine/scene/

文档结构

{
  "schemaVersion": 2,
  "projectId": "a1e00000-0000-4000-8000-000000000001",
  "name": "courtyard",
  "revision": 7,
  "materials": { "stone": { ... } },
  "lighting": { "quality": 1, "localShadows": true, "ibl": true },
  "entities": [ { ... } ],
  "settings": { "walkSpeed": 4.2, "runSpeed": 7.4, "jumpSpeed": 5.2, "gravity": 18 }
}
字段作用约束
schemaVersion文档版本当前 2；v1 文档仍可读
projectId事务作用域UUID；与事务不匹配直接拒绝
revision乐观并发控制每次成功提交 +1；撤销也 +1
materials命名材质表最多 256 条，键为材质名
lighting光照质量与开关quality 0–2，独立布尔开关
entities实体数组上限 10,000；JSON ≤ 16 MiB
settings角色运动参数四项必填，且 runSpeed ≥ walkSpeed

实体

实体没有旋转，只有位置与轴对齐缩放——这条限制让 AABB 成为精确的碰撞与剔除代理，也是"没有旋转"能一直成立的原因。九种 kind：ground、wall、prop、player、key、door、goal、light、vehicle。

字段类型说明
idUUID持久身份；同一文档内唯一
namestring人类可读名，查询与日志使用
kindenum决定运行时行为与默认外观
position / scale[x,y,z]米；scale 为完整尺寸，不是半长
color[r,g,b]0–1 线性
colliderbool是否参与碰撞；必填
material / namedMaterialstring内联材质或引用 materials 表
lightobject仅 kind: light；见下
physicsobjectmode + 质量 / 摩擦 / 恢复
destructibleobject强度、碎片数、寿命、结构标记、种子
componentsobject玩法组件覆盖，见玩法运行时

事务

唯一的写入格式。整批命令先应用到副本，全部校验通过后提交一次，revision 只增加一次。

{
  "projectId": "a1e00000-0000-4000-8000-000000000001",
  "expectedRevision": 0,
  "commands": [
    { "op": "set", "entityId": "a1e00000-0000-4000-8000-000000000030",
      "changes": { "position": [-4, 0.6, 1] } },
    { "op": "create", "entity": { ... } },
    { "op": "remove", "entityId": "..." }
  ]
}
拒绝原因错误码
项目 ID 不匹配PROJECT_MISMATCH
revision 已过期（他人先提交）REVISION_CONFLICT
未知字段 / 未知 kind / 非有限数值 / 违反不变量INVALID_SCENE
重复 UUIDDUPLICATE_ENTITY
未知 op 或命令结构错误INVALID_COMMAND
文件被其他进程持有PROJECT_BUSY
存在未完成的提交，需要先恢复RECOVERY_REQUIRED
构建目标冲突BUILD_CONFLICT

场景层使用裸大写错误码（不带 NG-E- 前缀），这是历史原因，也是公开契约的一部分：SceneError.code 稳定，message 不稳定。

保存与恢复

文件作用
.history.json最多 100 步线性撤销；撤销后 revision 继续增加
.snapshot.json上一有效场景，用于回滚
.pending.json记录中断的提交，供 recover 判定
.lock阻止并行写入；崩溃遗留需确认进程停止后手动移除
 
node tools/scene.mjs recover assets/courtyard.scene.json

recover 要么完成已提交的中断写入，要么恢复最后有效快照——它不会"猜"一个中间状态。

场景 CLI

命令作用
validate <scene>Schema + 不变量校验，不写盘
preview <scene> <tx>在副本上应用事务，返回差异，不写盘
apply <scene> <tx>原子提交
undo <scene>回退一步（revision 仍 +1）
recover <scene>中断恢复
build <scene>内容寻址构建包
query <scene> --query '<json>'声明式查询
lint <scene>设计期规则检查 + 可达性 BFS

查询 DSL

纯函数、零 I/O、不改输入。同一文档 + 同一查询永远得到逐字节相同的 JSON。这让 Agent 可以安全地"先问再改"。

node tools/scene.mjs query assets/courtyard.scene.json --query '{
  "select": "entity",
  "where": [
    { "field": "kind", "op": "eq", "value": "prop" },
    { "field": "position", "op": "within", "value": { "x": 0, "y": 0, "z": 6, "radius": 4 } }
  ],
  "orderBy": { "field": "z", "direction": "asc" },
  "limit": 3
}'
部分取值
selectentity · material · light
where[].opeq · ne · lt · lte · gt · gte · within · in · contains
orderBy{ field, direction: asc|desc }；平局按输入顺序
aggregatecount · sum

设计期 lint

lint 检查的是"这张图能不能玩"，不是"文件合不合法"。12 条规则覆盖重叠实体、悬空引用、不可达道具、玩家出生点被堵、光照范围异常等；可达性用 BFS 在碰撞体上求解，并考虑跳跃高度。

npm run scene -- lint assets/courtyard.scene.json

小院基线为 0 findings。lint 是建议，不是事务闸门——它不会阻止提交，但会出现在 CI 报告里。
