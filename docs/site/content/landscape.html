UE5 的做法与它的代价

UE5 地形不是"一个网格"，而是"一张 16 位高度图 + 一套按需派生的数据"。四个关键决策值得学，也值得知道代价。

决策做法代价
存高度场每顶点 uint16，世界Z = (h − 32768) / 128 × ScaleZ（ScaleZ=100 时 ±256 m，1 LSB ≈ 0.78 cm）精度上限固定；陡崖会出现阶梯
组件化每组件 63×63 四边形 = 64×64 顶点，边缘与邻居重复存储内存冗余，换来独立流送与独立 LOD
顶点着色器取高度VS 采样 heightmap mip 算位置与法线，CPU 只决定 LOD 级别绑定 vertex texture fetch；材质受限
权重图即材质分层RGBA8 一张装 4 层，每层配 LayerInfo（物理材质、硬度）层数受纹理数量约束

内存上的理由很硬：1 km² @ 1 m 精度 = 100 万顶点，存成高度图是 2 MB，存成网格（pos + normal + uv）是 32 MB。16 倍的差距，而且高度图天然带 mip，LOD 与碰撞简化都只是"取哪一级"。

UE5 还有两个对 AI 生成特别友好的机制：Edit Layers（高度/权重分图层存，运行时 GPU 合成，非破坏）和 Landscape Patch（蓝图驱动的运行时补丁，道路与河床不改基础高度图）。它们让"AI 写一层、美术改一层"成为可能。

关键结论

第一版不需要 LOD，也不需要 clipmap。 一块 128 m × 128 m、0.5 m 精度的地形 = 257² ≈ 66k 顶点，一个 draw call，约 1.5 MB 顶点数据——用现有静态网格路径就能跑完。LOD 等视距推到 1 km 再说。

设计：高度图 → 地面

1. 资产

assets/terrain/hills.ngheight
  header: magic | version | width | height | scaleZ | minZ | maxZ | contentHash
  data:   uint16[row * width + col]         // 行主序，小端

走现有 .ngtex 的内容寻址思路：同样的输入 → 同样的字节 → 同样的哈希，可以直接进构建缓存。

2. 网格生成

for each (i, j) in [0, N]:
    h  = bilinear(height, u, v)
    p  = (x0 + i * cell, h, z0 + j * cell)
    n  = normalize(cross(dh/dx, dh/dz))   // 中心差分

法线用中心差分而不是面法线：面法线会在四边形边界产生硬边，中心差分得到连续法线，且不需要额外的法线贴图。

3. 分块与接缝（P2 才做）

当视距超过 300 m 时，按 32 m 分块，每块独立选 LOD。块间 LOD 不同必然产生 T 型接缝，三种处理：

方案做法适用
Skirt 裙边块边缘向下延伸一圈，遮住缝隙最简单，与现有单网格路径最兼容
索引缝合T 型接缝处插入顶点，硬保证无缝最正确，需要每块生成变体索引缓冲
顶点形变同时采样 LOD n 与 n+1，按因子 lerp 位置UE 的做法；掩盖跳变，不消除裂缝

第一版选 skirt：实现成本最低，视觉上几乎看不出，而且不需要每块维护多套索引。

4. 碰撞

只做查询，不做刚体：

float heightAt(float x, float z);   // 双线性插值
vec3  normalAt(float x, float z);   // 中心差分

角色贴地用 heightAt，不引入 heightfield 刚体。现有物理是盒体 SAT + O(n²) 宽相，heightfield 是另一个量级的工作，而且和现有角色控制器（AABB 扫掠）语义冲突。

5. 材质

按坡度与高度离线烘焙 splat 权重图（RGBA8，一张四层），运行时按权重混合 albedo / normal / roughness。这一步不需要新 shader 架构——现有材质路径能直接吃权重图。

AI 生成管线

"AI 自动生成地编场景"要拆成三件事看，可行性完全不同：

任务可行性真正的卡点
高度图 → 地面成熟不是生成，是 LOD / 接缝 / 碰撞 / 材质混合
程序化地形（噪声 + 侵蚀）成熟参数调优，不是技术
扩散模型生成高度图可用但需后处理高程绝对尺度、可平铺、流域一致性、16 位精度
LLM 直接产出关卡布局可行必须走结构化 DSL，不能吐坐标
一键生成"像美术做的关卡"不行构图、叙事、可玩性

为什么必须有侵蚀

扩散模型生成的地形"不像真的"，根源不是分辨率，是没有流域一致性：水不会往低处流，河谷不连续，山坡上出现孤立坑洞。加一道水力侵蚀 + 流量累积，比换更大的模型有效得多。

文本 / 参考图
   │  产出约束而非像素：河谷走向、村落位置、道路端点
   ▼
宏观形态（扩散或噪声）     只负责大形状，不负责物理正确
   ▼
侵蚀与流域                 水力 / 热力 / 流量累积 ← 像不像真的在这一步
   ▼
派生图                     坡度 / 曲率 / 流量 / 湿度
   ▼
组装                       材质 splat · 植被散布 · 道路 · POI
   ▼
场景 DSL → 渲染 → 打分     确定性种子 + 固定机位截图 + VLM/规则评分
   └──────────────────────▶ 回到"宏观形态"改参数

核心原则：LLM 不该碰顶点，该碰参数和图结构。它输出的是"河谷沿 X 轴、村落放在坡度 < 8° 的南向台地、道路连接 A 与 B"，由确定性求解器落地。这样才可复现、可校验、可回退。

分阶段计划

阶段内容验收
P0高度图资产格式 + CPU 双线性采样 + 法线单测：已知高度场往返误差 < 1 LSB
P1128 m 单瓦片网格，接入现有 draw 循环固定机位截图，与纯平面基线有可测差异
P232 m 分块 + skirt 接缝块边界无可见裂缝（截图 + 逐像素检查）
P3坡度/高度 → splat 权重图烘焙三种地表在固定机位下可区分
P4离线 AI 生成工具（Node），输出高度图 + 场景 JSON同一提示词 + 同一种子 → 逐字节相同产物
确定性要求

侵蚀仿真必须确定性：CPU 定点顺序执行，或 GPU 上用整数原子加（整数加法满足结合律，与线程调度顺序无关）。参考粒子与场里 splat 源项的做法。浮点求解器不承诺确定性，这一点必须写清楚。

明确不做

  • 不做 UE 式的组件网格 + 顶点工厂（前置是任意网格路径 + VS 纹理采样 + 每组件常量）。
  • 不做运行时地形编辑（笔刷、图层合成）——离线生成，运行时只读。
  • 不做 heightfield 刚体。
  • 不做地形流送（World Partition 等价物）；单场景单瓦片。
  • 不在 P0–P2 阶段引入任何 AI 依赖；生成工具是最后一步。
