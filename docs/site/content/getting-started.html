从零到第一帧大约需要一次工具链下载、一次构建和一条运行命令。构建过程不会修改系统环境：编译器、DXC 和着色器全部落在仓库内的 .tools/ 与可执行文件里。

已验证 Windows 11 x64 · PowerShell 5.1 · Node.js ≥ 22

前置条件

项要求说明
操作系统Windows 11 x64依赖 D3D12、DXR、Mesh Shader
GPU支持 D3D12DXR 阴影需要 Tier 1.1+；缺失时自动回退纯光栅
Node.js≥ 22.12场景工具、编辑器服务、MCP 服务都跑在 Node 上
PowerShell5.1+所有构建与证据脚本的入口
Git任意近期版本报告会记录 commit 与工作树脏状态

不需要 Visual Studio，也不需要 Windows SDK：D3D12 头文件与导入库来自项目内 LLVM-MinGW 自带的副本。

1. 引导工具链

powershell -NoProfile -ExecutionPolicy Bypass -File tools/bootstrap.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tools/bootstrap-dxc.ps1

第一步下载 LLVM-MinGW 20261006（clang 23.1.3，UCRT），第二步下载 DXC 1.9.2609。两者都会校验归档 SHA-256，校验失败直接中止，不会"带病继续"。产物落在 .tools/，该目录被 .gitignore 排除——仓库里只有下载地址与哈希。

为什么固定 DXC

着色器编译结果的差异会直接改变像素。DXC 版本漂移会让图像回归基线失去意义，所以版本、归档哈希和 dxcompiler.dll 哈希都被写进 .developmentAgent/core/TOOLCHAIN.md 与运行报告。缺失时报告 dxcUnavailable，而不是静默用系统 PATH 上的另一个 DXC。

2. 构建

powershell -NoProfile -ExecutionPolicy Bypass -File tools/build.ps1

构建会先用 DXC 编译 shaders/ 下所有 HLSL，把 DXIL 内嵌进可执行文件，再编译 C++。着色器清单在 shaders/manifest.json，新增着色器必须登记，否则不会被编译。

产物在 build/：NativeGPU.exe、若干测试可执行文件（*_tests.exe）、以及每次构建的日志。

3. 运行

powershell -NoProfile -ExecutionPolicy Bypass -File tools/run.ps1
# 或者直接
build/NativeGPU.exe --scene assets/courtyard.scene.json

默认场景是 assets/courtyard.scene.json（可玩小院）。交互按键：

4. 验证

不同层次的验证入口刻意分开，避免"跑通一个就算全过"。

命令覆盖范围产物
npm testNode 事务 / 工具 / 查询 / lint 单测终端输出
npm run test:editor编辑器服务与传输终端输出
npm run test:nativeC++ 物理、数学、RHI 契约*_tests.exe
npm run animation动作导入、蒙皮截图、严格回放reports/latest/animation-evidence.json
npm run physics刚体 / 破坏前后截图、重复摘要、步预算reports/physics-evidence.json
npm run probe设备能力与材质 / 灯光 / 加速结构探针reports/probe.json
npm run verify构建 + Node + 原生 + 冒烟 + 探针 + 热重载 + MCPreports/verify*.json
npm run ci干净状态完整重放（verify + 打包 + CI 报告）reports/<version>/<commit>/<ts>/

第一次跑建议用 npm run verify。它会在隐藏窗口里做原生冒烟，因此需要可用的 D3D12 设备。

5. 打开编辑器

npm install
npm run editor        # Electron 桌面版
npm run editor:web    # 本机浏览器版

编辑器与 MCP 复用同一套场景事务；它不会绕过校验直接写 assets/。原生预览是独立进程的窗口，按需快照是一次隐藏的原生截图任务——两者都不是实时共享纹理，详见编辑器。

6. 打包

powershell -NoProfile -ExecutionPolicy Bypass -File tools/package.ps1

产物在 outputs/，包含可执行文件、默认场景、角色资产、着色器与清单，并生成 zip。打包产物没有代码签名、安装器、自动更新和崩溃上传。

常见失败

报告 dxcUnavailable
没有跑 bootstrap-dxc.ps1，或 .tools/dxc/1.9.2609/ 被清理。重跑脚本即可；引擎不会退回到系统 DXC。
构建报着色器清单错误
新增了 HLSL 但没登记进 shaders/manifest.json。
冒烟在远程 CI 退化
GitHub 托管 runner 没有 D3D12 GPU，显卡相关步骤会走 WARP 并允许失败。远程通过不等于本机显卡证据。
场景校验失败但原生能跑
材质校验器与 Schema 的 wetness / wear 字段正在并行迁移，已知不一致；原生加载路径不受影响。
安全边界

场景工具、编辑器服务和 MCP 服务都是受信本地工具：它们假定调用者已经拥有这台机器。浏览器入口只监听本机，不要暴露到不可信网络。加入网络服务、模型凭证或远程执行之前，必须先补权限、配额、审计和超时。
