AI 接入面是一个本地 stdio MCP 服务，不监听端口、不持有模型凭证、不接受任意 shell 文本。它只做一件事：把"改场景"变成可校验、可拒绝、可回滚的事务。

12 个工具 ai/mcp-server.mjs · ai/tool-service.mjs · ai/README.md

启动与注册

node ai/mcp-server.mjs
[mcp_servers.nativegpu]
command = "node"
args = ["ai/mcp-server.mjs"]
cwd = "C:\\path\\to\\AI-Native Game Engine"

直接测协议，不需要任何客户端：

'{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | node ai/mcp-server.mjs

工具

工具作用写盘
scene_validateSchema + 不变量校验否
scene_query声明式查询（实体 / 材质 / 灯光）否
scene_preview在副本上应用事务，返回差异否
scene_apply原子提交（需 projectId + expectedRevision）是
scene_undo回退一步是
scene_build内容寻址构建包是（outputs/）
material_patch材质参数原子修改是
gameplay_catalog组件与行为字段描述否
gameplay_validate行为参数与依赖校验（不执行 Lua）否
gameplay_inspect读取 reports/ 内的状态/错误报告否
runtime_smoke启动原生程序跑冒烟是（reports/）
engine_probe设备能力与子系统探针是（reports/）

注意"写盘"那一列的分布：能改场景的只有 scene_apply / scene_undo / material_patch，且三者都走同一套事务实现。其余工具要么只读，要么只写构建产物与报告。

路径策略

目标允许目录
场景文件assets/
构建输出outputs/
冒烟报告reports/

拒绝 ..、根目录外的绝对路径和符号链接逃逸。工具不接受任意 shell 文本——没有 exec 参数，也就没有命令注入面。

一次典型的 Agent 闭环

1. scene_query    "玩家 4 m 内的道具"           → 拿到实体 ID 列表
2. scene_preview  把其中一个移到 (-4, 0.6, 1)   → 返回差异，不写盘
3. scene_apply    projectId + expectedRevision  → 原子提交，revision +1
4. runtime_smoke  跑 120 帧                     → 报告写入 reports/
5. 读报告         摘要、GPU P95、错误码          → 判断是否达标
6. 不达标 → scene_undo，回到第 2 步

每一步都有结构化返回，失败带稳定错误码。Agent 不需要"猜"上一次操作有没有成功。

三条设计原则

  1. 模型无关。 服务不绑定任何模型或供应商，不需要模型凭证。换模型不影响工具面。
  2. 不伪造能力。 没有接入模型时，就只说"提供模型无关的工具面"。工具描述里不会出现"AI 自动完成"这类措辞。
  3. 不可绕过的闸门。 不允许模型直接写 assets/；必须走 scene_preview / scene_apply，并携带项目 ID 与 expectedRevision。

安全边界

这是受信本地工具。加入网络服务、模型凭证或远程执行之前，必须先补权限、配额、审计和超时。浏览器入口只监听本机，不要暴露到不可信网络。

边界

  • 没有自然语言任务编排层——那是调用方的事。
  • 没有多 Agent 协作、没有会话状态、没有记忆。
  • 不提供代码补丁能力；只能改场景与材质。
  • MCP 协议冒烟只验证协议层，不验证 Agent 的决策质量。
