动画系统是"数据很窄、纪律很严"的典型：只支持一个刻意收窄的 glTF 子集和 60 Hz 量化片段，但把确定性、通道掩码、阶段哈希做成了硬约束——因为动画一旦不确定，整个回放体系就失效了。

部分实现 无脚 IK / 动作匹配 .developmentAgent/animation-audio/ANIMATION.md · engine/native/animation.*

运行

npm run build:native
npm start
npm run animation

默认小院角色使用仓库内原创的 16 骨骼人偶与六段 60 Hz 动作，通过顶点着色器蒙皮绘制。WASD / Shift / Space 驱动 idle / walk / run / jump / fall，E 触发上半身 interact slot。通知进入动画事件队列，不直接修改钥匙或门的玩法状态——这条隔离很重要，否则动画会变成第二套玩法逻辑。

导入子集

node tools/offline/animation.mjs import --in character.gltf --out build/animation/custom
build/NativeGPU.exe --character build/animation/custom/character.json
支持限制
.gltf JSON，buffer 为 base64 或同目录 .bin不支持 GLB、扩展、压缩、稀疏 accessor、morph
一个 scene、一个 identity 根 mesh 节点、一个 skin—
一个 indexed TRIANGLES primitive多 primitive 拒绝
POSITION / NORMAL 必需，UV 可选—
JOINTS_0 为 U8/U16；WEIGHTS_0 为 FLOAT 或归一化 U8/U16每顶点超过四权重拒绝
最多 256 骨骼/辅助节点，单根、父先、无环、名字唯一—
TRS 节点、正的均匀 scale、LINEAR/STEP 轨道非均匀/负 scale、CUBICSPLINE 拒绝

动作固定 60 Hz，最后一个样本是端点；变换十分量乘 10,000 后编码为 int32le，运行时归一化四元数。片段最长 120 秒、最多 64 段、总包上限 64 MiB。

输出 character.json + animation.bin：顶点 64 字节（position / normal / UV / u32 joints / float weights），索引 uint32le，片段 frame-major。头里含骨架、片段偏移、通知与二进制长度，以及 FNV-1a 检错哈希。

两个哈希，不要混用

contentHash 是 SHA-256，覆盖头 + 二进制，用于内容寻址与缓存；runtimeFingerprint 是 64 位 FNV-1a，由运行时对实际加载的字节计算，进入玩法摘要。前者回答"这是不是同一份资产"，后者回答"这次运行的动画内容和上次是否一致"。

运行时

Trait DAG

动画图不是节点树，而是按 (stage, priority, id) 排序的 DAG。五个阶段：Select → Blend → Correct → Deform → Emit。after 必须引用排序中更早的节点，违反顺序或成环直接拒绝——不会"根据依赖悄悄改顺序"。

阶段职责约束
Select选片段、算权重必须确定；不得写骨骼
Blend混合姿态必须确定
Correct修正（未来的脚 IK 在这）必须确定
Deform形变（肌肉/布料）不得写根骨骼
Emit输出最终姿态不得写骨骼

每个 trait 执行后检查全部 256 骨骼与 32 曲线；越界写立即 NG-E-ANIM-MASK。reads 是数据流声明，writes 是实际强制检查——前者靠自觉，后者靠代码。

SoA 双缓冲

256 骨骼按结构体数组拆成 SoA，双缓冲避免读写同一份数据。阶段哈希分五段（S1–S5），S1 包含意图与选择，S2–S4 累积量化后的确定性写通道，S5 不进入哈希。空阶段也有可定位的链节点，但没有对应效果——这样报告里能看到"哪一段是空的"，而不是一片空白。

控制器

五状态控制器（idle / walk / run / jump / fall）、1D 走跑混合、2D 三角形混合 API、Montage / Slot、逐骨骼 profile、固定 tick Notify、根位移提取。

惯性化用绝对 tick 年龄的临界阻尼解析解，旋转偏移用 quaternion log/exp，不做逐帧弹簧积分。Montage 使用逐骨骼 mask/profile、100 ms smoothstep 权重包络，结束恢复 locomotion。Notify 按跨过的固定 tick 派发，宿主用 Game::takeAnimationEvents() 消费，不会丢掉一个渲染帧第一个子步的事件。

确定性

固定 120 Hz 控制器与 Game 同步；渲染不推进动画。片段 tick、状态、蒙太奇、弹簧偏移与速度、双缓冲的必要历史、内容指纹都进入 digest()。计时只供报告，绝不进入摘要。

门禁包含：720 tick 跨运行对拍、60/120 Hz 更新等价、固定 tick 通知、严格回放零不符。

渲染

最多同时一个蒙皮角色，256 骨骼、每顶点四权重。静态物体继续走 Mesh Shader / 顶点路径，角色走独立 VS 路径。几何在每个在途帧首次遇到内容时上传一次；palette 使用三套 fence 隔离的 upload buffer，每帧只更新骨骼矩阵。

DXR TLAS 只包含刚体——角色可以接收静态物体阴影，但自己的变形阴影未实现，报告里明确 dynamicBlas=false。把蒙皮角色当单位方盒塞进 TLAS 是错误做法，会得到一个随方盒变化的假阴影。

边界

  • 2D 混合空间只提供已测 API，未接小院输入。
  • 没有脚部 IK，不能宣称无脚滑。
  • 没有动作数据库、26 维特征、KD-tree、距离匹配、运动扭曲。
  • 没有 Sync Marker 对齐。
  • 没有肌肉、软组织、生理、面部。
  • 根旋转提取未实现；小院用 in-place 模式，角色平移由扫掠碰撞控制器决定。
