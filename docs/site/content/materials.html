纹理管线是离线的，材质是数据驱动的。一张 PNG 进，一个带 mip 的 .ngtex 出，中间有预算求解器决定每张图能有多大——不是"能塞多少塞多少"，而是"总预算 4.5 MiB，怎么分最不亏"。

已实现 tools/textures.mjs · engine/material/ · shaders/material.hlsl

端到端

assets/source/textures/*.png
        │  cook：解码 → 尺寸归一 → mip 链 → 格式选择
        ▼
assets/textures/*.ngtex          RGBA8 / BC1 / BC3 / BC5 / BC7
        │  预算求解：按总字节上限逐张降级
        ▼
场景 v2 materials 表             albedo / normal / ORM / emissive
        │  运行时：8 槽有界表 + 代际
        ▼
material.hlsl                    采样 → 光照 → 合成

.ngtex 容器

自定义容器，不是 DDS：头部记录尺寸、格式、mip 数量、源内容哈希与 FNV-1a 检错，后面紧跟 mip 数据。内容寻址——同一份 PNG、同样的 cook 参数，产物字节完全一致，可以直接进构建缓存。

格式用途每像素
RGBA8UI、需要精度的 albedo4 B
BC1不透明 albedo、粗糙度0.5 B
BC3带 alpha 的 albedo1 B
BC5法线（双通道重建 Z）1 B
BC7高质量 albedo / 法线1 B

Cook 命令

node tools/textures.mjs cook --source assets/source/textures --out assets/textures \
  --report reports/textures --size 256 --format auto --budget-mib 4.5
参数说明
--source / --out输入 PNG 目录 / 输出 .ngtex 目录
--size边长上限，超出则降采样
--formatauto 或指定格式；auto 按用途与 alpha 选择
--budget-mib总预算，超了会逐张降级而不是静默丢弃
--report每张图的最终尺寸、格式、字节数与降级原因

预算求解的结果会写进报告：哪张图被降级、降了几档、省了多少字节。没有这份记录，"4.5 MiB 预算"就只是一句口号。

材质模型

"materials": {
  "stone_wet": {
    "albedo": "textures/stone_albedo.ngtex",
    "normal": "textures/stone_normal.ngtex",
    "orm":    "textures/stone_orm.ngtex",
    "roughness": 0.62,
    "metalness": 0.0,
    "uvScale": [2, 2],
    "wetness": 0.35,
    "wear": 0.2,
    "emissive": [0, 0, 0]
  }
}

wetness 与 wear 是"表面经历"参数，不是贴图：湿润会降低粗糙度、加深 albedo；磨损会提亮边缘、提高粗糙度。它们让同一个材质资产能覆盖"新石头 / 泡水石头 / 被踩烂的石头"三种状态，而不必烘三套图。

运行时材质表

8 槽有界表：0 为缺材质默认槽（品红棋盘），1–3 常驻，4–7 可分配。带代际计数——材质被替换后旧句柄立即失效，不会采样到别人的纹理。

情况行为
句柄越界返回诊断，使用默认槽
代际过期返回诊断，使用默认槽
材质缺失NG-E-MAT-MISSING
材质过期NG-E-MAT-STALE
表满NG-E-MAT-TABLE

参考场景：石桥小镇

npm run textures
npm run town

town.scene.json 是材质与光照的综合基线：608 个实体、4.5 MiB 纹理预算、默认光照质量档 1。它会生成固定机位截图与报告，是"管线没坏"的日常体检。

编辑入口

npm run material -- list --scene assets/town.scene.json

Web 编辑器的材质面板通过 material_patch 工具原子写入 wetness / wear / roughness / metalness / uvScale。它和场景事务走同一条校验路径，不会出现"编辑器能改、Agent 改不了"的分叉。

边界
  • 材质表是有界 8 槽，不是 SM 6.6 descriptor heap 直接索引；后者已验证一致但未迁移主路径。
  • 没有材质图编译器（engine/material/ 只有 graph 与 MIR 的骨架），没有节点编辑器。
  • 材质像素着色器用世界空间平面投影 UV，不读顶点 UV；没有 alpha test、没有双面。这三条是植被系统落地前的硬前置。
  • 没有运行时纹理流送，全部常驻。
