帧预算管理器

它只决定何时降档，具体降什么由宿主执行。决策指标是滚动窗口的中位数，不是 P95——短窗口的 P95 只要一帧毛刺就拉满，会在单帧卡顿时误降档。

规则取值
决策指标GPU 与 CPU submit 的滚动中位数
触发条件中位数连续 sustainFrames 帧超目标，且窗口样本足够
阶梯单调、每档只应用一次、不可回退（回退会抖动）
耗尽走完阶梯仍超目标 → status=exhausted，只记录不再动作
档位名称宿主动作
0rt-shadows-off关闭 DXR 阴影，回到纯光栅 + 全 1 可见性
1mesh-path-off关闭 Mesh Shader，回到顶点路径

阶梯只包含本次运行里真正可用的档：--rt-shadows off 时对应档不会进入阶梯。

build/NativeGPU.exe --smoke --no-watch --frames 240 --budget auto \
  --budget-target-ms 16.6 --budget-window 120 --budget-sustain 30
参数默认含义
--budget auto|offoff是否启用（默认关闭，避免改变既有证据）
--budget-target-ms16.6GPU 中位数目标
--budget-cpu-ms0CPU submit 中位数目标，0 = 不启用
--budget-vram-mb0显存峰值上限，0 = 不启用
--budget-window120滚动窗口帧数
--budget-sustain30连续超目标帧数

报告 budget 段：enabled、status、level、targetGpuMs、windowFrames、sustainFrames、samples、gpuSamples、overBudgetFrames、gpuP95Ms、cpuP95Ms、vramPeakBytes、ladder[]、steps[]（每步含 name、frame、reason、gpuMedianBeforeMs、cpuMedianBeforeMs）。

图像误差契约

tests/image-contracts.json 定义了 5 条契约：每条指定两次运行的产物、比较指标与阈值。阈值来自实测，不是先写一个"看起来合理"的数。

指标用途
平均绝对误差（MAE）整体亮度/颜色偏移
变化像素比例"有多少像素被改动"
最大单通道差抓局部炸点
 
powershell -File tools/error-contract.ps1
powershell -File tools/error-contract.ps1 -Contract shadow-off-fallback

典型契约："关闭 DXR 阴影后与纯光栅逐像素一致"（maxDelta = 0）；"开启阴影与关闭阴影的差异在 11.73% 左右"——差异必须存在，否则说明阴影根本没生效。这两条互为对照，防止"两边都黑"式的假通过。

    artifacts/                   固定机位截图
  latest/                        最新一次的别名（不覆盖历史）

run.json 里的 worktreeDirty 与 staleBuild 两个字段是"这份证据能不能引用"的开关：脏树或过期构建跑出来的数字，必须在引用时注明。

CI

powershell -File tools/ci.ps1 -Clean       # 删 build/ outputs/，保留 reports/ 历史
powershell -File tools/ci.ps1 -CleanAll    # 连 reports/ 一起删，从零重放

tools/ci.ps1 是唯一入口，本地与 .github/workflows/windows.yml 调用同一脚本。失败保留 logs/ 与 ci-failure-<commit>-*.log。

远程 CI 不等于显卡证据

GitHub 托管 runner 没有 D3D12 GPU，显卡相关步骤会退化为 WARP 并允许失败。远程绿灯只能证明"代码能编译、逻辑测试通过"，不能替代本机显卡证据。
