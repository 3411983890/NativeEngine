# AI 原生游戏引擎创业计划宣讲 PPT 策划案

## 一、项目主题与宣讲定位

**主题：AI 原生游戏引擎——让小团队创造更大的游戏世界**  
**副标题：以智能体协作、统一场与新一代实时技术，重构游戏世界的创作流程**

面向创业比赛评委、潜在合作伙伴与早期投资人。建议 15 页、12–15 分钟，重点回答：为什么需要新引擎、产品如何工作、关键技术有什么价值、如何验证商业可行性。具体演讲时长可按活动要求调整。

**核心主张：**让 Agent 不只是生成代码或指令，还能通过引擎接口操作场景、读取结构化反馈，并借助原生截图观察结果；在此基础上持续迭代，帮助创作者构建可运行、可编辑的游戏世界。场、Weave、Xihe 和 CDM 则分别服务于环境交互、几何、光照和角色动作。

**叙事主线：**制作门槛 → AI 为什么需要引擎反馈 → 产品闭环 → 四项技术 → 场景演示 → 市场与商业化 → 发展路线和资源需求。

## 二、内容原则与项目边界

1. 用创作者能理解的结果解释技术：世界能交互、细节可扩展、光照会变化、角色能适应地面。
2. 每项能力明确标注「已有实现」「阶段性实现」或「规划中」；报告中的历史验证只对应当时版本，不能自动代表当前全部工作区。
3. **Weave（簇织）和 Xihe（曦和）：**按现有技术方案介绍为未来研发方向。方案明确运行时尚未开始，部分离线基础已落地；不声称已完成虚拟几何或完整动态全局光照。
4. **场：**已有粒子与烟的共同视觉场协调、部分 GPU 验证；CPU 权威、完整跨系统耦合与最新宿主验收仍有缺项。风、布料、水体联动可作为目标场景，需避免说成全部已打通。
5. **CDM：**已有脚部接触、支撑、骨盆补偿及地形接地等阶段性实现；参考动作库、全面复杂动作等不要表述为已交付。
6. **Agent 反馈：**项目已有 MCP 场景查询、预览、提交与验证等工具；编辑器服务另有原生截图入口，可输出截图路径和场景 revision。当前资料不能证明现有 MCP 已直接提供截图图像给 Agent，也不能证明完整的自主视觉闭环已经端到端跑通。以「已有组件 + 拟打通的目标流程」呈现，并在正式演示前实测。
7. 未经调研或实测，不填市场规模、降本比例、客户数量、营收、融资额和性能领先等数字。

## 三、逐页策划

| 页 | 标题与目的 | 页面核心内容 | 视觉与讲述建议 |
|---|---|---|---|
| 1 | **封面：让小团队创造更大的游戏世界** | 项目名称、主题、副标题、团队信息待补。 | 使用真实引擎画面作为主视觉；如使用概念图须标明。开场提出「让创作者专注创造，让 Agent 参与实现」。 |
| 2 | **游戏世界的制作，为什么仍然困难？** | 场景、资产、光照、环境与角色需要多工种反复协调；小团队面临工具学习与迭代成本。 | 展示传统流程链与反复返工节点；不使用未经验证的行业数字。 |
| 3 | **AI 会生成，还需要能观察和验证** | 仅有自然语言输入不足以保证场景正确、画面符合意图；Agent 需要读状态、看结果、获得错误反馈。 | 一侧展示「指令→结果不确定」，另一侧引出「观察→调整」。用具体案例说明，例如调整场景中一条道路的位置。 |
| 4 | **产品方案：创作者与 Agent 共建游戏世界** | 创作者提出目标，Agent 通过引擎工具查询、预览和修改，原生运行与截图提供验证依据，创作者确认结果。 | 核心闭环图：目标→查询/预览→修改→运行/截图→判断→调整。图中区分现有组件与待贯通流程。 |
| 5 | **关键创新一：Agent 能读取引擎反馈、观察原生画面** | 结构化场景状态、事务结果与错误；原生画面截图及 revision；目标是使 Agent 同时获得「数据反馈」与「视觉反馈」。 | 优先展示真实接口输出与截图配对；演示前验证 Agent 获取图片的实际方式。页面标注「截图入口已具备；端到端视觉闭环待验证」。 |
| 6 | **关键创新二：场——让环境影响共享** | 把风、流动或视觉效果等空间信息组织为可查询、可共享的数据；现有粒子与烟共同视觉场是阶段性切片。 | 风场/粒子/烟的示意图；布料、水体等作为未来扩展，用虚线区别。讲价值：减少各系统各自为政，为一致的环境交互打基础。 |
| 7 | **关键创新三：Weave 簇织——面向复杂世界的虚拟几何** | 规划以几何簇、层级细节与按需流送管理复杂场景，目标是在细节与资源开销之间取得更好的平衡。 | 同一场景从远到近的簇层级概念图；显著标注「研发规划」，不展示未经验证的性能对比。 |
| 8 | **关键创新四：Xihe 曦和——面向动态世界的光照** | 规划动态间接光与反射，让时间、光源和场景变化能够反映到画面；与 Weave 共享几何数据是设计方向。 | 日照变化与室内外光线传播概念图；显著标注「研发规划」。不要把现有光照能力等同于完整 Xihe。 |
| 9 | **关键创新五：CDM——让角色与地面建立真实接触** | 基于接触约束处理支撑脚、脚跟/脚尖滚动、转向和骨盆补偿；已有高度场接地、坡面相关修复。 | 角色上下坡连续帧 + 接触点标注；说明当前为阶段性实现，不承诺任意地形和复杂动作均已解决。 |
| 10 | **一次创作：从意图到可检查的世界** | 示例：「创建山路场景，调整地形与植被，检查角色在坡面行走」。分别展示可复现步骤、引擎反馈、截图与人工确认。 | 以真实演示录屏或截图为主。若 Agent 截图链路未打通，明确展示人工桥接，不伪装成自主闭环。Weave/Xihe 不纳入现有演示。 |
| 11 | **面向谁：先服务小型游戏团队** | 首选独立开发者和中小游戏团队；关注快速搭建、可编辑性和迭代效率。教育或可视化可作为后续探索。 | 用户画像与典型任务；这些是初步定位，需通过访谈验证。 |
| 12 | **商业模式：以工具价值建立持续收入** | 可探索免费试用/基础版、专业订阅、团队协作或企业授权；价格与收费边界待用户验证。 | 从单人试用到团队付费的简洁路径；不把假设写成已有收入。 |
| 13 | **竞争与差异化：以可观察的 Agent 工作流切入** | 与传统引擎工作流、通用 AI 生成工具作定性比较：引擎内可编辑、结构化反馈、画面验证、可复现工作流是拟打造的组合价值。 | 用对比表但避免绝对化或断言竞品不具备某能力；正式版须补竞品调研。 |
| 14 | **阶段成果与发展路线** | 已有：场景事务与原生截图入口、世界生成主体、共同视觉场切片、CDM 部分功能；下一步：打通并验证 Agent 闭环、补场联动验收；长期：Weave/Xihe 运行时研发。 | 三阶段横向路线图，不编造时间承诺。列出每阶段可验证交付：真实演示、可复现报告、用户试用反馈。 |
| 15 | **愿景与合作诉求** | 愿景：让更多创作者具备构建丰富互动世界的能力。明确寻求的试用团队、技术合作、资源或资金，具体由项目方填写。 | 以真实项目画面收尾；团队信息和融资需求留待确认。 |

## 四、演示与素材准备

- **优先演示 Agent 反馈链：**固定一份场景和明确目标；记录查询、预览、提交、运行反馈与原生截图；核对截图与 scene revision，展示一次基于反馈的调整。先验证所用 Agent 实际能否取得并查看截图；若不能，诚实说明人工桥接和待开发部分。
- **场：**选取已有粒子/烟共同场报告对应的画面或复现可用场景，保留对应版本和验证条件；不同系统完整耦合作为示意。
- **CDM：**从内置动作测试场景录制平地、坡面与转向；录制前确认运行版本与当前实现一致。
- **Weave/Xihe：**使用标明「概念示意 / 研发规划」的示意图，不用概念图冒充运行画面。
- **原生素材：**记录场景、版本、运行条件与截图来源；不要用旧报告推断最新工作区已经通过。
- 演示准备失败时保留可复现的截图与日志，明确演示是录制还是实时操作。

## 五、视觉风格与时间分配

视觉风格建议采用深色科技底色、清晰的青蓝与暖金强调色；优先使用真实引擎画面、简洁流程图和局部技术标注。技术术语首次出现时配中文解释，单页只保留一个核心结论。概念图和实际截图使用统一但清楚可辨的标签。

建议时间：背景和问题 2 分钟；Agent 产品闭环 3 分钟；四项技术 4–5 分钟；演示 2 分钟；商业与路线 2–3 分钟。答辩预留关于实现状态、技术验证、目标用户和商业化的追问。

## 六、正式制作前待补资料

1. 宣讲场景、时长、听众与主办方要求；团队名称、成员与可公开信息。
2. 可展示的最新引擎截图、演示视频，以及 Agent 获取原生截图的实际接入方式和验证结果。
3. 用户访谈、潜在客户需求、竞品和市场资料；对外数据需要可追溯来源。
4. 希望提出的合作诉求、融资需求、资金用途和阶段目标；没有可靠信息时留空。
