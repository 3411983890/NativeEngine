## 二、阶段二：单支撑点求解

| 方案要求 | 现状 | 证据 |
| --- | --- | --- |
| 以脚底实际接触点而非脚踝为约束目标 | 已实现 | 锚点存于接触面局部空间，滑动在鞋底接触点上测量（`FootState::pivot`） |
| 区分脚底位置、脚掌方向、脚尖旋转 | 已实现 | `ContactMode::Flat/Heel/Toe` + 绕接触边的刚体滚动（`rolledAnkle`、`soleEdge`），脚骨与脚趾分别对齐 |
| IK 前计算有限的骨盆水平、垂直、旋转补偿 | 部分 | 水平（按伸展度投票、限幅 `maxPelvisShift`）与垂直（最深需求 + 过伸下沉）已实现；**骨盆旋转补偿未实现** |
| 明确约束优先级：地面接触 > 腿部可达 > 身体目标 > 基础动画 | 已实现 | 接触可达才锁；接近满伸时先削滚动角，其次提前释放，最后才交给动画（`Overreach`） |
| 支撑期锚点不得无意移动，释放需记录原因 | 已实现 | 释放原因逐脚可读；重锚只发生在落步/换表面/超伸 |
| 过渡期控制权重，避免“看着锁了实际只修一半” | 已实现 | 权重 18/s 渐入并吸附到 1；`weight ≤ 0.98` 期间的位移记为 `switchJump` 而非滑动 |
| **验收：左右脚分别支撑、身体转动、小范围移动都保持稳定；超范围触发换步或降级** | **达成** | 单支撑 98.6% 稳态占比；转向 `contactSlip = 0.000`；超伸触发 `Overreach` 释放并进入 `fallback = unreachable` |

## 三、阶段三：双支撑与转身换步

| 方案要求 | 现状 | 证据 |
| --- | --- | --- |
| 同时求解左右脚，而非各自修正争夺骨盆 | 已实现 | 共享骨盆求解：垂直取最深需求，水平按伸展度加权，避免左右偏置 |
| 双脚站稳时身体先在允许范围内转动 | 已实现 | `pivotLimit = min(turnThreshold, maxTwist)` 内骨盆带动，超出后按残留量枢轴旋转 |
| 达到阈值后按方向、可达性、重心选择先抬哪只脚 | 已实现 | `candidate` 取需求最大的支撑脚，落点用 `sampleLanding` 验证 |
| 摆动脚落地后再交换；快转时提前落地 | 已实现 | `hurry` 判定在身体转过一 step 可吸收量时立即落地 |
| 快速反向、连续旋转、两脚不同高度 | 部分 | 连续转向（2.4 rad/s、460 tick）已验证；**反向急停与两脚异高台阶未单独用例** |
| 脚跟/脚尖支撑作为可配置模式 | 已实现 | `soleRoll` 资产默认 + 场景覆盖；脚尖支撑时绕前掌转动而非整只钉死 |
| **验收：慢转、快转、反向、连续转向无明显水平滑动，无交叉/过伸；无解有明确回退** | **基本达成** | 连续转向 460 tick：支撑 100%、意外滑动 0.000 m/s、主动枢轴 0.41 m/s、单脚摆动始终成立（`swinging ≤ 1`）；快速反向尚无独立用例 |

## 四、阶段四：扩展为多接触引擎能力（数据契约与手臂链已落地）

> 2026-10-28 更新：本轮补上通用接触集合、优先级、有效期、任意骨骼绑定、允许滑移与手臂链识别，详见 [多接触层实现记录](CONTACT-DRIVEN-MOTION-MULTI-CONTACT.md)。

| 方案要求 | 现状 |
| --- | --- |
| 脚踩地、脚尖支撑 | 已实现（双腿专用求解器，脚掌滚动与接触边） |
| 手扶墙、抓扶手、攀爬手点 | **求解与数据层已实现**：`detectArmChains` 识别左右手臂链写入 `rig.arms`，原生自动注册为接触链（左=0、右=1），`setContact` 以表面局部锚点驱动两骨 IK；**攀爬/抓取行为状态机未实现** |

## 五、“如何判断是否真正解决”的六项

| 判据 | 状态 | 数据 |
| --- | --- | --- |
| 位置误差（最终显示脚底 vs 锚点） | 已度量 | `anchorError` ≤ 0.0039 m（3 m/s）、0.0012 m（1 m/s） |
| 相对滑动（相对地面/平台速度） | 已度量 | `contactSlip` ≤ 0.13 m/s；移动平台用例门禁 0.05 m/s |
| 方向误差（脚掌扭转） | 已度量 | `soleAngle` ≤ 0.35 rad（上限 `soleRoll` 0.45）；转向按 `pivotSlip` 单独统计 |
| 状态连续性（换支撑无跳点/无意外双脚释放） | 已度量 | `switchJump` ≤ 0.013 m；稳态双脚离地最长 1 tick |
| 身体质量（膝盖方向、骨盆抖动、腿不穿插拉长） | 部分 | IK 超伸即释放、不无限拉伸；膝盖极向由 pole 决定。**尚无膝盖方向/骨盆抖动的量化门禁** |
| 边界行为（撞墙、快速反向、跳跃、传送、斜坡、不可达） | 部分 | 传送（`Teleport` ×2）、斜坡、跳跃离地（`NotGrounded`）有测试；**撞墙、快速反向、台阶高度差未单独用例** |

## 六、结论与建议顺序

1. txt 的阶段一～三已经落地并通过数值验收，本轮把其中“真正不滑”这条从 1.05 m/s 收进了 0.13 m/s。
2. txt 的阶段四数据契约已完成（通用接触集合、优先级、有效期、任意骨骼绑定、允许滑移、手臂链识别），**行为层仍未做**：攀爬/抓取状态机、四足步态、编辑器可视化。因此 txt 整体仍是“阶段四部分完成”。
3. 建议顺序：先补 Game 层门面（`setCharacterContact/releaseCharacterContact`）让场景能用上接触；再做“手扶墙/扶手”行为用例（抓取判定 + 沿墙移动）；四足另立能力定义，不能由双足推定。
4. 回归手段已就绪：`native_animation_tests` 5,350 基础断言 + 266,788 项检查通过，含接触链、滑移与存档续跑用例。
