# 接触驱动动作系统 · 支撑脚滑动收敛（P1.1）

日期：2026-10-28
上一轮记录：[P1 单支撑 · P2 双支撑与转向](CONTACT-DRIVEN-MOTION-IMPLEMENTATION.md)
方案与验收边界：[CONTACT-DRIVEN-MOTION-DEVELOPMENT.md](CONTACT-DRIVEN-MOTION-DEVELOPMENT.md)

本轮目标不是新增阶段，而是把方案 §3.2/§4 的“接触优先、无解时明确降级”真正落到求解器里：上一轮虽然建立了接触约束与度量，但支撑末期仍报告 **1.05 m/s** 的鞋底滑动，用户最初描述的“左脚还在滑”并未消除。

## 1. 逐 tick 探针定位（P0 补做）

用一次性探针（只链接 `animation*.cpp`，结束时已删除）复现 3 m/s 行走 240 tick，逐 tick 导出每只脚的 `locked/phase/mode/weight/roll/pivoting/release/target/previous` 与四项指标。探针不进入测试目录，结论：

| 现象 | 真实原因 |
| --- | --- |
| 滑动尖峰只出现在每步 1～2 个 tick，且都落在 `mode = Toe`、`roll ≈ 0.26` 的 tick 上 | 脚尖滚动把踝目标绕前掌边抬起，当时腿已在 100% 伸展，目标超出手臂可达范围 → IK 钳制 → 接触边被拖着走 |
| 站立/接地阶段稳定存在 0.1～0.2 m/s 的“慢滑” | `targetLocal` 预钳制在 `legReach × 0.995`，直腿支撑时永远差 0.5%（≈7 mm），随着身体前进一点点被拉回 |
| 水平骨盆补偿实测恒为 0 | 补偿量用的是“动画踝正下方”的地面点，与动画踝的水平差**按构造**就是 0，该项从来没生效过，腿过伸时骨盆不会跟 |
| 双支撑时补偿互相抵消 | 两只脚的需求一前一后取平均，结果趋近 0 |
| 转向一步后 `contactSlip` 出现 11.5 m/s 的假尖峰 | 换步/重锚把接触点按设计搬到新位置，但测量没有重启，把“主动换步”记成了滑动；快速转向时上一 tick 的主动转动也让下一 tick 的比较基线失效 |

## 2. 实现改动

`engine/native/animation_features.cpp` / `animation.hpp`：

1. **滚动可达预算**（`rolledAnkle` + IK 前预算）。脚尖/脚跟滚动后若踝目标超出腿长，按 1、1/2、1/4、1/8、0 五档缩减滚动角，取第一个可达档；接触边在滚动角变化时不动，因此“放弃一点抬脚”不会把鞋底拖走。计数进入 `FeatureMetrics::rollLimited`。
2. **取消 0.995 预钳制**。支撑腿允许完全伸直，只有真正超出 `legReach` 才回拉；落地阶段的 7 mm 静止偏差消失。
3. **水平骨盆补偿改为按“伸展度”投票**。需求改由**锚定目标**（`FootState::flat`）减去动画踝得到；只有 `required / legReach` 接近 1 的腿参与投票，并按权重归一化。等价于“腿快伸直的脚说了算”，避免双支撑互相抵消。
4. **站立不参与水平补偿**。静止时直腿骨架天然“过伸”，若参与投票会把程序化呼吸/重心摆动当作过伸去抵消（`Static idle clip must still produce visible idle motion` 会失败）。水平补偿仅在 `Walk/Run` 生效。
5. **预测性抬脚**。维持判定新增 `stretching`：以落锁时的髋-锚距离 `FootState::reachAtPlant` 为基准，若本次支撑已经把它拉长 2 cm 且已到 99% 腿长，则本 tick 就释放（原因记 `Overreach`）。这是方案 §3.2“预测即将不可达时提前换步”的最小实现：不再让 IK 硬撑，也就不再拖接触点。
6. **度量修正**（不改物理，只改读数）：
   - 重锚/落步时重置滑移测量（`pivotValid = false`）：主动换步不再被算成滑动；
   - 新增 `FootState::pivoted`（上一 tick 是否主动转动），跨主动转动边界不做比较，把转向的位移留在 `pivotSlip`；
   - 接触模式（整脚/脚跟/脚尖）改在滚动预算**之后**判定，避免“想滚→被削减→模式翻转”每 tick 重置测量，使真实滑动隐身。
7. **持久化**：`FootState::flat/reachAtPlant/pivoted` 进入存档（缺省可恢复）与状态摘要 `hashFeatures`；`reachAtPlant` 影响后续决策，必须存档。

`host/main.cpp` 报告新增 `animation.rollLimited`。

## 3. 结果（内置机器人，modelScale 1.84，平地，240 tick）

| 指标 | 改动前 | 改动后（稳态 91–300 tick） |
| --- | --- | --- |
| 鞋底接触点滑动（最大） | 1.05 m/s | **0.13 m/s**（1 m/s 0.14，2 m/s 0.15，4 m/s 0.69） |
| 锁定脚踝残差（最大） | 0.0276 m | **0.0039 m** |
| 有支撑脚的 tick 比例 | 87.5%（含 30 tick 混合期） | 86.2%（含混合期）/ 98.6%（稳态） |
| 交接跳点 | 0.013 m | 0.013 m |
| 水平骨盆补偿 | 0（从未生效） | 0.100 m（上限 0.129 m） |
| 穿透 | 0.019 m | 0.0196 m |
| 脚尖滚动次数 | 4 | 4（`rollLimited` 0） |
| 原地转向（2.4 rad/s，460 tick） | 未度量 | 接触滑动 **0.000**，主动枢轴 0.41 m/s，支撑 100%，单脚摆动 |

转向数据说明度量拆分生效：转向时鞋底确实在原地转，这部分记入 `pivotSlip`，`contactSlip` 保持 0。

4 m/s 明显变差（0.69 m/s、穿透 0.049 m）：walk 片段被重定时到约 4 倍，超出该片段可表达的速度范围，属于内容/参考库问题（P3），不是求解器项。方案 §5 的“超出适用范围明确降级”在此处尚未实现。

## 4. 测试与门禁

`tests/animation_features_tests.hpp`：

- 行走：`walkSlip` 门禁 1.2 → **0.2**，`walkAnchor` 0.04 → **0.01**，`walkPenetration` 0.04 → **0.03**；支撑比例门禁由 17/20 放宽为 5/6，理由写在注释里（前 30 tick 是 idle→walk 混合期，按设计两脚都不锁）。
- 转向：新增 `turnSlip < 0.05`（实测 0.000）与 `turnPivot > 0`（实测 0.41）两条，用来固定“主动转动与意外滑动分离”的性质。

### 5.1 一次误判的记录（避免重复踩坑）

本轮中途曾判定"工作区 `Game::initialize()` 崩溃、与改动无关"，并写进了文档。**该结论是错的**：崩溃来自我手工链接测试程序时漏掉 `engine/native/gameplay_bridge.cpp`，于是链接器从 `build/gameplay/nativegpu-gameplay.a` 里取了一份更早编译的 `Game::syncGameplay()`，与当前 `Game` 布局不一致。补上该源文件后 `Game::initialize` 正常，全套测试通过。

教训：手工编译该工程时，`build.ps1` 的目标列表并不等于完整依赖——`game.cpp` 的桥接实现在 `gameplay_bridge.cpp`，静态库里还有一份旧副本，漏掉源文件不会报链接错误，只会在运行期崩溃。

## 6. 与方案后续阶段的差距
