# 动画系统技术方案（Trait DAG + 动作匹配 + 分层物理 + 面部绑定）

- 版本：v0.4（M1–M4 可运行首版已接入；面部与高级扩展继续规划）
- 日期：2026-10-22
- 范围决定：暂不开发任何必须依赖机器学习或神经网络的功能。传统 Motion Matching、规则驱动 Rig、数值 IK、表观肌肉和局部软组织的首版已实现，范围见 [ANIMATION-M1-M4.md](ANIMATION-M1-M4.md)；手工面部绑定与高级扩展仍为计划。AnimGen、Learned Motion Matching、神经网络推理与训练均延期。
- 方案编写时基线：NativeGPU 0.6.0（D3D12、Mesh Shader、DXR 静态阴影、确定性场景事务；当时无骨骼动画、无蒙皮；当前实现边界见 `ANIMATION.md`）
- 目标硬件：RTX 5060 为主目标，Radeon 890M 作为低端回退验证
- 状态：E04 首条纵向链路已落地：glTF 蒙皮导入、16 骨骼/6 Clip、VS 蒙皮、Trait DAG、五状态、分层混合、惯性化、Notify 与阶段哈希。A2 的无脚滑、A3–A12 的高级能力仍未完成，不能据此宣称全部方案完成。实现和可重放证据见 `docs/ANIMATION.md` 与 `reports/latest/animation-evidence.json`。动画线不依赖 GPU 底座；当前宿主沿用 Web 编辑器 + 独立原生预览的既有选择。
- 参考来源：AnimNext/UAF（Epic，实验性）、Animation Blueprint（UE4/UE5）、Motion Matching（Ubisoft, GDC 2016）、Inertialization（Bollo, GDC 2018）、Learned Motion Matching（Holden et al., SIGGRAPH 2020）、RigLogic / MetaHuman DNA、ARKit 52 通道规范。具体链接在评审时补齐，标注「需核实」的条目在实现前必须用官方文档或实测确认

## 0. 结论摘要

1. **动画做成"确定性数据流 + 分层姿态运算 + 可验证质量"**：用 AnimNext 的数据模型，用 Animation Blueprint 的能力清单，但**两样都不照抄**。
2. **不实现 ABP 式虚拟机，也不做 Update/Evaluate 线程分裂**。全流程单线程确定性求值；未来并行只并行"同 stage 内无数据依赖"的 trait，归约顺序固定。
3. **动作选择与姿态计算分离**：离散决策（选哪一帧）必须整数化、可日志、可回放；连续计算可以近似。
4. **物理只写增量，不改意图**：辅助骨骼增量写姿态缓冲；肌肉和软组织的顶点增量使用独立 DeformationBuffer，并有各自的误差预算。不得改写角色碰撞根或动作选择。
5. **面部走 ARKit-52 + 校正**，不做 MetaHuman DNA 级自建内容；DNA 读取器作为可选加速路径，前提是授权明确。
6. **全 CPU + 轻 GPU**，不依赖 compute/HZB/TAA 底座。这是所有方向里最快能出可验收成果的一条线。
7. **每一层都可哈希**，把"动作为什么错"从不可查变成可复现。

## 2. 设计原则

1. **确定性优先于性能**。先能逐帧复现，再谈并行。
2. **显式数据流**。每个 trait 声明读哪些通道、写哪些通道；越界在 debug 期直接失败。
3. **选择与计算分离**。S1 只做离散决策；S2 之后只做连续混合。
4. **物理只加细节**。物理层不得写根骨骼，不得改变运动意图，超出预算必须衰减。
5. **每层可观测**。每个 stage 结束输出哈希、耗时、可选截图。
6. **内容可替换**。运行时与内容解耦：换绑定、换动作库、换 DNA，运行时不变。
7. **失败要显式**。缺骨骼、缺通道、缺纹理必须报告，不允许静默回退成 T-pose。

## 3. 架构总览

```text
┌──────────────────────────────────────────────────────────────┐
│ 输入：Intent（速度/朝向/状态/语义标签/面部控制）               │
└───────────────────────────┬──────────────────────────────────┘
                            ▼
┌── Trait DAG（固定拓扑 + 固定顺序 + 显式读写掩码）─────────────┐
│                                                              │
│  S1 Select   ← 动作匹配 / 状态机 / 选择器（离散决策，写日志）   │
│  S2 Blend    ← 片段采样 + 惯性化 + 按骨骼分层混合              │
│  S3 Correct  ← 脚部 IK / 距离匹配 / 运动扭曲                   │
│  S4 Deform   ← 表观肌肉 / 软组织增量（物理，带预算）            │
│  S5 Emit     ← 生理总线 → 材质/标量参数（不写 pose）           │
│                                                              │
│        每阶段结束：stageHash += 量化后的写入通道               │
└───────────────────────────┬──────────────────────────────────┘
                            ▼
              PoseBuffer（扁平、SoA、双缓冲） → digest / 渲染
```

面部是**独立的 PoseBuffer 与独立流水线**，可以跑不同频率（面部 60 Hz、身体 30 Hz），只在渲染前合并。

## 4. 核心数据模型

### 4.1 PoseBuffer

```cpp
// renderer 与 engine 共享的扁平姿态缓冲。SoA 布局，固定容量，双缓冲。
struct PoseBuffer {
    static constexpr int MaxBones = 256;

    float translation[MaxBones][3];
    float rotation[MaxBones][4];   // quaternion, xyz w
    float scale[MaxBones][3];
    float layerWeight[MaxBones];   // 分层混合权重，0..1

    CurveSet curves;               // 相位、归一化时间、速度等标量轨道
};

struct CurveSet {
    static constexpr int MaxCurves = 32;
    float value[MaxCurves];
};
```

### 4.2 Trait

```cpp
enum class Stage { Select, Blend, Correct, Deform, Emit };

struct BoneMask {
    uint64_t bits[4];              // 256 位
    bool has(int bone) const;
};

struct Trait {
    BoneMask reads;                // 显式声明
    BoneMask writes;
    Stage    stage;
    int      priority;             // 同 stage 内排序键
    uint32_t id;                   // 稳定 id，参与排序与日志
    bool     deterministic;        // true 才参与哈希

    void evaluate(const Intent& in, PoseBuffer& out, Hasher& h);
};
```

### 4.3 三条硬约束

1. 只能写自己声明的通道。debug 期在 `evaluate` 前后对比掩码，越界立即报 `NG-E-ANIM-MASK`。
2. 同 stage 内按 `(priority, id)` 升序执行，**顺序是契约的一部分**；改顺序即改行为，必须在提交信息中注明。
3. `deterministic=false` 的 trait 不允许出现在 `Select` 与 `Blend` 阶段。

## 5. 求值流水线

| 阶段 | 职责 | 确定性 | 主要输出 |
|---|---|---|---|
| **S1 Select** | 动作匹配、状态机、Chooser | 必须 | 片段 ID、帧号、混合权重、决策日志 |
| **S2 Blend** | 采样、惯性化、按骨骼分层 | 必须 | 基础姿态 |
| **S3 Correct** | 脚部 IK、距离匹配、运动扭曲 | 必须 | 修正后姿态 |
| **S4 Deform** | 表观肌肉、软组织增量 | 可近似 | 形变后姿态 |
| **S5 Emit** | 生理参数 → 材质/标量 | 不参与 | 不写 pose |

**每阶段结束调用一次 `hasher.quantized(...)`**，形成哈希链。任何一段与参考不一致，可定位到具体阶段。

## 6. 确定性契约

### 6.1 规则

1. **决策整数化**：动作匹配特征量化为 `int16`，距离用整数运算。
2. **固定遍历顺序**：KD-tree 查询顺序写死，不依赖并行归约。
3. **浮点只出现在混合**：S2 之后单线程固定顺序求值。
4. **每阶段一个哈希**，链式累积进现有 `digest()`。
5. **决策日志落盘**：`(tick, 选中片段, 帧号, cost, 次优帧, 次优 cost)`。

### 6.2 确定性等级

| 等级 | 承诺 | 范围 |
|---|---|---|
| D0 | 同一二进制、同一机器，逐帧一致 | 必须达成（CI 门禁） |
| D1 | 同一二进制、跨机器架构，逐帧一致 | 目标，允许个别阶段降级 |
| D2 | 跨平台逐位一致 | 不承诺；只承诺统计一致 |

### 6.3 哈希链

```text
h0 = hash(Intent)
h1 = h0 ⊕ hash(S1 写入通道 + 决策)
h2 = h1 ⊕ hash(S2 写入通道)
h3 = h2 ⊕ hash(S3 写入通道)
h4 = h3 ⊕ hash(S4 写入通道)
digest = h4
```

只哈希"被写入的通道"，不哈希整块缓冲，避免未初始化数据污染。

## 7. 动作匹配（S1）

### 7.1 特征向量

| 特征 | 维度 | 说明 |
|---|---|---|
| 未来轨迹 | 6 | 0.2/0.4/0.6 s 后的角色空间位置 |
| 未来朝向 | 3 | 同上的朝向增量 |
| 左脚位置 + 速度 | 6 | 角色空间 |
| 右脚位置 + 速度 | 6 | 角色空间 |
| 根速度 | 2 | 水平面 |
| 相位 | 2 | sin/cos |
| 髋高 | 1 | 归一化 |

合计 26 维。每维独立权重，暴露为配置。

### 7.2 量化与搜索

- 每维按统计范围映射到 `int16`（`[-32768, 32767]`）。
- 距离用加权 L1 或加权 L2 的整数版本，**不使用 SIMD 归约**（顺序不确定）。
- KD-tree 构建一次，运行时只查询；叶节点内按帧号升序扫描，保证平局确定。
- 查询返回 top-K（K=8），S1 取最优，但把次优一起写进日志。

### 7.3 决策日志

```json
{ "tick": 1042, "clip": "run_fwd_02", "frame": 37, "cost": 1184,
  "alt": [{"clip": "run_fwd_01", "frame": 41, "cost": 1201}] }
```

日志可回放：给定同样的 Intent 序列，日志必须逐帧一致。这是 CI 门禁之一。

## 8. 混合与过渡（S2）

### 8.1 惯性化（Inertialization）

用弹簧-阻尼衰减姿态差值，替代 cross-fade，避免姿态跳变与脚滑：

```text
给定源姿态 P0、目标姿态 P1、初始速度 v0
offset(t) 由临界阻尼弹簧解析解给出，叠加到 P1 上，随时间衰减到 0
```

**必须用解析解**，逐帧积分会引入非确定性。

### 8.2 分层混合

- 基础层：下半身 locomotion。
- 上层：Montage/Slot（攻击、交互），按 `Blend Profile` 逐骨骼加权。
- 加性层：呼吸、镜头晃动、受击抖动。

### 8.3 Montage 与 Notify

- Slot 节点决定 Montage 插入点。
- Notify 在固定 tick 上派发，事件进入 gameplay 队列，**不直接改 gameplay 状态**（保持单向依赖）。

## 9. 修正层（S3）

### 9.1 程序化 Rig 底座（A4a，优先）

- 建立 Rig 资产：骨骼语义映射、骨链、控制点、参考姿态、关节限制、膝肘 pole vector、控制空间和显式读写掩码。骨骼命名不再直接绑定业务逻辑。
- 增加局部 / 模型 / 世界空间转换和求解后层级更新；求解节点沿用 Trait DAG，不以节点编辑器或 VM 为首版前置。
- 首批节点：FK、Two-Bone IK、Look-at、目标混合；多目标全身 IK 为后续 A4c。
- 增加统一地面 / 障碍查询接口、法线和移动平台速度；固定 tick 内读取一致的环境快照。角色台阶、斜坡与碰撞能力单独验收，IK 不代替角色移动。
- 扩展 Intent：期望与实际速度向量、移动 / 视线朝向、未来轨迹、动作标签、接触与交互目标。玩法决定角色运动，碰撞后的实际位移反馈给动画；Root Motion 驱动模式后续显式加入，禁止双重积分。
- 加入脚接触标记、接触相位同步、脚锁定 / 解锁、骨盆高度与法线对齐；锁定目标保存在地面或平台局部空间，避免把移动平台误判成脚滑。

### 9.2 修正节点（A4b–A4c）

| 功能 | 做法 | 验收 |
|---|---|---|
| 脚部 IK | 两骨 IK + 地面射线 + 骨盆下沉 | 接触期脚滑 < 0.05 m/s |
| 距离匹配 | 按剩余距离缩放播放速率 | 起停无滑步 |
| 运动扭曲 | 目标点对齐（开门、翻越） | 手/脚落点误差 < 2 cm |
| 膝关节保护 | 极角约束 + 软限制 | 无反转 |

验收场景包括静止、起停、急转、斜坡、台阶、移动平台和不可达目标；接触速度以接触面为参考。不可达时限制伸展并记录剩余误差，不以拉长骨骼掩盖问题。

## 10. 物理层（S4）

### 10.1 表观肌肉（Apparent Musculature）

**目标：不解肌肉控制问题，只解"看起来像肌肉在动"。**

1. **A6a 形变底座**：导入稀疏 morph POSITION / NORMAL delta、统一顶点索引与空间语义、静态 GPU 存储和逐帧权重；提供独立 DeformationBuffer，不能复用已有骨骼预算冒充顶点预算。当前导入器拒绝 morph，必须先扩展资产版本、校验器和渲染路径。
2. **A6b 肌肉资产**：记录起止锚点的骨骼与局部坐标、静止长度、影响权重、最大隆起、关节角响应曲线和手工校正形状。首版只做上臂 / 前臂少量区域，不预设全身肌肉数量。
3. **驱动**：关节角、长度变化、显式用力 / 动作曲线驱动收缩与隆起，并按固定 tick 平滑。拉伸程度不等于神经激活；首版不称为 Hill 生理肌肉模型，也不从长度唯一推断真实肌力。
4. **形变**：手工 morph / 辅助骨骼与姿态空间校正，增加肘肩体积保持和挤压修正；使用解析曲线，或对手工参考姿态做固定参数插值，无训练依赖。
5. **顺序**：身体基础姿态 → IK 修正 → 姿态驱动肌肉权重 → 绑定空间 morph → 蒙皮 → 软组织模型空间位移 → 法线 / 切线处理。其他空间的校正必须显式声明转换，防止重复蒙皮。

验收：固定屈伸与转腕序列的轮廓、局部体积变化、最大位移、法线和关节穿插；左右及极限姿态对比、禁用后恢复基准。参考网格和容差随内容冻结，不能以“有隆起”作为唯一通过条件。

成本尚未测量。记录 CPU 求值 / GPU 形变耗时、活跃通道、顶点数及显存，首版同时比较静态 delta 缓冲和纹理存储；不预先承诺微秒级开销。

### 10.2 局部软组织（A7，已纳入计划）

- **A7a 次级运动**：先做少量辅助骨骼 / 代理点弹簧阻尼，驱动上臂等局部晃动；固定子步、位移 / 速度限制，不驱动碰撞根。
- **A7b 局部 XPBD**：低分辨率代理组织网格、固定迭代顺序的距离 / 体积约束、骨骼附着与胶囊 / 球体碰撞；嵌入映射到渲染网格。分别报告代理点、约束、四面体和渲染顶点数量，不混淆单位。首版不做全身 FEM 或自碰撞。
- **A7c 稳定性与 LOD**：根据距离与预算减频或关闭；切档渐变、传送重置、暂停恢复、热重载和存档恢复均定义状态迁移规则。面颊 / 下巴须在面部绑定与接触校正后再接入，保护嘴唇和眼睑。
- 验收：静止收敛、冲击后衰减、快速转向、极限关节、碰撞穿透、体积误差、LOD 连续性；重复输入对拍，无 NaN 或能量持续增长。数值阈值在代理资产试验后冻结，再作为 CI 门禁。

### 10.3 预算算子

物理层输出姿态增量 Δ，引擎按姿态度量衰减：

```text
||Δ|| = Σ_bones w_b * (|Δp| + α|Δq|)
Δ' = Δ * min(1, budget / ||Δ||)
```

超预算的部分记日志并计入质量门禁。该公式只覆盖骨骼增量；顶点形变另记录最大 / RMS 位移、局部体积误差及接触区穿透，分别限制肌肉和软组织贡献。回放必须保存会影响未来结果的速度、约束历史、接触 / LOD 状态及资产指纹；D0 先以固定 CPU 求解路径验收，GPU 图像按容差检查。

## 11. 生理总线（S5）

参数（不是模拟）：

| 参数 | 范围 | 消费者 |
|---|---|---|
| 心率 | 40–200 bpm | 血管搏动频率、面部微动 |
| 体温 | 35–40 ℃ | 皮肤潮红（SSS 血液项）、出汗 |
| 肾上腺素 | 0–1 | 瞳孔、面色、呼吸幅度 |
| 疲劳 | 0–1 | 姿态塌陷、眨眼频率 |
| 酒精/药物 | 0–1 | 眼球运动、平衡 |

总线本身只输出材质参数与着色器常量，不写 pose；这些是美术参数，不作为真实生理模拟。若疲劳 / 呼吸等要驱动姿态，必须通过另一个显式声明写通道的确定性 trait。凡影响未来模拟、姿态或回放的参数与调度状态都进入摘要；只供显示的派生材质量可从摘要中排除，不能仅因位于 S5 而一律忽略。

## 12. 面部系统（A8–A12）

### 12.1 数据模型

```cpp
struct FacialRig {
    static constexpr int MaxJoints   = 32;
    static constexpr int MaxChannels = 128;

    Joint   joints[MaxJoints];        // 下颌、眼球、舌头；中性变换 + LOD
    Channel channels[MaxChannels];    // 稀疏 delta：索引数组 + 向量数组 + LOD
    AnimatedMap maps[16];             // 抖动/皱纹图，由权重驱动
    Corrective  correctives[64];      // 手工 PSD / 固定参数插值；无 MLP
    Driver      drivers[64];          // raw control → expression
};

struct FacialState {
    float controls[52];               // ARKit-52
    float jawOpen, eyeLookX, eyeLookY;
};
```

### 12.2 求值顺序

```text
1. raw controls（52）
2. drivers → expression（组合出"微笑""皱眉"等）
3. correctives：手工 PSD（关节驱动）+ 接触校正 + 显式组合规则
4. 输出：joint transforms、channel weights、map params
```

核心面部求值器使用固定顺序规则和插值；D0 须由同二进制同机器的对拍验证，不能仅由“纯函数”推断。眨眼 / 视线调度、输入曲线和可选面部软组织的历史状态另行进入回放。

### 12.3 校正优先级

1. **关节驱动（PSD）**：下颌张开 → 脸颊/颈部拉伸；眼球转动 → 眼睑滑动。
2. **接触校正**：唇闭合接触、舌齿接触、眼睑闭合。**这是"像不像人"的分水岭。**
3. **抖动/皱纹图**：按表情强度驱动法线（鼻唇沟、额头纹、鱼尾纹）。
4. **组合校正**：微笑 + 张嘴、闭眼 + 视线等使用手工组合 morph、PSD 或固定参数 RBF 插值。参考姿态、权重和半径由作者提供；不引入训练、自动拟合或神经网络。

### 12.4 GPU 路径

- 候选为常驻 GPU 的稀疏 / 稠密 delta 缓冲或 `R16G16B16A16_FLOAT` morph texture，复用 A6a 的存储与空间合同；纹理采用分块寻址并校验设备尺寸限制，不能直接假设所有顶点放在一行。
- 顶点着色器按活跃通道累加；首版上限暂定 16，需通过组合表情裁剪误差验证后冻结。每帧只更新权重与活跃索引，不重复上传静态 delta。

稠密位置 delta 内存参考：52 通道 × 2 万顶点 × 8 字节 ≈ 8.3 MB；不包含法线、切线、纹理分块填充和其他角色资源。

### 12.5 渲染清单

| 部件 | 要点 |
|---|---|
| 面部皮肤 | 复用层状 SSS；加血液项与厚度图 |
| 眼睛 | 角膜折射 + 虹膜视差 + 泪膜高光；独立 shader 与网格 |
| 牙齿 | 半透 + 高光 |
| 嘴唇 | 双重 SSS（唇红区） |
| 面部绒毛 | 走毛发方案的细丝路径，或壳层近似 |

### 12.6 分阶段开发与内容前置

- **A8a 最小面部链路**：复用 A6a morph 底座，先验收下颌、眼球和少量表情；扩展导入器、面部资产、控制曲线和 GPU 通道累加。当前身体 32 曲线与面部控制集分开定义，显式桥接，不把 52 通道直接塞入现有数组。
- **A8b 控制覆盖**：逐步扩展为 ARKit 风格的 52 个语义控制槽位；这里只作为输入命名约定，不依赖 ARKit 面捕、相机推断或自动识别。允许缺省通道但必须报告覆盖度；完整 52 通道阶段要求内容资产齐备。
- **A9 校正与微动**：手工组合表情、唇闭合、眼睑随动、眨眼、视线和皱纹权重。程序化微动使用固定 tick 和显式种子；几何形变完成后再接动态法线 / 皱纹材质。
- **A10 近景渲染**：分期实现皮肤近似 / SSS、眼睛、牙齿、嘴唇；其材质与渲染依赖单列验收，不阻塞基本表情，也不把现有材质能力视作完整皮肤方案。
- **A11 非 ML 驱动**：先做编辑曲线、脚本 / 事件驱动、预制表情和人工音素时间轴到 viseme；简单音量包络仅驱动张嘴，不能宣称语音识别或准确口型。提供曲线导入、录制、回放和 LOD。自动语音转音素、音频到表情、视频面捕延期。
- **A12 质量与工具**：逐通道滑杆、组合表情回归、唇 / 眼睑间隙、头颈接缝、通道裁剪误差、耗时 / 显存和 LOD 连续性。超过活跃通道上限时采用稳定选择规则并报告丢弃误差，不能静默截断。
- 必需内容：拓扑稳定的面部中性网格、眼球 / 牙齿 / 口腔、表情 delta 和校正参考；先用原创少通道夹具验证，再接真实角色。授权与形变质量须逐资产核验。

| 路径 | 质量 | 成本 | 授权 |
|---|---|---|---|
| 商业 FACS/ARKit 绑定资产 | 高 | $100–1,000 | 清晰 |

## 14. 质量门禁

| 指标 | 阈值 | 测量方式 |
|---|---|---|
| 脚滑 | < 0.05 m/s（接触期） | 脚部世界速度 vs 地面速度 |
| 穿地 | > -2 mm | 脚/膝最低点 vs 地面 |
| 姿态 jerk | < 阈值 | 关节角速度二阶差分 |
| IK 修正量 | < 15° | 最终姿态偏离原始姿态 |
| 决策确定性 | 完全一致 | 同 Intent 序列两次运行，日志逐帧相等 |
| stageHash 一致性 | 完全一致 | 跨运行 |
| LOD 姿态误差 | < 阈值 | 加权关节位置 + 速度范数 |
| 唇闭合间隙 | < 1 mm | 闭嘴帧上下唇顶点 |
| 眼睑穿模 | 0 个顶点 | 眼球 vs 眼睑 |
| 表情覆盖度 | 52 通道极值可达 | 逐通道扫描 |

全部来自实际运行，写入 `reports/<version>/<commit>/<timestamp>/`，超阈值 CI 红。

**沿用现有约定**：能力查询与效果实现分字段；没有截图/时序证据不能宣称完成；不允许为通过测试放宽阈值。

### 15.1 动作匹配实施边界

先用穷举搜索建立可解释的正确性参考，再按实际数据库规模评估 KD-tree / 分块剪枝；26 维只是初始 schema，不预设 KD-tree 一定更快。统计归一化与建索引均为离线数据处理，不训练模型。纳入继续播放偏置、切换惩罚、最短保持时长、动作标签过滤与稳定平局规则；性能报告同时保留搜索质量与查询耗时，不能只验吞吐。

### 15.2 分阶段质量合同

第 14 节的数值是目标，不是已通过的结果。每阶段交付参考资产、固定输入序列、CPU 状态 / 决策证据、图像或几何误差以及性能报告。肌肉增加轮廓 / 局部体积、软组织增加收敛 / 穿透、面部增加组合表情 / 接触 / 通道裁剪 / 头颈接缝指标；尚未冻结的阈值必须在阶段开始时记录单位、测试范围与基准，不得在失败后放宽。角色 LOD、软组织和面部历史加入存档与回放合同，D0 与图像容差检查分开报告。

## 16. 明确不做

- ABP 式虚拟机（节点图 + VM 调用）
- Update/Evaluate 线程分裂
- 全身 FEM / 肌肉驱动的完整人体
- 所有依赖训练或神经网络的功能暂缓：AnimGen / Flow Matching、Learned Motion Matching、RL 物理控制器、神经肌肉控制、ML Deformer / MLP 校正、自动视频面捕、自动语音识别及学习式音频到表情
- AnimNext 兼容层（只借鉴数据模型，不依赖其 API）
- 自建 MetaHuman DNA 级内容（只做读取/烘焙，不做创作）
- 当前实现不得依赖 Python ML、模型权重或推理运行时；已有公开研究仅作背景，不形成开发前置
