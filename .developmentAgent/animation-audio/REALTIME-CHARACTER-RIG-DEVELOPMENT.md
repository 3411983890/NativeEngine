# 通用实时角色 Rig 与脚步控制开发方案

状态：阶段 A–D 已实现（2026-10-27，见 [REALTIME-CHARACTER-RIG-IMPLEMENTATION.md](REALTIME-CHARACTER-RIG-IMPLEMENTATION.md)）；编辑器视口、移动平台专项与性能/回放门禁仍未完成，本文其余部分仍是验收边界与后续扩展方案。  
日期：2026-10-27  
首版对象：导入的双足玩家角色；静止转向及行走防滑。机器人 GLB 只是验收样例之一，不得将模型名、骨骼索引或尺寸写死在引擎中。

## 1. 目标与范围

在现有骨骼动画上增加可配置的实时姿态修正，让角色根据实际运动、身体朝向和地面调整支撑脚、落脚点和身体姿态。首版需要：

- 行走、跑步及启停时，根据脚的支撑期锁定脚底，减少相对地面滑动；摆动期平滑释放并落到合理位置。
- 原地转向时，身体先旋转，支撑脚保持稳定；达到阈值后双脚依次抬起换位，恢复自然站姿。
- 导入不同命名和比例的双足角色后，可自动识别并由用户校正骨骼映射、脚底和关节方向，不依赖特定模型。
- 首版玩家路径接入，并提供配置、状态诊断、可视化和按角色关闭或回退的能力。

目标是可复用的引擎运行能力，不以完整复制 UE Control Rig 的节点编辑器为首版前提。首版建议覆盖平地与盒形碰撞体支持的斜坡、台阶；具体地形范围仍待产品确认。移动平台设计时保留接口并专项验证，其是否列入首版交付待确认。NPC、四足、全身 IK、任意网格地形及完整 Rig 图为后续扩展，不作为首版完成条件。

## 2. 当前基础与限制

- `engine/native/animation.hpp` 和 `animation_features.cpp` 已有骨架、双骨 IK、脚锁点、骨盆高度修正、脚面法线对齐及地面查询接口；动画图已有 Select、Blend、Correct、Deform、Emit 阶段。
- `engine/native/game.cpp` 玩家路径提供实际速度、期望速度、朝向、角速度，地面查询针对物理刚体的盒形碰撞体；不能假设视觉网格表面与碰撞表面一致。
- `tools/offline/animation.mjs` 读取 `extras.nativegpu.rig`；缺少 Rig 时腿链为空。当前腿链要求大腿、小腿、脚直接父子连接；接触信息来自片段元数据，静止速度下倾向于双脚接触。
- 已有接触锁定不包含主动换步状态机；普通导入资产不能保证具备骨骼语义、脚底标定和准确接触区间。NPC 当前不走玩家的程序化控制路径。
- 当前腿链模型不应被宣称适配所有人形骨架。对夹有辅助骨、扭转骨、不同朝向或特殊比例的资产，应验证并提示，不能静默错误匹配。

具体基线实现和现有限制参见 [ANIMATION-M1-M4.md](ANIMATION-M1-M4.md) 与 [外部资产说明](../assets/EXTERNAL-ASSETS.md)。开发前重新核对代码，避免覆盖并行开发中的变化。

## 3. 通用资产与配置契约

### 3.1 角色 Rig 配置

为每个角色提供版本化、可持久化的 Rig 配置，使用骨骼语义而非固定名称：骨盆、脊柱链、左右大腿 / 小腿 / 脚，以及可选脚趾。保存坐标空间、角色前方向、左右侧、脚底相对脚骨的接触偏移与朝向、脚掌长度、膝盖 pole、关节弯曲范围及角色尺寸相关参数。将自动生成的候选、用户确认值和诊断区分保存；重新导入或更换骨架时检查身份与映射有效性，不能将旧索引盲目套到新骨架。

自动映射支持常见命名规则（包括 Mixamo 前缀），结合层级和左右语义校验；同名歧义、缺失骨骼、非双足层级、零长度骨、反射 / 非支持缩放和无法表达的转换必须给出明确错误或关闭对应功能。先兼容现有直接三骨链；带中间扭转骨的模型是否通过链折叠或新求解器支持，应先设计并单独验证，不能误报支持。用户可手动选择并确认骨骼及方向。缺少可选躯干骨时可关闭躯干扭转；缺少必要腿链时回退基础动画。

配置应作为角色资产或项目内持久配置的一部分，遵守现有身份、重导入、打包和场景引用规则；实现前确定具体格式和版本迁移策略，兼容现有 animation/1、animation/2 资产。不要修改源 GLB 或要求用户手工编辑其内部 extras。

### 3.2 动作与接触数据

支持逐片段配置左右脚接触区间或曲线、循环与非循环行为、动作速度和转向语义。优先使用人工确认的数据；可提供依据足部相对地面高度、速度及相位的离线候选，显示置信度，允许逐帧修订。无可靠数据时使用保守推断并提示，不能默认半周期就是正确接触。动画切换、重定向及循环边界需保持时序一致。没有待机或转身片段时，可使用选定静态基础姿态加程序化换步，但不承诺达到专门制作动作的自然度。

## 4. 运行时设计

固定 tick 按以下顺序执行：碰撞后的角色运动和环境快照 → 动画采样与混合 → 接触和转身状态更新 → 身体朝向及步幅修正 → 地面查询、支撑锁定与摆动目标 → 骨盆调整和双腿 IK → 脚掌方向修正 → 形变及蒙皮。明确所有输入和输出的局部、角色及世界空间；动画根位移与玩法位移只选择一个权威来源，禁止双重积分。实际速度而非仅输入速度驱动补偿，防止撞墙时继续按预期速度迈步。

### 4.1 行走与落脚

每脚维护支撑、释放、摆动、落地过渡状态、支撑表面身份、局部锚点、目标、权重和历史位置。接触时锁定地面相对位置；摆动期解除锁定并结合原动画和速度预测目标，按可达范围平滑调整步幅。落点查询必须过滤角色自身、不可行走表面与不合适坡度，并遵循物理碰撞查询的统一语义。保持原动画姿态为主要运动来源，设置位置和旋转修正上限，超限时平滑降级。

脚底偏移、地面法线与可选脚趾信息决定脚掌姿态；台阶边缘采用可配置采样与稳定规则，避免单点查询导致脚掌穿透或突然翻转。骨盆补偿受速度、上下限及平滑约束；双腿冲突或不可达时保持有限解而非拉伸骨骼。移动平台锚点在表面局部空间保存，表面失效时释放；记录相对平台滑动，而不是把平台运动误计为滑步。

### 4.2 原地转向

分别维护目标朝向、身体 / 骨盆可见朝向和脚的支撑朝向。小角度旋转时支撑脚稳定，脊柱分配有限扭转；角差、腿部可达性或站姿超出阈值后，选择一只脚释放并沿平滑的抬脚弧线换位，另一脚保持支撑；落地后按剩余角差选择是否移动另一脚。左右脚选择、抬脚高度、步长、转向阈值、冷却时间、身体扭转上限与插值均按角色比例配置。

定义进入和退出阈值的滞回与最大扭转上限，处理快速反向、连续旋转和目标变化；禁止普通情况下两脚同时处于摆动，除非跳跃等状态明确要求。脚步不可达、无有效落点或连续大角度转向时，应限制扭转并采用明确回退策略。允许未来融合原地转身片段，但首版不能假设资产带有此类片段。

### 4.3 中断、确定性和性能

跳跃、坠落、传送、重生、碰撞体消失、动画切换、角色替换和功能禁用时，定义状态释放和重初始化；避免旧锚点造成瞬移或姿态突变。扩展快照、存档、严格回放与状态哈希，保存影响后续计算的脚状态和转身状态；固定 tick 查询一致的环境快照。对远距离或预算不足的角色设计逐级降频 / 关闭及平滑过渡，首版测量玩家每 tick 查询数和 CPU 耗时；预算以基线测量后确定，不虚构性能保证。

## 5. 编辑器与使用流程

1. 导入角色后检测骨架和动作，展示可用能力、骨骼映射候选、缺失项与原因。
2. 允许在视口确认左右腿、脊柱、前方向、膝盖 pole、脚底和站立姿态；参数随角色配置保存。
3. 预览动作，显示左右脚接触时间轴，支持人工调整和重置自动推断。
4. 提供 Rig 开关及关键参数；运行中显示骨架、地面命中点 / 法线、脚目标、锁点、支撑状态、身体和脚朝向、IK 可达误差及当前回退原因。
5. 配置保存、重导入、重新打开项目和运行包中保持一致。引擎创建的运行时项目和输出遵守 `%USERPROFILE%\Documents\nativeEngineProject\<项目名>` 目录约束。

## 6. 分阶段实施与完成条件

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| A 基线与契约 | 角色能力诊断、Rig 配置格式、资产兼容和映射校验 | 旧角色不回归；无配置、歧义和不支持骨架均有明确反馈 |
| B 通用绑定 | 自动候选、手动映射、脚底 / pole 校准、持久化 | 两个不同命名或比例的双足资产可配置；重导入和重启后配置有效 |
| C 接触与行走 | 片段接触编辑 / 推断、锁脚、过渡、步幅和地面适配 | 平地启停、不同速度及碰撞阻挡下支撑脚稳定，无明显跳脚 |
| D 原地转向 | 身体与脚朝向分离、交替换步及异常降级 | 左右慢转、快转、反向、连续转和转走过渡均稳定 |
| E 工具与交付 | 调试显示、参数调整、保存打包、性能与回放检查 | 用户无需修改源文件即可配置和诊断；样例与测试均可复现 |

参考样例：`futuristic+robot+3d+model.glb` 有 65 根骨骼，左右腿均为直接三骨链，包含 `walk.001`、`run.001`、`jump.001`，未发现项目专用 Rig 元数据、待机或原地转身片段。它用于覆盖 Mixamo 风格命名及缺少转身动作的情况；再选一个骨骼命名、比例或骨架结构不同的合法双足资产，防止实现针对样例硬编码。外部样例的复制、分发和测试夹具使用须先确认其许可；没有许可时仅使用本机路径进行手动验证，自动测试使用项目可分发夹具。

## 7. 测试与验收

- 按改动范围运行增量测试；禁止未经新明确要求运行全量测试、`npm test`、`npm run verify` 或完整 CI。导入相关使用 `npm run test:assets`，需要原生绘制验证时使用 `npm run assets:verify`；动画运行时选择现有动画专项中直接相关的入口，核对实际运行范围后执行。
- 定向测试骨架映射、歧义和损坏输入、资产版本兼容、配置保存与重导入、动作接触周期、左右脚状态转换、不同帧率下固定 tick 一致性及确定性快照续跑。
- 场景覆盖平地行走 / 跑步、启停、不同速度、墙体阻挡、静止左右转、快速反向、连续旋转、起跳 / 落地、传送、落点丢失、不可达目标；斜坡、台阶和移动平台按最终范围分别覆盖。
- 测量支撑脚相对地面或平台的滑动速度、脚底穿透、IK 不可达 / 截断次数、换步连续性及时间开销。阈值基于实际角色尺度、测试场景和固定 tick 先建立基线并经确认，不把现有固定夹具的指标直接宣称为所有角色的保证。结合录制或人工目视评审抬脚、脚尖、膝盖方向和身体扭转；数值合格不能替代观感验收。
- 新增测试、验证命令放在 `.incrementalTesting/` 对应分类，并同步命令索引和 CI 引用；测试场景放 `.screen/`，临时场景放系统临时目录或 `build/` 专用目录并清理。报告放 `reports/` 或其他既有输出目录。

## 8. 需要确认的产品选择

1. 首版地面是否包含斜坡、台阶和移动平台；复杂网格碰撞是否单独排期。
2. 程序化换步的风格、可接受的自然度，以及是否提供待机 / 转身动作素材。
3. 编辑器配置是角色资产级默认值、场景实例覆盖，还是两者均需支持；多角色自动映射的人工确认流程。
4. 不同尺寸角色的画面质量、支撑脚滑动和性能验收阈值；经样例测量后确定。

实现前确认上述范围；未确认的项目不得当作已交付承诺。实施时遵守根目录 `AGENTS.md` 的文件落位、增量测试和保留工作区其他改动要求。
