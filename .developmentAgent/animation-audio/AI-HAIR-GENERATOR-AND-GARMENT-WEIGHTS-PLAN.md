### 0.2 仍未实现（不得描述为完成）

- **阶段 C 的透明、场景投影、GPU guide 与运动稳定性**：D3D12 发丝绘制通道已实现（`renderer/hair_draw.*`、`shaders/hair.hlsl`、`HGP1` 磁盘包与原生读取器），离屏真帧验证了 IA/VS/PS 工作、覆盖率、调试通道、深遮罩自阴影、背光透射与发际线近景；宿主 `--groom` 已把同一通道接进场景帧（与角色共用 HDR 目标、深度与环境光），并有同相机有/无发型的像素差证据。CPU guide 模拟已实现：固定 tick、根固定、头球碰撞、风（目标速度）、逐帧插值并上传，离屏与宿主都验证了拉伸/穿透/根漂移/有风像素差。已实现按根点视深的后到前排序（order 索引缓冲，`stats.transparency` 为 `depth-sorted-alpha`，排序相对上传顺序改变 20,119 个离屏像素）；也实现了发丝到头部骨骼的刚性绑定：宿主从角色 head 骨骼的 skin matrix 驱动发丝，转头时头网格与发丝共用同一变换（25° 转头改变 6,437 个宿主像素 / 40,787 个离屏像素），模拟重力与风按逆变换转回静止空间，深遮罩在静止空间采样。仍未实现：顺序无关或按像素有界透明缓存（跨发丝交叠仍可能次序错误）、向身体与场景投影的毛发阴影（深遮罩只作用于发丝自身）、GPU guide 求解、走跑/跳跃与镜头运动序列抗闪烁、GPU 时序与显存测量。CPU 参考渲染（`engine/hair/render-reference.mjs`）仍是这套通道的数值权威；两者都有测试与出图。

### 0.3 验证入口

- `npm run test:hair`：15 项，纯 JS，约 7 秒。
- `npm run test:garment`：17 项，纯 JS，约 20 秒。
- `npm run test:garment:native`：原生蒙皮布料，9 组约 1350 项断言，约 40 秒；只编译 5 个翻译单元，不调用 `tools/build.ps1`。
- `npm run test:hair:draw`：发丝绘制契约 9 项 + GPU 上传契约 8 项（含磁盘包往返与篡改拒绝），约 8 秒，输出 PNG 到 `build/hair-render/`；`npm run hair:sample` 生成可复现样例记录 `build/hair-sample/record.json`。

- `npm run test:hair:host`：构建 `build/hair-host/NativeGPU.exe`，用 `.screen/hair-preview.scene.json` 在同一相机下跑无发型、无风、有风、25° 转头四组 240 帧 smoke。实测 240 帧全部绘制发丝（3,467,520 次发丝提交、166,440,960 个 IA 顶点），模拟 240 tick、拉伸 1.000016、穿透 0、根漂移 0、陈旧上传 0；640×360 截图中发型改变 4,459 像素、压暗 1,425 像素，5,0,2 的风再改变 3,417 像素（0.45 → 1.66 m/s），25° 转头改变 6,437 像素，深遮罩 17,544 texels / 0.089 m；输出 `with-groom.png`、`with-groom-wind.png`、`without-groom.png`、`with-groom-head-turn.png` 与 `build/hair-host/evidence.json`。首次构建宿主较慢，之后走对象缓存；需要硬件 GPU。
- 三个入口都用内置角色 `assets/builtin/robot/character.json` 与程序生成的成衣（按角色实测截面外扩 12 mm），证明的是数据契约、分区、求解与报告，不是某件导入成衣或某张参考图的最终美术结果。

### 0.4 本次修复的缺陷

建立这两个入口时发现并修掉的实现错误，都直接影响第 10 节的验收项：

| 缺陷 | 影响 | 修复 |
| --- | --- | --- |
| `isInsideBody` 用三条轴向射线的奇偶投票定内外 | 角色是多肢体网格，从躯干中心出发的射线会穿出躯干再穿过手臂，命中偶数次，于是**躯干内部被判为外部**，初始穿透检查对所有衣物恒报 0 | `signedDistanceRobust` 改以最近三角面法线为主判据，仅在点几乎落在三角面平面内（< 60°）时回退到奇偶投票 |
| `resolveProxyPenetration` 对每条 guide 无条件做两遍平滑 | 作者 1 cm 的控制点偏移被稀释成 4.4 mm 并扩散到相邻点，"局部编辑"名不副实；每次重生成还会缩短发长 | 只在真的发生投影时才平滑，且只平滑被推动点附近 |
| `smoothWeights` 的 `locked` 只接受字节掩码，而 `applyLocks`/`validateWeights` 用 `Map` | 按文档传 `Map` 时逐顶点查到 `undefined`，**锁定被静默忽略** | 两种形式都接受；`bindGarment` 新增 `locks` 入口，锁定在平滑前写入并作为边界 |
| `validateWeights` 用浮点序列化结果比较锁定值 | Float32 存储与 Float64 期望值差最后一位就报违规 | 改为 1e-6 容差比较 |
| `partitionGarment` 的半径放大循环在首次查询为空时 `break` | 放大逻辑成为死代码；超出首个半径的顶点被当作未解析，继承邻居权重（腰部顶点因此拿到 17% 手臂权重） | 改为 `continue`，并把放大限制在 3 档（6/12/24 cm） |
| 分区置信度对所有近中线顶点乘 0.6 | 合身上衣近一半顶点被判低置信度，低置信度报告失去意义 | 仅对**有侧别**的区域施加侧别惩罚 |
| `transferWeights` / `smoothWeights` 不做侧别约束 | 裆部三角形横跨双腿，平滑两遍后正确的一侧主导（0.39/0.08）被翻成 0.28/0.40，裤腿摆向错误 | 转移阶段过滤并平衡对侧影响，平滑阶段同样过滤对侧邻居 |
| `regionForBoneName` 不认 `Spine1` 这类带编号骨骼 | 三段脊柱的角色整个胸部被判为 `unknown`，而 `unknown` 与所有区域兼容，区域过滤在胸口失效 | 去掉尾部编号后重查映射表 |
| `patchWeights` 接受未解析的裸网格 | `vertexIds` 为 `undefined` 时抛无关的 TypeError | 明确拒绝并提示用 `parseMesh` 的结果 |

### 0.5 2026-10-28 增量中修掉的缺陷

| 缺陷 | 影响 | 修复 |
| --- | --- | --- |
| `validateTriangleTopology` 用 `2*(columns-1)*(rows-1)` 校验三角形数 | 任意三角网格成衣在原生侧必然被拒，`columns/rows`对成衣无意义 | 成衣分支改为校验“三角形数等于膜数”，并要求 `columns/rows` 为 0 |
| 复用网格的 `bakeTriangleTopology` 生成膜反矩阵 | 它按 X/Y 轴投影构造材料系，绕身体的曲面三角形静止应变不为 1，原生校验直接拒绝 | 新增 `bakeGarmentTopology`：在三角形自身平面建正交标架后再解 `{e0,e1}` 基底 |
| 沿发丝路径的圆胶囊代理 | 扁平躯干上一个圆胶囊在 X 向凸出 6 cm，胸部初始穿透 71 mm，求解器只能把衣服顶起 | 按骨骼分段内切椭球（55 分位半径），两件夹具静止穿透 0 |
| 投影顺序为 应变→蒙皮 | 焊接缝边在蒙皮投影后又被拉开，报告的拉伸包含求解器从未处理过的量 | 改为 膜→蒙皮→应变→碰撞，碰撞优先于位移预算 |
| 诊断把运动学缝边计入求解拉伸 | 焊缝被骨架拉长时报告成求解失败 | 拆分 `seamStretchMax` 与 `stretchRatioMax`，并新增 `targetStretchMax` 作为下限 |
| 原生测试里 `*loadClothLibrary(...).cloths.at(...)` 绑定到临时对象的成员 | 临时 `Library` 析构后资产被释放，偶发段错误 | 先持有 `Library` 再取 `shared_ptr` |

## 1. 需求与交付边界
本次需求包含两条主线：

1. 制作引擎编辑器内的发型生成器插件。AI 读取用户参考图片，通过结构化接口生成、修改发型；引擎负责发丝生成、绑定、模拟和真实感渲染，并提供截图、对照、局部修改、保存与撤销能力。
2. 衣服由外部建模或 AI 建模生成，作为已有网格输入。引擎负责衣服适配诊断、骨骼权重生成与修正、布料约束生成、角色动态碰撞，以及供 AI 读取的权重视图和数值数据导出。

同时交付 AI 使用说明、提示词模板、工具参数示例和完整操作样例。这里的“插件”指引擎自身可注册、可禁用的编辑器功能模块与 AI 工具适配层，不等同于安装到 Codex 的外部插件。

本次不开发衣服造型生成器、二维裁片设计或缝纫工作台。可接收已经成衣的三维网格，不强制要求裁片。不得以“模型可导入”替代服装模拟验收，也不得承诺任意服装和任意动作绝对不穿模。

## 3. 总体架构

发型工作流：参考图 → AI 视觉分析 → 发型规格 → 真实头皮绑定与 guide → 插值发丝 → 模拟与渲染 → 多视角截图/指标 → AI 局部修改 → 版本发布。

服装工作流：角色与成衣网格 → 坐标/姿态/初始相交检查 → 分区对应与权重转移 → 模拟代理及物理约束 → 动态碰撞 → 权重视图与动作截图 → AI 修正 → 资产发布。

视觉模型由调用方 AI 提供：引擎接收图片引用与 AI 输出的结构化分析，不要求运行时内置云端视觉模型。可选视觉适配器必须显式配置提供方与图片使用范围；不得自动上传整个角色项目。离线模式允许人工或本地 AI 提交同一份规格。

## 4. 图片驱动发型生成器

### 4.1 图片分析与不确定性

- 支持单张或多张参考图，记录图片哈希、视角、裁剪范围、主体、可见发际线及分析置信度。
- 单张图不能确定后脑、遮挡发束和真实尺度。不可见区域记录为 `inferred`，按风格先验补全；多图冲突时输出诊断，不自动取平均抹掉特征。
- 分析项包括发长、分缝、刘海、头顶体积、侧面轮廓、后脑体积、卷曲、发束宽度、碎发、颜色和粗糙度建议。图片高光不能直接当作发色纹理。
- 照片视角不明时先估计相机再比较轮廓；不能用错误投影驱动几何反复变形。背面推断结果必须提供背视图给用户或 AI 检查。

### 4.2 可编辑源资产

建议新增版本化的 `nativegpu.hairstyle/1`，通过适配器生成现有 Groom cooked 资产，避免不兼容地扩充旧格式严格校验器。

源资产至少包含：角色/头皮哈希、单位与坐标系、参考图及置信度、随机种子、发区、稳定 guide ID、根绑定、曲线控制点、发束层级、材质参数、模拟参数和 LOD 预算。

生成器需支持：

- 从真实角色头皮三角形建立重心根绑定，头皮随头骨或面部变形后正确更新；不得默认使用球冠替代真实头皮完成生产验收。
- 头皮密度、长度、梳理方向、分缝、卷曲、成束、碎发和渐细参数；参数限定范围并使用米制单位。
- 少量 guide 插值大量渲染发丝；随机流和稳定 ID 独立于编辑顺序，修改刘海不重生成后脑。
- 命名发区，例如 `bangs`、`crown`、`left_side`、`right_side`、`back`；侧别统一按角色自身左右命名。
- 根部固定、曲线局部编辑、成束方向调整、分区重生成与区域锁定。辫子、扎发需要显式束约束，不能仅靠噪声参数近似后宣称支持。
- 近景发丝、中景发片、远景简化表示共用同一源数据；首个发丝版本不必等发片自动生成全部完成，但必须提供性能回退策略。

### 4.3 引擎发丝生成、模拟与渲染

| 层级 | 要求 |
| --- | --- |
| 生成 | 有界 GPU/CPU 数据上传；切线、半径、根尖属性与材质组明确；无效曲线拒绝发布 |
| 模拟 | 仅模拟 guide，渲染发丝插值；固定时间步、长度/弯曲与形状保持；支持暂停、重置、传送和 LOD 迁移 |
| 碰撞 | 头、肩、胸等随骨骼运动的代理；报告穿透；快速转向另验 swept/CCD，不能把终点投影称为 CCD |
| 光照 | 沿发丝方向的纤维散射、高光展宽、根尖色差、背光透射；浅发色和深发色独立校准 |
| 可见性 | 亚像素覆盖率、深度遮挡、抗锯齿和透明合成；选择有界的透明缓存或覆盖算法并报告溢出 |
| 阴影 | 毛发自遮挡和对场景的透射阴影；不能用单个实体头发外壳投影替代验收 |
| 稳定性 | 验证镜头运动、转头、LOD 切换下的闪烁、拖影、发根漂移与发束体积变化 |
| 性能 | 记录 guide/strand/segment 数量、GPU 生成/模拟/绘制时间、显存、透明缓存溢出和回退原因 |

首轮调优可从 128–512 条 guide、每条 8–24 段、2–6 万条渲染发丝开始。这是实验起点，不是性能承诺；最终按目标 GPU、分辨率和同屏角色数测量后锁定档位。

### 4.4 截图、修改与复核

- 固定正面、背面、左右侧面、四分之三视角和发际线近景；提供中性光照与背光场景。
- 截图通道包括 beauty、轮廓、发区 ID、guide、根绑定、切线、覆盖率、碰撞/穿透和 LOD。
- 每张图附相机参数、角色姿态、资产哈希、revision、随机种子、分辨率、曝光、帧号/时间点与灯光配置。
- 支持按发区 ID、guide ID 和截图选区修改；二维选区映射必须结合相机、深度或 ID 缓冲，明确可见面与穿透选择模式，拒绝过期截图映射。
- AI 基于截图提交结构化 patch，必须带 `expectedRevision`；支持 dry-run、差异预览、撤销和重做。
- “修改截图”指读取截图定位问题后修改三维资产，再重新截图。不得直接修饰截图冒充引擎效果；对照图的标注层与原始截图分开保存。

## 5. 成衣权重与真实布料

### 5.1 输入要求与检查

输入为角色骨骼/身体网格和已有衣服网格，可来自 GLB/FBX 导入包。要求单位一致、静止姿态可对应，衣服保留领口、袖口、腰口等结构；材质、UV 和顶点对应关系需可追溯。

预检报告退化面、非流形、断裂片、法线/绕序、初始穿透、薄层距离、镜像尺度及姿态差异。不能把大范围体型不匹配交给刷权重解决；修形超过阈值时生成待处理报告，禁止无提示强行收缩衣服。

### 5.2 必须分开的权重与物理数据

| 数据 | 作用 | 调整方式 |
| --- | --- | --- |
| 骨骼蒙皮权重 | 决定衣服随骨骼运动的基础姿态 | 按骨骼转移、平滑、归一化、锁定与局部补刷 |
| 动态混合权重 | 决定每个区域使用蒙皮目标还是物理解 | 0 为跟随蒙皮，1 为自由模拟；在过渡区连续变化 |
| 最大位移 | 限制布料相对动态蒙皮目标可移动的距离 | 使用米制距离，不能与 0–1 权重混用 |
| 固定/附着约束 | 领口、腰带、肩部等固定或弹性连接 | 随骨骼更新锚点，可设柔性而非一律钉死 |
| 碰撞间距与背侧限制 | 控制厚度和向身体内部移动的范围 | 按区域调整，避免统一放大造成衣服悬浮 |
| 材料参数 | 决定拉伸、剪切、弯曲、密度、阻尼和摩擦 | 物理预设加实测标定，不能靠蒙皮权重替代 |

### 5.3 自动刷权重流程

1. 在统一静止姿态中建立身体与衣服的语义分区：躯干、左右上臂/前臂、左右大腿/小腿等。
2. 在分区、法线和距离限制下寻找身体三角形，用重心插值转移权重；对腋下、裆部、双腿间、衣服内外层避免跨区最近点误配。
3. 对宽松裙摆、披风等身体对应不明确区域，优先使用衣服连接关系和指定锚点传播；输出低置信度区域，不盲目贴到最近腿骨。
4. 保留用户锁定权重，做受边界约束的平滑与稀疏化；每顶点权重有限、非负并归一化，骨骼影响数遵守运行时实际格式上限。
5. 为肩、腋、肘、胯等处生成动作诊断；需要时增加姿态修形。权重转移成功不等于动作形变验收成功。
6. 保存稳定顶点 ID、源资产哈希、目标骨架哈希、对应关系和生成参数；重新导入或拓扑变更后必须验证映射，不能按旧顶点索引直接补刷。

### 5.4 角色服装模拟

- 新增任意三角网格的模拟资产导入，保留衣服面片边界及必要缝合关系；规则 grid 仍可作为环境布入口。
- 分离低分辨率模拟代理与高分辨率渲染衣服，预计算重心/局部框架映射；UV 接缝、硬边和材质分段不得产生模拟裂缝。
- 每个物理 tick 更新蒙皮目标、锚点和身体碰撞体；正确处理世界/角色/骨骼空间及大位移重置。
- CPU 参考与 GPU 实现覆盖相同约束合同；模拟结果与蒙皮过渡必须验证位移、速度连续性，避免重复应用骨骼变换。
- 单层衣服先支持动态身体代理碰撞，再扩展局部精细碰撞、自碰撞和层间碰撞。长裙、宽袖等依赖自碰撞的服装，在对应能力通过前不得标为正式支持。
- 快速动作需要子步、连续碰撞或有明确界限的位移限制；发生持续穿透、约束发散或非有限值时报告并安全恢复。
- 可配置隐藏被衣服完全覆盖的身体区域以减少可见穿帮，但验收同时保留身体可见的碰撞诊断，不能只靠隐藏身体通过物理验收。

## 6. AI 权重视图导出

引擎新增专门的调试导出能力，服务于 AI 检查、局部刷权重和动作复核，而非只输出一张没有数值的彩色图。

### 6.1 导出内容

- 单骨骼权重热图：固定 0–1 色标、骨骼名称/ID、遮挡切换、正背与左右视图。
- 主导骨骼分区、影响骨骼数、权重和误差、零权重/非法权重、平滑不连续区域。
- 动态混合权重、最大位移、固定区域、碰撞厚度、自碰撞启用区域等独立通道；禁止共用图例混淆物理含义。
- 骨骼叠加、身体/衣服线框、碰撞代理和穿透热图；静止姿态与指定动画帧都能导出。
- 输出 PNG、元数据 JSON、无损顶点/三角形 ID 缓冲，以及按稳定顶点 ID 索引的实际权重与物理数值数据。大数据支持分块或二进制导出。
- 数值包括未归一化残差、最大影响数、异常列表、区域置信度、穿透深度和相关姿态；不能仅凭热图推算精确权重。

### 6.2 AI 修改闭环

导出权重视图 → AI 定位区域和原因 → 读取该区域数值 → 提交骨骼或物理权重 patch → dry-run 检查 → 应用 → 同姿态同相机重拍 → 动作复核。

顶点选择支持稳定 ID、语义区域、拓扑邻域以及截图选区映射。补刷操作支持设值、增减、受约束平滑、转移和镜像；镜像要求显式左右骨骼映射，不能简单按坐标取负。

## 8. AI 使用说明与提示词交付

手册必须说明工具发现、当前版本能力、项目路径、输入准备、单位、左右方向、默认参数、截图阅读、局部修改、撤销、错误恢复、验收及导出。提供完整调用记录和对应原始截图，不能仅给概念性提示词。

### 8.1 发型制作提示词模板

> 为目标角色制作参考图片中的发型。先查询当前工具与版本能力，检查角色头皮和项目路径。分析图片的可见发际线、分缝、长度、轮廓、发束流向、卷曲与颜色，标明不可见区域的推断和置信度。生成结构化发型规格，固定种子与预算，通过实际可用的发型工具创建资产。使用同一灯光和相机导出正面、侧面、背面、四分之三及发际线截图，检查轮廓、发根、头皮露出、高光与碰撞。每轮只修改明确的发区，带 expectedRevision，保留已确认区域；修改三维资产后重新截图，不修饰截图冒充结果。运行转头与动作验证，报告失败项、截图路径、资产版本和实际性能；未通过项不得描述为完成。

### 8.2 服装权重与布料提示词模板

> 为目标角色绑定已有成衣网格，不重新设计衣服。先检查单位、静止姿态、拓扑和初始相交；明显体型不匹配先诊断。生成保留衣服分区的骨骼权重，避免左右肢体和内外层误配。分别设置蒙皮权重、动态混合、最大位移、固定区域与碰撞参数。导出相关骨骼热图、主导骨骼、物理权重、线框和穿透视图，并读取数值异常。通过稳定顶点 ID 局部补刷，保护锁定权重；修改后在同相机同姿态复拍，运行抬手、蹲下、走跑、转身与跳跃。对穿透、发散和未支持自碰撞明确报错，不靠隐藏身体代替物理检查，不宣称所有动作绝对无穿模。

### 8.3 截图驱动修改示例

> 发型正面截图中刘海遮住右眼：使用截图资产哈希、相机和 ID 缓冲定位角色右侧 bangs 的可见 guide；仅调整这些 guide 的弯曲和长度，锁定分缝与后脑。重新生成正面和四分之三视图，核对右眼露出与左右轮廓。

> 抬左臂截图中袖子被胸骨拉扯：导出左上臂、锁骨、胸骨热图和对应顶点数值，检查分区映射与权重；局部降低错误胸骨影响并归一化。再检查模拟过渡与碰撞，避免把物理穿透错误当成蒙皮权重错误。

## 10. 增量验证与验收指标

仅执行本次依赖范围的增量验证。未经用户新要求，不运行全量测试、`npm test`、`npm run verify` 或完整 CI。

- 毛发入口放 `.incrementalTesting/vegetation/`，角色服装入口放 `.incrementalTesting/simulation/`，截图与 AI 事务入口放 `.incrementalTesting/editor/`。
- 新增或移动入口时同步 package.json、工作流或 `.incrementalTesting/core/ci.ps1`、commands.json 与测试索引；禁止在 tools 根新增验证脚本。
- 毛发单测覆盖确定性、稳定 ID、真实头皮绑定、区域锁定和 LOD；原生覆盖 CPU/GPU 约束、碰撞、透明缓存和设备恢复。
- 权重测试覆盖左右近邻误配、宽松服装、锁定值、影响数上限、归一化、静止姿态差异和过期拓扑。
- 截图测试覆盖图例、线性色标、ID 精度、相机复现、姿态与 revision 一致性；数值导出与热图必须来自同一份权重快照。
- 动作集至少包含静止、走、跑、急转、抬双臂、蹲、跳、暂停恢复、传送，以及头部转动和肩部接触。

验收分两层：数值正确性必须硬性通过；视觉与性能阈值按目标设备和服装类型锁定后执行。初始建议如下，均须在样例标定后写入机器可读配置，不能作为已经达到的指标：

| 指标 | 初始验收目标/方法 |
| --- | --- |
| 权重合法性 | 负数、NaN、零总权重、越界骨骼数均为 0；解码后权重和误差不超过 1e-4，量化格式另记录误差界限 |
| 根绑定 | 脱根与无效绑定为 0；记录随骨骼运动的最大位置误差 |
| 服装碰撞 | 按区域输出穿透 P95/P99/最大值、持续帧数与连通区域；单层样例可先以 P99 ≤ 2 mm 为调优目标，领口/袖口等视觉关键区单独检查，失败即报告 |
| 稳定性 | 非有限值和爆炸为 0；记录边长伸长、抖动和恢复事件，不仅检查最后一帧 |
| 图片相似度 | 校准相机下比较可见轮廓、分缝和发长；不可见区域不纳入“精确重建”评分；真实截图复核高光和发束体积 |
| 帧预算 | 指定 GPU/分辨率/同屏数，分别报告生成、模拟、绘制 P95/P99 和显存；禁止仅用平均值或离线速度宣称实时 |
