# 接触驱动动作系统开发方案

日期：2026-10-27  
状态：方案 + P1/P2 求解器侧已实现（见 [实现记录](CONTACT-DRIVEN-MOTION-IMPLEMENTATION.md)、[支撑脚滑动收敛](CONTACT-DRIVEN-MOTION-STANCE-BUDGET.md)）；阶段四数据层（通用接触集合、手臂链、允许滑移）已实现（见 [多接触层](CONTACT-DRIVEN-MOTION-MULTI-CONTACT.md)）；P3 参考库、P5 编辑器与攀爬/四足行为仍是设计契约。  
系统名称：**接触驱动动作系统**（Contact-Driven Motion，简称 CDM）。  
范围：引擎通用角色能力，融合动态支撑点、多接触约束、程序化步伐和动作参考库；不同模型通过骨架语义与角色配置接入。

## 1. 产品目标与基本原则

角色根据输入、实际碰撞位移和环境实时生成动作。接触约束决定脚或手如何连接环境，程序化控制器决定步伐与动作阶段，动作参考库提供自然姿态、节奏和表现风格。

首个目标是解决“右脚抬起时左脚仍然滑动”：左脚支撑时，相对其接触表面保持有效接触；右脚落地后完成支撑交换，再允许左脚抬起。静止转向时，身体先在允许范围内转动，随后双脚依次换位。正常步行、跑步腾空和跳跃采用各自的接触时序，不能强制所有动作始终单脚着地。

动作库作为参考输入，最终姿态由运动目标、环境和接触约束共同决定。允许改变参考动作的步幅、转角、相位和局部姿态，但必须限定修改范围并保留动作语义。

该方向与浮动基座逆运动学、多接触控制及姿态检索已有研究相关，不将基本概念宣称为原创发明。项目的开发重点是通用资产接入、实时交互、确定性求解、编辑器和可验证质量。

## 2. 当前基础与待确认问题

当前代码已有双骨求解、表面局部脚锚点、脚步状态、程序化换步、动画混合和动作检索基础，集中在 `engine/native/animation.hpp`、`animation.cpp`、`animation_features.cpp`；角色运动与地面查询由 `engine/native/game.cpp` 接入。现有实现记录见 [首版实现记录](REALTIME-CHARACTER-RIG-IMPLEMENTATION.md)。

代码检查发现以下可能造成支撑脚滑动的路径，尚未通过用户实际复现序列确认根因：

- 转向补偿可能围绕身体位置偏移脚目标或更新锚点，造成支撑点移动。
- 部分约束权重下，求解后又混回基础动画，最终脚底未严格到达接触目标。
- 腿部不可达时释放锁定；原动画、身体运动和接触状态可能缺乏统一协调。
- 骨盆主要进行高度补偿，尚未统一求解水平偏移、旋转和多个接触点。
- 现有滑动指标覆盖有条件的锁脚状态，未全面覆盖过渡期、脚掌角度与渲染插值。

实施前重新核对代码与并行改动，先录制和定位，不能把上述候选直接当成已证实根因。

## 3. 两类根与动态支撑

骨架维持导入时的合法层级和蒙皮关系。运行时支持切换求解参照和接触约束，不反复修改骨骼父子关系或逆绑定矩阵。

| 概念 | 职责与权威 |
| --- | --- |
| 角色运动根 | 碰撞后的世界位置和运动方向；由角色控制器负责 |
| 姿态求解基座 | 骨盆或身体允许调整的自由度；在有限范围内满足接触和姿态目标 |
| 动态支撑点 | 脚底、脚跟、脚尖或手等环境接触；相对接触表面稳定 |

“左脚为根”的实际含义是左脚接触约束优先，骨盆和关节围绕该约束协调。固定脚底接触点不等于冻结所有脚骨旋转；脚尖支撑时允许脚跟抬起，接触自由度由模式决定。

### 3.1 支撑状态与交换

- 单支撑：一个接触点承担主要约束，另一肢体执行摆动目标。
- 双支撑：同时满足两脚接触，有限调整骨盆并准备下一步；不能简单平均两个不兼容的约束。
- 无支撑：腾空期间释放地面约束，预测落地并在接触后重新建立锚点。
- 多接触：后续同时处理脚、手等接触，使用明确的优先级、自由度和冲突策略。

典型步行交换：左脚保持 → 右脚摆动 → 验证右脚落点 → 建立右脚接触 → 短暂双支撑 → 释放左脚。换脚必须保持位置、方向和速度连续；跑步按动作定义允许腾空，不能强塞双支撑阶段。

### 3.2 运动与碰撞边界

角色控制器提供碰撞后的权威位移，姿态求解器先通过有限骨盆补偿和关节运动维持支撑。预测即将不可达时，提前换步、缩短步长或提出运动限幅建议；建议必须在角色控制器允许的阶段处理并通过碰撞求解。禁止最终动画直接回写碰撞体位置导致穿墙或双重积分。

无解时按规则保留碰撞有效性和关节限制，执行提前落地、重新规划或平滑释放并报告。不得通过无限延长骨骼、无提示移动锚点或隐藏误差“维持锁定”。首版提供运动学与视觉协调，不宣称实现力学平衡、摩擦力或接触力模拟。

## 4. 通用接触数据与求解

拟定 `ContactConstraint`：稳定标识、绑定骨骼及其局部接触框架、表面身份与局部锚点、位置/方向约束自由度、权重、优先级、模式、有效期、获取/释放条件和失效原因。

接触模式至少区分整脚、脚跟、脚尖、允许滑移和自由状态。整脚模式约束脚底位置与允许的方向；脚尖模式围绕实际接触点旋转。移动平台每 tick 从表面变换恢复锚点，使用精确变换差分评估相对运动，不能仅用平移速度近似旋转平台。

拟定 `SupportState` 记录活动接触集合、主要支撑、交换阶段、计时和计划中的下一落点。所有影响未来计算的状态参与存档与确定性摘要；表面销毁、瞬移、重生和角色替换时定义清理规则。

求解先预测可达性，再确定接触阶段，随后在有界迭代中协调骨盆和肢体。接触有效且可达时优先满足支撑；接触之外尽量接近参考姿态，遵守关节限制。所有影响接触的姿态混合必须在最终接触校正前完成，或在其后重新投影校正；不能在最终锁脚后再次混合而破坏约束。渲染插值也需采用保持接触的策略并独立验收。

首版复用双腿专用求解器，加有限骨盆平移与旋转；多目标全身求解单独扩展。双支撑采用同时评估的误差和确定顺序，避免左右腿先后处理造成结果偏置。

## 5. 动作参考库

### 5.1 参考内容

动作资源保留原始片段，并建立版本化的可派生参考数据：骨架语义与重定向信息、姿态和关节速度、左右接触阶段及下一接触时间、脚轨迹、步长与抬脚高度、平移和朝向变化、骨盆起伏、躯干倾斜、摆臂，以及动作类别、风格和允许修改范围。

接触、速度和风格等数据允许人工标注；自动分析输出来源、置信度和诊断，并可修订。跨模型使用角色尺度与语义坐标归一化，保留源资产身份；换骨架或重导入时失效检查并重新生成派生数据。未知接触不能默认解释为可靠半周期。

参考数据可分为完整姿态、步态节奏、局部曲线和语义参数，按需求逐步增加；首版不要求把所有曲线完全解耦，避免丢失躯干与四肢之间的协调关系。

### 5.2 决定权

| 内容 | 决策主体 | 参考库作用 |
| --- | --- | --- |
| 实际位移与碰撞 | 角色控制器 | 运动速度和加速度参考 |
| 支撑顺序与切换 | 程序化动作控制器 | 接触时序和节奏建议 |
| 下一落点 | 步伐规划及环境查询 | 自然步长和转向参考 |
| 有效支撑点 | 接触求解器 | 不能由参考姿态直接拖动 |
| 躯干与四肢表现 | 姿态目标生成器 | 保留动作风格和连续性 |
| 最终关节旋转 | 约束求解器 | 在约束允许范围内接近参考 |

### 5.3 检索、变形与过渡

先按行为类别与能力过滤，再按当前姿态、关节速度、实际/期望运动、朝向变化、接触阶段和短期轨迹检索。成本项包含接触不兼容、连续性、运动差异及切换代价。初版可使用有界线性检索，测量库规模和耗时后再引入索引。

参考相位应以落脚、起脚等事件对齐。当前左脚支撑时，不能因候选姿态接近而直接跳到右脚支撑；需要兼容阶段或显式的过渡计划。设置持续偏置、滞回与紧急响应例外，防止频繁换参考，也避免为了保持参考而产生操作延迟。

按任务和身体部位配置参考跟随强度、允许偏移和优先级，避免一个总混合百分比控制全部身体。步态可大幅调整落脚，摆臂较多参考素材；攻击或抓取等行为有自己的关键轨迹和接触约束。方向、步幅、时间和局部姿态修改必须有范围，超出范围时换参考、调用基础程序化步态或降级，不能将普通行走无限变形成无关动作。

示例：目标右转 70°，库中有右转 90°素材。提取其抬脚节奏、重心变化与摆臂，根据当前支撑和目标转角重新规划落点；保持支撑脚约束，有限调整身体和摆动脚，不必完整播放原素材。

## 6. 每 tick 数据流

1. 取得输入意图、碰撞后运动结果和一致的环境快照。
2. 评估当前接触、可达性、行为和短期目标，生成参考检索需求。
3. 获取兼容参考，映射动作相位，产生姿态、节奏和接触建议。
4. 程序化控制器结合环境更新步伐、支撑交换和落点计划；接触建议不能无条件覆盖实际有效接触。
5. 生成基础姿态及局部表现，限制步幅、方向与时间调整。
6. 统一求解支撑、骨盆、摆动肢体、关节限制与地面方向。
7. 执行不破坏接触的后续形变，生成蒙皮数据和诊断；检查最终输出误差。

计划使用当前 tick 的状态与短期预测；避免玩法持续读取上一 tick 的“是否抬脚”来决定旋转而形成不清晰的反馈环。确需跨 tick 的输入须写入明确契约和摘要。

## 7. 引擎接口与编辑器

拟定职责模块：`ContactManager`（接触生命周期）、`StepPlanner`（步伐和转向计划）、`MotionReferenceLibrary`（参考数据）、`MotionReferenceSelector`（检索与连续性）、`PoseTargetBuilder`（目标与表现）、`ContactPoseSolver`（最终求解）。允许先实现为现有控制器内部边界，再按复杂度拆文件，不以拆模块本身作为交付目标。

资产级配置存骨架语义、接触框架和默认步态；场景实例允许有界覆盖；行为配置定义参考类别、关键约束、风格和修改范围。对现有资产、场景和快照采用显式兼容/迁移策略，避免无提示改变旧资产行为。

编辑器显示接触点/锚点、脚底框架、支撑阶段、实际与候选落点、参考片段和相位、身体补偿及误差；时间轴支持接触事件、允许变形范围和置信度修订。记录每次换参考、改支撑、移动锚点及降级的原因，并能回放同一输入。

## 8. 实施阶段与交付条件

| 阶段 | 内容 | 完成条件 |
| --- | --- | --- |
| P0 复现与基线 | 记录用户滑脚序列，逐阶段探针与渲染对比 | 确认真实根因，保存可重复证据；不以指标漏报作为零滑动 |
| P1 单支撑 | 接触框架、严格支撑、有限骨盆补偿与提前换步 | 左右脚分别支撑、另一脚抬起时，在可达范围内保持接触稳定 |
| P2 双支撑与转向 | 同时评估双脚、支撑交换、脚跟/脚尖模式 | 连续转向、反向和转走过渡无明显滑动、跳点及腿部交叉 |
| P3 小型动作参考库 | 走/跑/转向数据，接触标注、相位映射 | 同一参考适配不同速度、转角和至少两种角色比例 |
| P4 参考选择与表现 | 连续检索、局部跟随、修改边界与风格 | 切换保持接触和姿态连续，风格可辨，超范围明确降级 |
| P5 工具与交付 | 参数、可视化、持久化、性能及回放 | 可配置、可定位问题，旧资产兼容，按预算运行 |
| 后续 多接触 | 扶墙、抓扶手、攀爬、四足或全身求解 | 每类行为单独定义能力和验收，不能由双足通过推定全部支持 |

首个验证使用同一参考集，在不同速度、转角和角色比例下生成不同步伐，同时保持支撑稳定与可辨动作风格。不要求首版具备大规模素材库、机器学习或完整物理控制；这些能力另行评估。

## 9. 测量与增量验收

测量最终脚底/接触框架而非仅脚踝目标：锚点位置误差、相对表面的滑动速度、方向误差、穿透、支撑切换连续性、不可达次数、参考切换频率、输入响应与 CPU/查询成本。同时记录每阶段误差和渲染插值结果；主动脚尖转动、允许滑移与意外滑动分开统计。先测量并确认按尺寸归一化的阈值，再固化门禁。

用例覆盖左右单支撑、双支撑、平地启停、行走/跑步、转向与快速反向、转走切换、墙体阻挡、斜坡台阶、跳跃落地、表面消失、传送重置、两种骨架命名与比例、动画与参考切换、不同渲染帧率、快照续跑。移动平台必须测试旋转和平移下的表面相对误差；多平台冲突单独定义降级。

测试遵守工作区约定：按改动依赖增量运行，未经新明确要求不得运行全量测试、`npm test`、`npm run verify` 或完整 CI。资产相关用 `npm run test:assets`，需要对应原生绘制时用 `npm run assets:verify`；动画求解选择直接相关的专项入口并核对范围。新验证入口放 `.incrementalTesting/` 对应分类并同步命令索引和 CI 引用；场景放 `.screen/`；报告与临时输出放既有生成目录，运行时项目内容只写入规定的用户项目目录。

## 10. 产品决策与范围边界

第一优先级是支撑稳定、程序化落脚和行走/原地转向；参考库优先覆盖相同动作适应不同环境，再扩展风格。该优先级为本方案建议，尚未获得额外产品确认。以下事项在相应阶段落地前确定：

- 首批参考素材、许可、角色覆盖和自动标注的人工确认流程。
- 身体允许偏离碰撞体的范围，以及角色控制器是否接受运动建议。
- 地形、移动平台、脚掌滚动及参考修改的质量与性能阈值。
- 缺参考和超出适用范围时允许的基础步态或回退表现。
- 后续交互/攻击动作对轨迹准确性、程序化自由度和网络同步的要求。
