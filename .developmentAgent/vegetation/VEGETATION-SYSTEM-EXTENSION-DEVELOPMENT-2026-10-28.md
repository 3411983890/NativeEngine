- 日期：2026-10-28。
- 状态：开发设计；本文新增数据结构、API 名称、阶段和指标均为拟议要求，不代表已实现或已验收。

- 目标：支持《青岚村植被清单》全部 63 个清单项的制作、导入、程序化变体、地图刷入、自动排布、保存与独立运行。荷花/枯荷、水稻/稻茬/枯稻等状态分别验收。

## 1. 交付定义与代码基线

“支持某种植物”必须同时满足：有明确物种配置和合法素材；近景能识别主要结构；程序化种子可复现；原生视口与发布运行一致；可从地图资源库刷入，重开后保留；数量和性能可观测。只换绿色贴图、出现一株近似植物或生成离线网格，不能作为完整交付。

本次静态核查发现下列基础；未重新运行生成、原生绘制或性能验收。

| 现有代码 | 已观察到的基础 | 本专项扩展边界 |
| --- | --- | --- |
| `engine/vegetation/species.mjs`、`generators.mjs` | tree/shrub/grass；层级枝干、叶片、草叶、物种 cook 与 LOD 数据 | 增加可组合部件和特殊生长形态，兼容旧物种 |

## 3. 作者数据与生成架构

### 3.1 用部件扩展现有物种

保留现有树枝图、叶片图集、材质和风权基础。拟增加 Plant Recipe 与 ComponentAsset 适配层，不新建第二套图片/模型解码器。

部件类型至少包括：stem、branch、leaf、compoundLeaf、frond、flower、fruit、seedHead、pod、culm、floatingLeaf、root、surfacePatch。它们是拟议语义，不直接把枚举加入旧严格 schema 而忽略原生消费者。

部件必须声明：稳定 ID、生成或导入来源、资源 ID/digest、米制尺寸、局部坐标、根点/连接点、可用挂点类别、材质引用、风分组、LOD 和适用阶段。外部部件支持几何实例挂接，不能将网格路径塞入纹理槽。

挂载规则包括：父部件、弧长范围、节序、互生/对生/轮生或自定义序列、朝向与重力偏转、数量/间距、尺度分布、互斥范围、状态筛选。稳定随机流按植物/分枝/挂点派生，调整果实数量不应重掷整棵树冠。

先选两条路径共存：参数化生成常规茎叶；导入模型表达复杂花果、包心白菜和英雄枯树。完整模型同样可注册为地图植被资源，不能强制所有植物完全程序化建模。

### 3.2 版本与资源生命周期

新增 schema 版本和迁移器，旧物种无新增字段时保持可读；cook 记录生成器版本、源 digest、素材依赖、材质合同与坐标转换。预览、cook、原生运行消费同一份规范化参数与部件输出。

物种编辑器先校验和 cook，再发布一个不可变资源修订。地图层引用 speciesAssetId + digest + variant/stage；资源更新显式选择升级，不能原文件变化导致已保存地图悄悄换树。资产缺失、版本过旧或不兼容时显示原因并保留最后有效地图。

## 4. AI 地图编辑器与笔刷自动排布（必须交付）

### 4.1 用户完整流程

1. 在植被编辑器生成或导入植物，选择状态、变体和质量档；预览后保存、烘焙。
2. 使用“加入地图资源库”，注册到当前项目，可搜索物种、生态类别和已烘焙状态，展示真实缩略图和成本。
3. 在 AI 地图编辑器选择单物种或混合预设，例如“柳树＋岸边草”“竹林”“水稻田”。选择绘制图层和目标表面。
4. 调整笔刷半径、密度、最小间距、聚簇、尺度、旋转、坡度、边缘衰减、种子以及道路/建筑退让距离。
5. 鼠标拖动时显示原生笔刷轮廓与低成本植物预览；植物自动接地、避障、分布，松开后提交一次可撤销操作。
6. 可擦除、补刷、替换物种、修改区域规则、锁定或移动单株、局部重新生成；保存重开后恢复结果。
7. AI 可根据自然语言形成同样的图层和规则草稿，例如“沿这段河岸种柳树，避开道路”；预览、编辑、提交走相同服务。
8. 发布项目后由原生运行时加载，离开编辑器和 AI 服务仍能看到相同植被。

### 4.2 笔刷交互合同

| 项目 | 要求 |
| --- | --- |
| 工具 | 绘制、擦除、密度增减、替换、区域填充；框选和单株编辑配合使用 |
| 形状 | 首版圆形与多边形填充，后续矩形；沿线种植使用路径工具 |
| 密度单位 | 木本按株/公顷，草本可显示丛/平方米，内部统一换算；明确“一丛”的资产单位 |
| 输入采样 | 按世界距离重采样，不按鼠标事件数累加；同一路径在不同帧率下得到同一笔迹 |
| 覆盖组合 | 绘制为目标覆盖度/密度遮罩；加密是显式操作。重复覆盖默认不无限叠加实例；擦除存持久遮罩或 tombstone |
| 命中 | 原生射线返回 surfaceId、命中点、法线、材质/语义、surfaceRevision；支持地形、选定网格、墙面、屋面、水面筛选 |
| 相机与窗口 | 绑定 viewportSession、cameraRevision；正确处理 DPI、窗口尺寸和正交/透视投影，过期命中丢弃 |
| 单次操作 | 按下到松开为一次事务和一次撤销；Esc 取消，丢弃草稿；拖动中不频繁提交场景 |
| 异步 | 预览与正式编译有独立任务 ID/版本；新笔迹可取消旧任务；过期结果不得覆盖新结果 |
| 原生反馈 | 显示笔刷范围、排除区和拒绝原因；覆盖层在原生视口绘制，避免被子窗口遮挡 |

### 4.3 自动排布规则

在既有 scatter 基础上增加密度遮罩、生态混合权重、路径/建筑/交互区排除、成行农田和表面锚定。支持自然聚簇、疏密变化、沿线等距和行列种植，不把所有农作物随机撒点。

跨 cell、跨物种、已有手工植株之间统一检查间距与占地。树冠间距、根部间距和建筑退界可以分别配置。使用确定性候选点与优先级；邻域只读采样形成 halo，按固定优先级处理边界候选，避免生成顺序影响结果。现有每格每规则网格散布不能据此宣称已经保证跨格或混合物种间距。

候选 ID 应由 world/layer/species/cell/candidateSlot 派生，在表面与规则筛选前分配；禁止按过滤后的数组序号标识单株。擦除、移动和锁定引用此 ID。改变密度优先启用/禁用稳定候选集，保留用户修改；超出可保持身份的布局变化必须提示并有迁移策略。

每次只重建笔迹与其影响半径涉及的分块。规则调整可能扩大脏区，必须在提交前计算依赖和成本；不相关区域 digest 和实例变换保持不变。边缘块裁剪到真实区域，防止刷出区域外。

### 4.4 表面与生态约束

- 地形与普通网格：根点对齐命中表面，倾斜幅度受限；检查表面版本并在地形修改后重投影。
- 多层建筑：保存明确目标表面，不以“最高命中”替代用户选择，避免地面草跳上屋顶。
- 墙面/石缝：支持任意方向射线、表面切线坐标、法线偏移、裂缝/遮罩引导；藤蔓保持支撑关系。
- 湿地与水面：区分底床高度、水面高度、水深与岸线距离；缺水深数据时明确禁用相应规则，不能伪造生态正确性。
- 农田：行距、株距、行向、田埂退让和局部缺株；稻茬与成熟稻为状态替换，不默认重复叠加。
- 苔藓/藻：笔刷写覆盖遮罩或表面贴片，不生成数百万独立普通实体。

### 4.5 UI 与 AI 共用服务

拟议操作：vegetation.registerToWorld、world.vegetation.preview、commit、erase、replace、regenerate、override。名称须与已有 world API 复核统一，不创建同义平行服务。这些名称当前不是已承诺可调用的命令。

输入至少包含 projectId、worldId、layerId、expectedRevision、资源 digest、规则引用、笔迹/区域、种子及 operationId。服务校验单位、数量上限、目标表面、资源状态与项目路径；输出任务状态、受影响分块、实际密度、拒绝计数、预算和原生 ACK。

AI 输出受控参数，不能直接执行任意脚本或把数十万实例逐项写入 scene.json。无法识别物种或缺素材时给出缺项；不得无提示地用橡树代替柳树。无网络或 AI 模型服务时，资源选择和笔刷仍可正常使用。

## 5. 地图存储、事务与运行时

在 World Recipe 中存图层、物种引用、规则、笔迹/遮罩与手工覆盖；cooked 产物存分块实例、部件批次、资源依赖、范围与版本。源和结果通过 digest 可核对。不要为每丛草创建普通场景实体。

编辑提交使用 expectedRevision 和幂等 operationId；编译成功后原子替换清单。保存、cook、原生加载失败时恢复最后有效修订。撤销/重做覆盖笔迹、规则、替换和单株修改，重开需恢复已提交作者状态；是否跨会话保留撤销历史单独声明。

原生以 bounded batch/文件引用接收分块更新，ACK 携带任务 ID、修订与 digest。地图显示、保存版本和 ACK 必须能核对；仅 ACK 收到命令不等于资源已绘制。

运行时按可见分块和距离加载，按物种/部件/材质/LOD 分桶；补齐实例 LOD、远景替身、风动包围盒和阴影预算。树干碰撞可使用代理，草默认无逐叶碰撞；英雄植物可提升为交互实体。透明裁切远景保覆盖，避免 mip 后整片消失。

## 6. 材质、风和状态

复用现有 baseColor/normal/ORM/opacity/thickness/height 合同及通用资产导入；新增花果等材质组时同步 JS cook、二进制、原生加载、GPU 绑定、shader 与调试显示，不能只加 UI 槽位。

薄叶支持双面与透射语义；果实、竹竿、树干使用合适的实体表面。Height 用途必须明确为微表面或视差等支持路径，不能把灰度图称为真实几何位移。材质跨植被与通用资源的一致性单列验收。

风按根、主干、枝条、叶、穗和大型叶片分组，子部件跟随父挂点，风动不脱节。静态阶段资源先交付；连续生长、果实脱落、漂浮植物流场运动为后续增强，不阻塞静态物种和笔刷闭环。

| P3 竹与草本农田 | 竹节、茎叶穗、行列布局、大叶莲座 | 毛竹、狗尾草、水稻三状态、白菜的原生对照 |
| P4 藤蔓与水生 | 引导路径、任意表面、底床/水面、水深、覆盖材质 | 墙面爬山虎、石缝蕨、荷与枯荷、浮萍、苔藓 |
| P5 全清单与规模 | 63 项档案/素材接入、全状态审查、LOD/流式/预算 | 逐项验收矩阵、三档场景性能、项目发布依赖报告 |

P2 需要最小的分块绘制和实例 LOD 可用；不能把所有性能问题推迟到 P5，导致笔刷已生成但地图无法绘制。

## 9. 增量验证与验收

本次是文档改动，只执行链接、清单覆盖和索引检查。实施代码时按依赖范围运行已有 `tests/vegetation*.test.mjs` 中受影响文件；新增验证入口放 `.incrementalTesting/vegetation/`。涉及资产导入用 `npm run test:assets`；需要原生资产绘制再用 `npm run assets:verify`，保留独立 `build/assets-host`。不运行全量测试、`npm test`、`npm run verify` 或完整 CI。

核心验收用例：

1. 同种子、同表面版本和同笔迹两次结果相同；改变笔迹事件频率仍得到相同提交数据。
2. 混合物种在跨分块边缘满足配置间距；负坐标、区域边缘、多层表面均正确；不相关块内容不变。
3. 绘制→擦除→撤销→重做→保存→重开，资源引用、规则和实例覆盖可核对；缺素材与冲突不半提交。
4. 调整密度或局部重生成后，锁定/移动/删除记录保留；稳定 ID 不随筛选结果重新编号。
5. 地形、水位、道路和建筑变化正确使相关分块失效；缺表面查询时不伪造成功。
6. 快速连续笔刷、切项目、取消与旧任务晚返回不污染当前文档；DPI、正交俯视和透视模式拾取一致。
7. 每种结构至少三种种子做近中远景；花果、竹节、穗、叶柄在静态和风动下连接正确；全清单不能只测橡树。
8. 原生帧中确认区域和多物种确实绘制，记录可见实例、LOD、draw call、显存、CPU/GPU P50/P95、分辨率和硬件；不以离线包数量代替可见数量。
9. 建议阶梯为 1k 木本、10k 木本、50k 草丛的专项场景，分别测试并确定实际可用档位；这些是压力输入而非已达性能承诺。记录笔刷预览与提交延迟、脏区数量、取消耗时；预算上限可配置，超限给出降档或分批方案。
10. 发布到独立目录并移走源素材路径后可运行，断开 AI 服务仍可加载；不存在用户机器绝对路径依赖或写回引擎源码目录。

交付时对照第二篇逐行标记“素材具备/生成通过/地图通过/发布通过”，明确艺术质量和功能状态。不能把有贴图标成有完整物种，也不能把本文阶段目标标成已完成。
