## 1. 素材与程序生成的分工

树干、枝条、一般草叶、规则叶轴和可重复茎秆优先程序生成；叶片外观、树皮、花果纹理需要制作或采集。近景复杂花果、包心白菜、特殊老树可导入模型，既可整株使用，也可拆成部件参与程序化组合。表中的“可选模型”不要求每个物种都额外制作完整树模型。

现有仓库以橡树贴图和程序化针叶图集为主要可见基础，不能算下列 63 项已齐备。正式素材验收需检查具体图像、metadata、材质绑定和原生结果，不能只看文件名或历史截图。

### 1.1 贴图套件代号

| 代号 | 交付内容 | 使用范围 |
| --- | --- | --- |
| L 薄叶/透明部件 | BaseColor + Alpha/独立 Opacity；切线 Normal；ORM；薄叶可加 Thickness；真实尺寸、连接点、正背面语义和图集 metadata | 叶片、草叶、花瓣、枝叶簇、穗卡片。没有测量数据的 Thickness 必须标为相对值 |
| B 实体表面 | 可平铺 BaseColor、Normal、ORM，声明平铺米数；Height 可选且明确尺度/用途 | 树皮、竹竿、粗藤、实体茎 |
| O 花果/特殊模型 | 模型 UV 对应 BaseColor、Normal、ORM；存在裁切部分再加 Opacity；薄瓣按 L 补充 | 果实、花朵、荚、莲蓬、地下或露出根部等 |
| S 表面覆盖 | 可平铺 BaseColor、Normal、ORM、覆盖/边缘遮罩；Height 可选；声明湿润与干燥版本 | 苔藓、贴面藻层和薄层覆盖 |

最小功能样件可使用颜色、正确透明轮廓与明确材质常量。正式近景交付按表中套件补齐；不要求为无意义的通道制作图片，金属度通常使用 0 常量。ORM 固定 R=AO、G=Roughness、B=Metallic，不能混用其他打包方式而不声明。

### 1.2 制作数量与分辨率建议

- 常规单叶起步 3–6 种轮廓/色差；草丛或叶簇 3–5 种；每物种至少 3 个可复现株型种子。数量是首批制作建议，按实际镜头和预算调整。
- 单叶源默认 1024²，近景可 2048²；树皮和图集一般 2048²，背景资产可更低。输出原生分辨率与细节来源，不把放大图标为高精度扫描。
- 各状态共享适合的几何和材质；秋叶、干叶、腐朽不必全部另做完整模型，但轮廓变化明显时需要对应几何或透明图。
- 卡片用于中远景或细碎部件，近景轮廓明显的圆叶、卷叶、果实和厚叶优先曲面/实体几何。所有 LOD 级别和具体面数由镜头及性能验收确定，不在素材表中承诺统一预算。

## 3. 贴图交付与导入合同

### 3.1 颜色和数据通道

- BaseColor 使用 sRGB，无烘焙方向阴影、无环境投影；Normal、ORM、Opacity、Height、Thickness 为线性数据。
- 法线声明 `directX-` 或 `openGL+`，由导入器统一转换；不能只改文件名。所有贴图使用同一 UV、形状和图集布局。
- 透明图必须是真实 Alpha，不画棋盘格、黑白背景、文字和标尺。颜色边缘正确扩展，遮罩与颜色轮廓一致；cook 保持 mip 覆盖率并隔离图集单元。
- Thickness 表示相对厚薄时标注 relative；Height 没有标定时不能标成米制。单张颜色图推导的数据图标明来源及近似性质。
- 正反叶面需要不同外观时明确提供背面图或声明可用的背面参数；不要通过错误翻转 UV 猜测背面。

### 3.2 根点、尺度与图集

单叶遵循已有 [AI 贴图与损伤规范](VEGETATION-AI-TEXTURE-AND-DAMAGE-SPEC.md) 及 `engine/vegetation/leaf-source.mjs` 的 canonical 合同：根部朝下、尖端朝上、等比缩放，根点 UV 默认 `[0.5, 0.0625]`，四周留安全区；坐标原点与图像 Y 轴转换显式声明。

声明 bladeOnly 或 bladeWithPetiole，防止贴图叶柄与生成叶柄重复。复叶、花、叶簇、穗、圆形浮叶不强行套单叶尖点模板；各自记录根点、连接点、主轴、尺寸和内容范围。导入器须验证相关类型，不支持时明确报错。

每份资产 metadata 至少包含：assetId、物种/参考名、部件类型、阶段、真实尺寸、pivot/socket、朝向、图集格及有效范围、贴图语义/色彩空间/法线约定、来源/授权、版本、digest。类型化导入后的字段名称以最终 schema 为准。

## 4. 模型交付合同

- 推荐以带材质的 GLB 作为统一交换输入；其他格式通过现有资产管线转换。植被部件适配是待开发功能，不能把能导入普通 GLB 等同于已能挂接到生成器。
- 规范化到米制、Y 向上；记录源坐标和正向，避免人工重复旋转。应用不必要的变换，检查负缩放、镜像切线、法线和双面设置。
- 完整植物原点在根部落地点；花果部件原点在连接端；浮叶记录叶柄挂点和水线。提供 socket 的局部坐标及方向。
- 材质槽稳定命名并绑定正确通道，透明裁切与实体材质分开；纹理可嵌入或以可移植相对依赖交付，不能依赖制作者绝对路径。
- 风权可导入或由部件规则生成，必须声明含义；不要占用已有顶点色字段而不迁移合同。部件接合处风权需连续。
- 提供近中远 LOD 或允许引擎生成；检查透明覆盖、花果保留、穗和细叶消失。烘焙 impostor 是引擎产物，除非特别指定，不必人工重复交付。
- 树干/英雄植物附简化碰撞代理；普通草叶、花瓣不要求逐面碰撞。

## 5. 地图笔刷需要的资源信息

每个可刷入资源除美术素材外，还必须具备以下数据，由作者填写或工具计算并允许校正：

| 信息 | 用途 |
| --- | --- |
| 物种 ID、不可变修订、变体和生长状态 | 地图稳定引用，支持升级和替换 |
| 缩略图与分类标签 | AI 地图编辑器搜索和选择，缺贴图资源不可显示为已就绪 |
| 根点、包围盒、占地半径、建议间距 | 自动接地、碰撞退让和密度换算 |
| 资产单位 | 明确是一株、一丛、一簇还是一平方米覆盖，防止密度数量失真 |
| 允许表面 | 地形、墙面、屋面、石缝、水面、底床；同资源可有不同放置预设 |
| 生态与布局预设 | 坡度、高度、湿度、水深、岸线距离、聚簇、农田行列；建议值应来自关卡需求并可编辑 |
| 风与 LOD 档位 | 预览、运行与性能预算一致 |
| 依赖与授权清单 | 保存、打包和独立运行能收集完整资源 |

可复用 G01/G04/G13 等资源制作“石缝、瓦缝、湿墙”预设，不因放置位置不同重复购买同一套纹理。贴图共享不能消除表面附着功能的开发需求。

## 6. 制作批次与交付检查

| 批次 | 代表资产 | 验证目的 |
| --- | --- | --- |
| A 基础闭环 | 垂柳、柿树、狗尾草 | 树冠、下垂枝、花果部件、草穗，发布到地图资源库并可刷入 |
| B 竹与农田 | 毛竹、水稻全部指定状态、白菜、大豆 | 竹节、行列种植、莲座包心、复叶与豆荚 |
| C 特殊环境 | 爬山虎、湿墙蕨、荷与枯荷、浮萍、苔藓 | 任意表面、水位、覆盖遮罩和正确锚定 |
| D 全清单 | 其余物种与状态 | 全部 63 行及对应子状态逐一完成，验证混合场景与独立发布 |

每批交付：源图/源模型、规范化输入、metadata、授权与来源、引擎 cooked 资源、近景/远景/风动截图及地图刷入示例。AI 生成图标注来源，不宣称实拍、扫描或物理测量。

采用以下逐项验收列：`素材齐备 → 通道/根点通过 → 单株原生通过 → 变体/状态通过 → 地图刷入与重开通过 → 发布运行通过 → 预算通过`。本表默认全部待验，不因使用同一套生成器就批量标记通过。

可编辑场景和地图源放在项目 `.screen/`；素材、缓存、报告和构建位于 `%USERPROFILE%/Documents/nativeEngineProject/<项目名>/` 的对应子目录。引擎开发说明仍在 `.developmentAgent/vegetation/`，不把运行时项目资产写回源码目录。
