# WF 逐来源发布预算与等待调度

2026-10-25。继 [发布事务](FIELD-PUBLICATION-TRANSACTIONS.md) 后，将持续超预算候选从整批发布中隔离。私有 LEF、共享 WF、视觉表现和 CPU 权威边界保持原方案定义；这是 B/C/G 的增量，不代表四系统生产目标已全部完成。

## 先估算，再生成粗投影

GpuVisualWorld.budget 接受可选 GpuVisualProposal：owner/source、区域、通道、单源页上限，以及同 owner 下要一起撤销的旧来源 ID。只遍历 CPU 租约/来源元数据并调用 GetResourceAllocationInfo，不申请写租约、不创建 GPU buffer、不推进 epoch，也不录制 GPU 命令。非线程安全，沿用单录制拥有者约定。

预估区分 Invalid、Pages、Leases、Sources、Snapshots、Rows、Bytes。成功结果包括下一版本页数、来源/页相交行数、描述符数量、下一快照构造峰值 allocationBytes 和既有 residentBytes。后者包含读者与在途快照；成功替换后可能释放已完成旧 current，所以构造峰值不能当成提交结束后的常驻字节。失败结果可能只包含到拒绝位置的诊断，不能把其零字节当作成功。

已退出控制器覆盖和提议中的原子撤销来源参与下一版本覆盖计算；读租约及仍有其他来源使用的原始写者覆盖继续计费。撤销墓碑在确认前仍占来源记录/写槽预算，不虚构释放。每个带贡献的来源按其整个声明覆盖计行数，包括已知零，不能仅用非零粒子所在格估算。

实际 tryCommit 使用同一预估，并在发出聚合命令前核对行数、描述符数量和实际对齐字节一致。预估不是写权限、时间/fence 或 GPU 投影对象的授权，真实 publish/commit 仍执行原校验。真实分配失败继续按 ResourceFailure/运行时失败协议处理。

## 可承受候选继续前进

服务先暂存真正退出实例的撤销，再稳定选择候选。每个候选先检查提升配额、私有投影容量和 WF 提议预算；不适配就记录该源延期并尝试下一个。被预估拒绝的来源不生成粗投影、不消费提升配额，也不留下写租约或来源 epoch。私有粒子模拟/细 LEF 仍执行，不能据此称该效果没有 GPU 成本。

已有 Shared 来源的可承受更新可以继续提交，即使另一个新来源持续超过行数或字节额度。实际整批的旧版本/读者/在途资源本身超预算时仍保留事务回滚；逐候选选择不会绕过物理资源计费。

移动的旧 Shared 来源与新 LEF 代际属于同一个候选组。预估成功且投影生成成功之后才暂存旧源撤销与新源发布；若移动候选不适配，旧源继续共享，其他来源可以更新。未获确认的旧代际保留在退休队列中，不能因其他候选成功就提前删掉。停止这个移动实例后，旧来源成为真正退出，可独立撤销。

## 排序、延期与取消

先按显式 priority 降序；同优先级按 pendingSince 最早者优先，再按稳定 source/serial。新到达者不能越过同优先级的旧等待者。配额只约束新的观察提升；已有共享更新和继承共享的移动保持既有合同。

服务不抢占已共享来源，也不承诺需求总量超过容量时每个来源都一定能共享。高优先级可压过低优先级；永久不适配的高优先级候选仍会被快速跳过，不能占住其他可承受候选的额度。动态分辨率降档、主动驱逐和完整时间预算另需实现。

每源 inspect.publication 提供 pending、pendingSince、lastAttemptTick、lastPublishedTick、deferredTicks、reason 和 overdue。deferredTicks 是尝试被延迟的 tick 次数；实际等待时长用当前 tick 减 pendingSince。publicationMaxDelayTicks 默认 6 个模拟 tick，超过阈值显式 overdue；它不是任意渲染频率下的三帧保证。

成功发布后清理等待/原因并记录真实 publish tick；sourceTick 仍取实际 LEF 生产时间。暂停生产者如果已有尚未发布的 LEF，会在容量释放后发布该缓存版本，保持旧 sourceTick；完成后不再重复生成投影或刷新年龄。局部效果观察需求取消时清除等待和超期状态。

publicationBacklog 返回有界的当前待发布清单，最多为服务配置的活跃实例数量，按同一排序提供 handle generation、source、priority 和 publication 信息。renderer 报告增加 publicationBacklog、deferredCandidates、pendingPublications、overduePublications、lastCandidateDeferral。最后一个是历史最近原因，当前是否仍等待应看清单和 pending。

## 增量验证

只运行相关写场服务、WF 和 TransactionOnly 宿主专项，不运行全量回归。新增场景覆盖：

- 首位 12 行候选在 8 行上限下拒绝，后面的 8 行来源仍提升；拒绝候选没有生成粗投影，持续等待显式超期。
- 配额为 1 时同优先级按等待时间前进；持续更新已有来源，新到达者不越过旧等待者。
- 24 行的扫掠移动在 16 行上限下保留旧贡献，另一来源继续更新；竞争来源退出后再原子切换。
- 仅描述符增量就使新候选超过精确字节上限时，原来源仍能更新；释放竞争来源后新候选恢复。
- 暂停后发布已计算版本、真实来源年龄继续增长；取消观察后待发布/超期清单归零。
- CPU 提议不改变租约/来源/发布计数，预测的行数、描述符和持有旧视图的真实分配峰值与实际 GPU 快照相符。

这不是 GPU 页池/脏页增量更新、多级分辨率、流体求解迁移或 CPU 玩法权威接入。原方案 A–G 及联合性能验收继续实施。
