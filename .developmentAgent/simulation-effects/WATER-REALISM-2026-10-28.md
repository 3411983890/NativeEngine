# 水体波纹与真实感演进（2026-10-28）

供模型交接与分阶段执行的详细版本见：[真实水体系统详细开发方案与 DeepSeek 提示词](WATER-REALISM-DEEPSEEK-PROMPT-2026-10-28.md)。

## 本次定位与改动

CPU 脚步已有可重放的半径、位移随机化和随速度变化的方向拉伸；它不是完全没有随机。GPU 事件只携带位置、半径与位移，方向丢失，注入也是单一波形。细波纹之前不参与可见表面，画面主要暴露较粗 CPU 轴向有限体积网格的方向偏差。

GPU 子步反复覆写同一上传常量地址，录制命令不会快照上传内存，所有 dispatch 最终可能读取最后一份参数，丢失第一步事件。上传也没有隔离三个在途帧。首帧重置直接 return，还会吞掉同帧事件。

本次修复：

- 每帧槽独立常量、事件、深度上传；每子步使用独立且 256 字节对齐的常量地址。复用依赖宿主现有帧槽 fence。
- 首子步从静水读取并允许同帧注入；后续子步正常传播。回退时间线重新清场。
- 九点传播降低细波纹的四重网格方向偏差；干邻居反射，边缘吸收。CPU 守恒浅水求解器未更换，因此不能宣称所有粗网格误差已消除。
- 世界距离和斜率分别使用 X/Z 格距，避免长条河道的波被拉成错误比例。
- 在原有 32 字节事件 ABI 内传递方向和拉伸，保留 CPU 已生成的随机大小；用事件稳定哈希变化双频带宽度与权重，重放时不闪烁。
- 校正负位移接触的中心凹陷方向；每个连续核具有零积分，GPU 离散采样和干岸裁切仍有误差。视觉层有 ±3 cm 限幅，不回写玩法质量账本。
- 重新启用有界细波纹位移和法线。
- 实景复核发现图形根描述表的第二个 SRV 范围默认偏移为 0，导致 t5 错读 t0 的 HDR 场景颜色；显式设置偏移为 4，避免颜色当成米制高度。额外添加真实绘制回读：用亮色背景和零波高水面绘制波高调试视图，检查 256 个内部像素的 RGB 半精度值严格等于 0.5，直接防止场景颜色与波高纹理混绑。

## 按收益排序的后续工作

### 1. 接触驱动：脚、入水、奔跑与拖曳分开

当前使用角色根部的步距触发，还不是左右脚真实落地事件。应消费动画脚掌接触时间、脚底面积、入水垂直速度和相对水流速度：脚尖轻触产生细短波，踩踏产生凹陷与环波，奔跑形成有方向的船首波和尾迹，跃入水面产生更强喷溅。站立时只保留环境风波。随机只做受能量约束的小变化，不能让慢走随机超过跳水。

验收：相同种子与动作可重放；慢走、奔跑、落水的平均波能按接触强度排序；左右脚产生可辨识但不机械重复的轨迹。

### 2. 连续水流与地形落差

现有浅水求解器有水深与水平动量、基础坡床，但 inflow/outflow 在全水域均匀加减水，不能代表河口注流。先做位置化入口/出口，显式设置流量（m³/s）、方向和入流动量；从场景地形构建河床高度，让水位梯度驱动重力流。维护水深、速度与流量，并把速度场用于法线、泡沫、漂浮物的平流，避免流水只是贴图滚动。

验收：上游输入减下游输出等于水量变化；平底静水不漂移；斜坡顺坡流动；干湿岸线不产生负水深。细波纹随主流平流，浅水慢、深水快，之后再增加波长相关色散。

### 3. 石头、岸壁与障碍

目前 `Body` 河床来自资产公式，尚未把场景石头几何投影进水体。先构建障碍掩码、浸没边界和床高，在通量层实施不可穿透边界；水从石头两侧加速，迎水面抬升，背水面形成尾流。动态物体采用物体表面相对速度，在交换动量时给水和刚体相反作用量。泡沫由速度剪切、压缩与碰撞能量驱动，并随流速搬运和衰减；湿痕由水位历史驱动。

验收：关闭边界不漏水；改变石头位置会改变流向；无流静态石头不凭空生泡沫；漂浮物对水体有反作用。更明显涡旋需要足够网格分辨率和适当数值格式，不能承诺加一个障碍贴图就有湍流。

### 4. 从高处流下：浅水 + 局部三维落水

单层高度场不能表示同一 XZ 处上下两层水、悬垂水片和自由下落水滴。落差口保留浅水上游流量，转换成局部水片/粒子，使用重力更新下落，落水池接收等量水和冲量，再驱动环波、泡沫和雾滴。水片用于稳定主体，粒子负责边缘破碎；只有近景高要求区域才考虑 FLIP/APIC 等三维模拟。

验收：上游流出与下游流入守恒；落差增大时落点冲击增强；降低视觉粒子数量不改变实际水量；进入/退出局部区域不重复计水。

### 5. 光学与尺度

再逐步加入深度相关吸收、水底视差与焦散、掠射反射置信度、岸边弯月面、泡沫寿命和大小分布、浑浊物搬运、湿石粗糙度变化。风控制细波方向和统计强度，主流控制搬运方向，两者分别建模。远处降低细节，角色附近提高分辨率；性能预算不足先减少视觉层，不降低玩法守恒步的稳定性。

## 验证

已有入口 `npm run test:water`：CPU 接触、随机范围、方向传输、确定性、质量/CFL 和水资产/场景合同。

已有入口 `npm run water:verify`：水体宿主依赖、真实 GPU 回读数值与项目内画面/AOV。新增 GPU 子测试属于此既有入口，不增加全量测试。输出分别位于 `build/water-realism-native/` 和 `%USERPROFILE%/Documents/nativeEngineProject/InteractivePond/reports/water-realism/`。

本次 CPU 专项通过 34,160 项断言与 6 项 JS 合同。真实 GPU 子测试通过 65,953 项断言（含实际绘制绑定回读）：圆形测试波的四重角向偏差为 0.000344341（阈值 0.1），定向接触的 X/Z 二阶矩比为 2.43109；首帧接触最低位移约 -9.73 mm。该偏差指标只针对平底、独立细波纹测试，不能当作完整场景水面真实度评分。

工作区其他动画文件在宿主编译期间发生修改，来源校验正常中止了原目录构建。最终画面验收使用 `build/water-source-snapshot-20261028/` 的冻结源码与其独立 `build/pond-host/` 宿主；保留了其他开发中的所有源文件。复现入口：`npm run water:verify -- --skip-build --host build/water-source-snapshot-20261028/build/pond-host`。该宿主固定于快照，不代表快照建立后发生的其他模块修改。

最终验收通过：240 帧水面绘制、28 次交互与细波纹注入、28 次喷溅实例及 6 个光学/波高调试视图；D3D12 验证错误为 0。实际画面已复核，错误颜色采样产生的整片尖刺已消除。报告见运行时项目的 `reports/water-realism/acceptance.json`；验收宿主 SHA-256 为 `F08F17158DC1CE9A333D17DF255B38836DF1B5C4BD91499A3D78D44BD59A8F47`。未执行全量测试或完整 CI。
