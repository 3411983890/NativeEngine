# 多生产者共同发布到一个 GPU 视觉世界场

2026-10-26。对应完整方案 B 的全局整合前置能力，关联 [WF](FIELD-WORLD-GPU.md)、[共享控制器](FIELD-SHARING-GPU.md)、[发布事务](FIELD-PUBLICATION-TRANSACTIONS.md) 和 [烟密度投影](SMOKE-FIELD-PROJECTION.md)。

## 当前实现范围

`GpuFieldTransaction` 将属于同一个 `GpuVisualWorld` 的多个 `GpuFieldSharing` 控制器纳入一个检查点和一个提交边界。实际 GPU 粒子池与实际烟求解器已能向同一份有类型通道目录、同一个世界场、同一个版本提交数据。每个求解器仍拥有自己的 LEF 和数值状态。

后续已将 `GpuFieldDeposits` 和 `GpuSmokeSharing` 都拆为本地准备、共同事务内暂存及提交后确认，并提供外部世界场和显式通道授予；真实 runtime 的两项生产服务同 tick 联合验证通过，见 [粒子阶段](FIELD-DEPOSIT-PHASES.md)、[双服务共同发布](FIELD-SERVICE-JOINT-PUBLICATION.md)。renderer 当前仍使用各自世界场；CPU 权威场也尚未接入全局服务，不能作为宿主全局整合、完整 B 或 A–G 验收。

## 提交合同

1. 在共同事务之前完成来源注册、消费者租约申请/释放、本地资源创建和本地求解。参与控制器、世界场须覆盖整个事务的生命期；控制器析构会先取消当前共同事务再释放自己的写租约。
2. `begin()` 拒绝空列表、重复、外部世界、已有事务或待确认的参与者。世界场已有未提交发布、撤销或已提交贡献的未提交删除时，也拒绝开始，避免把未纳入检查点的生产者顺带提交。
3. 为全部参与者复制有界元数据检查点，世界场只建立一次检查点。任一检查点分配失败均不取得共同事务所有权。
4. 只有参与者可以通过共享控制器暂存提升、更新、撤销和退休。未参与控制器的写入、退休、观察批次均拒绝；全部控制器的新来源注册均须留在事务外。
5. 事务内原始世界场接口不能申请/释放租约或发布/撤销来源，也不能单独提交。参与者的写接口仅在本次同步调用作用域临时获得内部写权限，不向调用者暴露写租约。消费者句柄不得在事务内产生或失效，避免回滚恢复已向外暴露的代际。
6. `commit(commands,fence,tick)` 仅发布一次 WF 快照。容量不足或其他提交拒绝自动恢复全部参与者的状态、epoch、配额、观察时钟和世界场的写租约/来源；已经完成的局部 GPU 求解不回滚。作用域结束或显式 `rollback()` 也取消尚未提交的共同批次。
7. 成功提交后逐源 `settle()`，不能在事务内提前确认。实际 GPU 执行和资源回收仍由真实 fence 控制，元数据确认不会等待 GPU。

事务复制 CPU 元数据和资源引用，不复制 GPU 数值，也不建立多线程并发事务。原单控制器显式 publish/commit/settle 和 beginTransaction/commitTransaction 路径保持兼容。

## 通道与全局查询需求

测试目录明确区分粒子量化沉积 `particleDensity / particle-q / effects / 1000` 与烟物理密度 `smokeDensity / kg/m^3 / smoke / 1024`，不把相同名字或整数存储当作单位相容。两者可以都使用 sourceId=1，身份由 owner 和 sourceId 联合确定。错误定点比例的投影返回 AccessDenied，不能自动混合或隐式换算。

`GpuVisualWorld::context()` 返回借用的 device/fence 和目录/grid 副本，供后续服务准入对齐；关闭后返回空上下文，借用指针不延长世界场生命期。

`subscribers(region,channels)` 查询世界场全部活动只读租约，包括其他生产者登记的消费者。按实际覆盖（含读取 halo）与通道交集计数，写租约不算订阅；非法区域或未知通道返回零。这是 CPU 元数据需求查询，不是 GPU 值读回。

## 真实硬件增量证据

- [场核心 20261026T072116Z](../reports/0.11.0/31c00bc53c0b/20261026T072116Z/fields-world-gpu-evidence.json)：17 组 / 1802 检查，128 次 CPU/GPU 查询比较。包含双控制器 600 联合聚合、固定一个快照预算下全部回滚、释放旧视图后重试得到 80、作用域取消、第三控制器与原始写接口拒绝、事务前暂存/未确认状态拒绝、未提交删除拒绝、析构取消与旧快照不变。
- [真实双生产者 20261026T072113Z](../reports/0.11.0/31c00bc53c0b/20261026T072113Z/fields-joint-gpu-evidence.json)：1 组 / 76 检查，14 次 GPU 查询比较。真实粒子沉积和求解后烟密度在 V1 为 16/256；第二域单位不匹配时第一域一起取消，V1 保持；不重新求解，使用保存的正确投影重试，V2 为 32/512；撤销粒子后烟仍为 512，旧视图仍为 32/512；最后撤销烟，两个通道均 Unavailable。Strong/CPU 权威租约被视觉场拒绝。
- [原粒子沉积服务 20261026T072124Z](../reports/0.11.0/31c00bc53c0b/20261026T072124Z/effects-deposit-service-evidence.json)：27 组 / 432 检查，原准入、延迟恢复、移动与真实 fence 回归通过。
- [原烟共享服务 20261026T072124Z-bc1bd8](../reports/0.11.0/31c00bc53c0b/20261026T072124Z-bc1bd8/smoke-sharing-evidence.json)：6 组 / 240 检查，16 次密度/WF 比较，原观察、驻留、尾烟、停止、快照和背压回归通过。

四份证据均使用实际 AMD Radeon 890M 和 D3D12 调试层，实际错误为 0。双生产者和烟共享专项执行前冻结来源/二进制；旧场核心和旧粒子服务专项在执行前后校验输入，执行后归档，不将它们记作执行前冻结。

增量入口为 `npm run fields:joint:gpu`、`npm run fields:world:gpu`、`npm run smoke:sharing` 和 `.incrementalTesting/simulation/effects-deposit-service.ps1`。标准 build/verify 只登记未来入口，本次没有执行全量构建、全量测试、verify 或 CI。

## 下一步生产迁移要求

- 建立不可变的全局类型目录和明确的资产通道映射，避免粒子量化密度与烟 kg/m³ 混用；各服务只能写获准 owner 的通道。
- 将两项生产服务拆为本地准备、事务内暂存、共同提交后确认。来源注册和 LEF 重建必须发生在检查点外；延后保存的粒子元数据必须清除只在回调期间有效的 GPU 池指针。
- 每个真实 simulationTick 中先生产两个域，再共同提交一次；不能把粒子 tick=T 和帧末烟 tick=T+1 串行提交到同一个世界场。
- 共同容量失败时保留真实本地 sourceTick，全部生产者一起取消暂存；全局消费者需求与预算只计一次，停止时新查询立即失效，旧视图继续按 fence 保活。
- 完成实际宿主接线、GPU 页池/多级分辨率、温度/速度合同、CPU 权威 tick/玩法/存档接入与跨系统预算后，再分别验收后续 B/D 目标。
