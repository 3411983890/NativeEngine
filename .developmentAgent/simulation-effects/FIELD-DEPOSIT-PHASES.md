# 粒子沉积生产服务的共同世界场模式

2026-10-26。对应完整方案 B 的生产服务迁移，建立在 [共同发布](FIELD-JOINT-PUBLICATION.md) 和 [原沉积服务](EFFECT-DEPOSIT-SERVICE.md) 之上。

## 生产接口与生命周期

`GpuFieldDeposits` 保留原构造函数和 `record(frame,error)`，独立模式由服务内部顺序执行本地准备、单参与者共同事务、发布和确认，原有回调入口不变。

新增构造函数接收外部 `GpuVisualWorld&`、显式可写通道 ID 集合及私有预算。使用世界场的同一 device/fence、完整目录和网格；通道名称必须唯一，可写集合必须非空、无重复、在范围内，且只能含支持的非负视觉标量。目录可包含其他 owner 的通道及 CPU 权威定义，但资产只能写明确授予本服务的通道；不能通过资产名称绕过授予集合。

外部世界场必须晚于服务及其活动发布事务销毁。服务只拥有自己的 LEF、控制器、准入预留与读取租约，不销毁外部世界场，也不把整个世界场字节重复计入自身 `allocationBytes`。`stats().world` 仍提供全局观察，`ownsWorld=false` 明确计费归属。全局所属服务需要将该份世界场预算另计一次。

共同模式必须使用显式阶段；`record()` 拒绝自行提交外部世界场，避免其他域被意外一起提交。

1. `prepare(frame,error)`：在 runtime 原后模拟回调中同步使用借用粒子池，处理准入、停止/移动、局部重建、splat/resolve。暂停和输入背压保留原行为。返回前清空所保存实例元数据的全部 emitter 池指针；以后只保留资产、句柄、serial、位置等稳定元数据和局部场自己的真实 GPU 资源引用。实际模拟 tick 在本地准备成功后推进，WF 失败不能要求重新模拟。
2. 所有生产者完成本地准备与注册后，协调者用 `publicationController()` 取得控制器，建立同一世界场的 `GpuFieldTransaction`。命令列表和真实 fence 覆盖本次整个记录作用域。
3. `stagePublication(commands,fence,error)`：只在活动共同事务内运行；命令列表和 fence 必须与准备阶段完全相同，重复暂存拒绝。按原稳定优先级/等待队列、预算和观察合同生成投影、暂存更新/撤销，不单独 commit 或 settle。返回 Ready、Deferred 或 Invalid；整个批次的 Deferred 必须共同 rollback，局部候选延期则继续处理可容纳候选。
4. 协调者共同 commit/rollback 一次，再给全部服务调用 `finishPublication(result,error)`。成功按真实已提交源确认，检查快照 tick 与准备 tick 相同；Deferred 要求控制器已无暂存状态，登记积压后保留最新 LEF；Invalid/资源错误标记服务失败，排空重建。不能在活动共同事务中提前完成。

已有未完成准备时拒绝再次 prepare；需要先完成或取消本次发布。活动共同事务内也不能调用本地 prepare。flush 只同步生命周期，不重新 splat、生成待发布帧或虚构模拟 tick。

## 跨服务观察与资源

发布需求改为读取世界场全部只读订阅，包括直接由全局消费者登记、未经过粒子服务包装器的租约。按区域、读取 halo、通道交集计算；仅因另一个域有消费者，不会让本域自动共享。资产仍可明确请求 worldVisible。

粒子资源只在 prepare 回调中借用；本地场输入及投影继续由既有真实 fence 保活。`retainedPoolPointers`、`publicationPrepared`、`publicationStaged` 进入服务统计，供阶段合同验证。命令列表仍属于本次调用者的记录作用域，不能在准备和暂存之间重置或销毁。

## 已验证范围与剩余迁移

新增真实硬件服务场景使用一个局部级粒子资产、直接登记的全局读取租约及另一 owner 的 GPU 投影控制器。检查共同版本、通道授予、准备后零池指针、错误 fence 拒绝、固定一个快照预算下共同回滚、保留本地进度并恢复到最新 tick、两域共同撤销，以及服务关闭后全局世界场和外部读取租约仍可用。

后续烟共享服务也已拆分，并有两项真实生产服务同 tick 的联合验证，见 [双服务共同发布](FIELD-SERVICE-JOINT-PUBLICATION.md)。完整宿主协调器和 renderer 接线尚未完成；CPU 权威整合、跨域总预算、GPU 页池/分辨率等仍属于后续 B 目标。

## 增量证据

- [服务 20261026T112705Z](../reports/0.11.0/31c00bc53c0b/20261026T112705Z/effects-deposit-service-evidence.json)：28 组/475 检查，保留全部原 27 组并新增共同模式。直接全局订阅使 local 资产共享；同一快照中粒子/另一 owner 投影为 250/64，固定一个快照预算时共同回滚，恢复为 250/128；最后两域均 Unavailable。准备后的保留池指针数为零，外部世界场仍有消费者/显存时粒子服务可以独立正常关闭。
- [宿主 20261026T112840Z](../reports/0.11.0/31c00bc53c0b/20261026T112840Z/effects-deposit-host-evidence.json)：仅正常发布、停止回收两个场景，8 项检查通过；原独立 record 路径实际绘制、发布节奏、最后撤销及 CPU 权威摘要保持合同。真实 tick=478、commit=476；停止后 commit=19、派发=36、场分配归零。每场实际调试错误 0，原有 760 条警告如实保留；没有将这个专项当作共同宿主或全部渲染验收。
- [核心/旧服务来源复核](../reports/0.11.0/31c00bc53c0b/20261026T112916Z-fields-joint-final/fields-joint-finalization.json)：沿用本批未改动的场核心、真实粒子/烟联合和烟共享通过版本，加入最新 28 组服务，250 项来源核验通过，四份专项相关输入零差异；没有因服务拆分重复运行无依赖变化的三个 GPU 专项。
- [服务/宿主收尾审计](../reports/0.11.0/31c00bc53c0b/20261026T113034Z-deposit-phases-final/deposit-phases-finalization.json)：360 项核验、342 项冻结来源核对通过，服务和宿主当前输入零差异。宿主依赖构建前后有来源校验，二进制/宿主来源在 GPU 执行前冻结；服务专项执行前后校验、执行后归档，二者证据顺序明确区分。

保留 [112347Z 失败](../reports/0.11.0/31c00bc53c0b/20261026T112347Z-deposit-phase-failure/failure.json)：新增夹具预期 1:1 网格的读值，却沿用 LocalSpec 默认 2:1 体积平均比例，原 27 组之后的新断言失败。归档失败二进制、全部实际匹配来源和错误日志，再把夹具显式设为 1:1 后重跑；未修改投影算法或覆盖失败记录。随后调整测试中协调器须先于服务销毁的生命期，再按最终来源重新运行服务专项。

只运行沉积服务增量和上述两个宿主场景，宿主使用独立 `build/field-phase-host` 依赖产物。没有运行全量构建、全量回归、npm test、verify 或 CI。
