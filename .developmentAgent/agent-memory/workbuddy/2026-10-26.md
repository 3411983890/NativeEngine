## 植被主线第四批：贴图 mip 链与遮罩覆盖率

- 格式升级 `NGT2` → `NGT3`（magic NGT3、版本 2）：头 32 B 的第 24 字段改为 mip 级数，各级按 `w>>L`×`h>>L` 顺序拼接，无偏移表。`engine/vegetation/texture.mjs` 与 `engine/native/vegetation/texture.hpp` 同步；文件扩展名 `.ngt3`。
- 每角色显式 `filter`（color/normal/coverage/data），写在 `assets/vegetation/textures/roles.json`；不按角色名猜语义。color 在线性光域平均，normal 平均后归一化。
- **关键教训**：遮罩覆盖率修正不能用「围绕 cutoff 缩放」——`cutoff + (a-cutoff)*s >= cutoff` 等价于 `a >= cutoff`，任何正 s 都不改变通过集合，实测覆盖率纹丝不动。必须求**偏移量**（二分，上界 = cutoff），且只在侵蚀时启用（`measure(0) >= target` 时原样保留）。
- 实测：512→8 级覆盖率最差 −1.7%；4/2/1 级刻意向上取整（亚像素叶片消失读作洞），代价是最近两级压成实心。
- 上传：`MipLevels` 与 SRV 级数取链长，逐级 `CopyTextureRegion`（每级独立 256B 行对齐），一块 staging 装整链。`VegetationTexture` 改为 `levels` 数组，`VegetationDrawStats::textureMips[6]` 记录实际上传级数。
- 新增 `node tools/vegetation-textures.mjs mips --in build/vegetation/textures` 输出每级覆盖率，作为可复现证据。
- 代价（已登记为已知缺陷）：22 m 近景覆盖 15,615→13,377（−14%，mip 软边被阈值切掉），45 m 叶片偏稀（−28%），根因是叶片几何稀疏不是 mip。下一步建议着色器侧 stochastic alpha / coverage-to-alpha。
- 证据：draw 9 组 / 15,728,709 断言 / 调试错误 0；Node 20/20。

## 植被系统缺陷分析（新增 docs/VEGETATION-DEFECTS-AND-PLAN.md）

- 关键发现（都在代码里有指认点）：**A1 `VegetationDraw` 没有被任何渲染器代码引用**（`grep -rln VegetationDraw renderer engine` 只命中自身，`d3d12_renderer.*` 无 vegetation 符号），`lightViewProjection` 目前只有测试在构造；**A2 单 256B 常量块**（`writeConstants` 每次 memcpy）导致多页绘制会互相覆盖，区域 25 页只能画 1 页；**A3 `lodBias` 是死字段**（着色器只读前 4 个 DWORD，`selectLod` 只在测试里）；**A4 LOD 误差对删叶片不可见**（降级=随机丢卡片，误差=稠密顶点到粗网格距离，故 oak LOD1 仅 0.085 m）；**B1 顶点记录无切线**（48 B 只有 pos/normal/uv/color/wind，着色器用实例 axisX 当切线，但卡片切线随卡片随机）→ 法线贴图方向是噪声；**B8 材质分类靠数组下标**（`isLeaf = material==1`，而 meadow_grass 的 blade 是 0 → 草走树皮分支，无透射/遮罩）。
- 量测：oak LOD0 70,008 tri = 叶片 62,976（31,488 张卡）+ 树皮 7,032；包 13.06 MB（132,984 顶点 × 48 B）；四物种合计 19.6 MB。
- 路线：Wave1 能进场景（帧图接入/多页/真统计/LOD 桶，8–12 人日）→ Wave2 像植物（切线/AO/材质位/风/曲率/覆盖误差）→ Wave3 跑得动（叶簇图集+卡实例化、顶点 48→20 B、BC、深度预 pass、impostor）→ Wave4 闭环（GPU 计时+golden、级联阴影、A2C/MSAA→TAA、编辑器二进制/原生视口）。合计 45–62 人日。
- 已同步 STATUS 台账升 v4：§4 新增第 10–12 条，§5 指向新文档的四波路线。

## 引擎内嵌到编辑器视口：复核（docs/EDITOR-VIEWPORT.md 新增 §9）

- 结论：能，三条路。A 截图读流 1–2 天 / 60–150 ms；B Electron 共享纹理 3–6 天 / <10 ms；C 原生子窗口 SetParent 2–3 天但不推荐。
- 实测：`node_modules/electron` = 44.9.1，`electron.d.ts` 确有 `sharedTexture.importSharedTexture`、`SharedTextureHandle.ntHandle`、`OffscreenSharedTexture`；但**全仓 `CreateSharedHandle` / `D3D12_HEAP_FLAG_SHARED` / `importSharedTexture` 0 命中**，链路一行没写。`Renderer::initialize(HWND, …)` 只接受窗口，`swapChain->Present(1,0)`，**无离屏模式**；`requestScreenshot/captureScreenshot` 是阻塞读回（waitIdle + 写 PNG）。`editor/server.mjs` 无 WebSocket upgrade。
- Electron 合同（类型定义原文）：ntHandle 是**进程局部**句柄需 DuplicateHandle；bgra/rgba/rgbaf16 **没有 keyed mutex**（只有 nv12 有）→ 背压与回收要自己做，建议 3 缓冲 + 原生 fence + `allReferencesReleased`；`getVideoFrame()` 内部等 GPU 完成，`release()` 逐份释放。
- 前置顺序：A1（VegetationDraw 接帧图）→ 拆"渲染到目标/呈现到窗口"+离屏 → A 或 B → 输入回传（frameId/cameraVersion 一致性）。
