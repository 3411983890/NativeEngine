# 制作说明

场景与脚本采用现有公共内容格式。`fogtown/quest` 仅包含项目任务；门、压力板和灯各自拥有独立实例状态，Game 中没有按任务阶段分支的雾镇流程。

`action` 将交互转为目标任务实体的下一 tick 事件。事件字段直接位于回调的 event 上。任务读写玩家的 inventory、progress、objective，并将可影响未来的阶段、节点顺序、截止 tick 等登记在行为 state 中。

三个开门组合共用 `door.lua`：item 指定钥匙；flag 指定压力板或任务旗标；压力板发送统一供能事件，使两个门同时响应。复制门实体并更换 ID/配置即可增加实例。

玩家 camera 组件选择 firstPerson，配置 eyeHeight、fov、initialYaw、initialPitch 和 worldExtent。第一人称隐藏自身模型，交互使用视线锥与活跃场景碰撞体遮挡检测。原第三人称场景没有 camera 时继续使用原设置。

新增公共组件：

| 组件 | 用途 |
| --- | --- |
| camera | 玩家视角和活动范围配置 |
| objective | 当前目标标题、说明、世界坐标与步骤 |
| illumination | 可保存的动态供能灯状态 |
| destruction | 原生层发布的破坏状态，供任务只读 |
| blast_request | 显式请求原生径向爆破，下一固定步消费并删除 |

音频与检查点请求是表现输出。宿主在模拟步完成后处理；声音不会决定任务结果。检查点保存整份现有模拟快照。冒险和导览共用场景；导览快照由同一通关验证产生。

运行 `npm run fogtown:generate` 会重建场景、行为描述、组件字段和原始 PCM 提示音。手工修改生成文件前应先修改生成源，避免下一次生成覆盖。普通玩法修改只需要 Lua、行为描述或场景；更改登记字段会使旧存档被内容校验拒绝。
