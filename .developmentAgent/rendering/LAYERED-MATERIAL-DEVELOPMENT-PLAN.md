# 多层材质与物理层叠开发方案

- 日期：2026-10-27。
- 状态：第一阶段（L0–L6）与物理层叠研究（L7）已按第 10 节完成条件验收；剩余改进项见第 13 节末尾，不作为本阶段未完成项。
- 目标：支持多套完整材质在同一物体表面混合，每层独立配置贴图、UV、法线和高度；后续建设可组合的物理材质层叠能力。
- 关联：[现有材质管线](MATERIAL-PIPELINE.md)、[材质正确性修复](MATERIAL-FIXES-2026-10-23.md)、[纹理与材质资产管线方案](TEXTURE-MATERIAL-PLAN.md)、[编辑器交互开发计划](../editor/EDITOR-INTERACTION-DEVELOPMENT-PLAN.md)。

## 1. 实际目标

在编辑器中创建一个“砖墙＋水泥＋苔藓”材质：

1. 砖、水泥和苔藓各自是一套可复用材质层，独立绑定基色、法线、粗糙度、金属度、AO 和高度。
2. 每层可以选择自己的 UV 集，调整缩放、偏移、旋转和采样方式；单个贴图槽也可覆盖该层的默认 UV 设置。
3. 通过遮罩、顶点色或常量控制各层覆盖范围，并可用高度影响相邻层的交界。
4. 编辑器实时预览完整混合结果，可单独检查某一层、遮罩和高度；保存后，静态模型、基础几何体和角色按各自支持范围使用相同材质。
5. 场景保存、导入、重新导入、构建与运行保留层配置和全部依赖。

再用“金属＋油漆＋锈蚀”和“木材＋积水”验证不同组合，确保方案适用于一般表面。

## 2. 范围与阶段边界

| 阶段 | 交付 | 视觉含义 |
| --- | --- | --- |
| 第一阶段：多层 PBR 参数混合 | 每层独立贴图/UV、遮罩和高度权重，合成为一套最终 PBR 参数，再进行一次光照求值 | 支持地面、墙面、锈蚀、泥土等实用表面混合 |
| 第二阶段：物理层叠 | 用可组合的表面散射表示，分别评估相邻表层和基底，并处理覆盖、反射与透射 | 逐步实现涂层、漆膜、湿膜等更接近物理的上下叠层 |
| 第三阶段：高级材质扩展 | 按需求增加体积、次表面、各向异性、头发/布料等闭包，结合预算做简化 | 扩大可表达的材料种类，具体范围以能力和实测结果确定 |

第一阶段的高度用于计算层覆盖，不改变几何轮廓。视差映射和真实顶点/微多边形置换是后续独立功能，不能以高度混合宣称已经实现。

“类似 Substrate”是能力方向，不宣称与 Unreal 的格式、着色模型、画质或功能完全兼容。Epic 对 BSDF 层叠、覆盖和透射的定义可参考 [Substrate 官方说明](https://dev.epicgames.com/documentation/unreal-engine/overview-of-substrate-materials-in-unreal-engine)。

## 3. 当前基线与约束

| 项目 | 当前代码现状 |
| --- | --- |
| 材质图 | `engine/material/graph.mjs` 是有限节点图；标量运算编译时折叠为单个扁平材质，不执行逐像素贴图混合 |
| 材质中间表示 | `engine/material/mir.mjs` 的 `layers` 当前只支持零层或一层 `clearcoat` |
| 着色 | `shaders/material.hlsl` 支持一套基础 PBR 参数、一层专用清漆、湿润和磨损标量 |
| UV | 现有八个材质贴图槽支持独立纹理变换/采样，导入时可按槽选择源 UV 集；顶点布局不是任意数量的通用 UV 集 |
| 贴图 | 已有 `.ngtex`、mip、压缩和 sRGB/线性语义；通用材质尚无高度槽 |
| 导入 | glTF/GLB 支持基础材质和 `KHR_materials_clearcoat` 等有限扩展；通用分层材质不属于现有导入契约 |
| 运行 | 已有 SM 6.6 bindless 材质路径和受约束的纹理数组回退路径；分层能力必须单独验证各路径 |
| 编辑器 | 有材质属性与贴图入口，但还没有可用的完整材质层堆栈和层混合编辑器 |

基础材质已有的清漆、湿润、磨损、透明、发光和独立贴图映射需要保留语义。物体不同部件各绑定一个材质不计入同一表面的多层混合。

## 4. 第一阶段功能规格

### 4.1 材质层

一层定义包含：

| 类别 | 字段和行为 |
| --- | --- |
| 身份 | 稳定层 ID、名称、启用状态；调整顺序不改变 ID |
| 基础贴图 | Base Color、Normal、Roughness、Metallic、AO、Emissive、Height；允许 ORM 打包与独立标量贴图两种表达 |
| 颜色空间 | Base Color/彩色 Emissive 使用 sRGB 解码；法线、粗糙度、金属度、AO、遮罩和高度使用线性数据 |
| 标量 | 基色因子、粗糙度、金属度、AO 强度、法线强度、发光强度、高度比例/偏移 |
| UV | 每层默认 UV 集与变换；每个贴图槽可覆盖 UV 集、平移、缩放、旋转、wrap 和 filter |
| 混合 | 覆盖权重、遮罩来源、混合模式、高度混合宽度与偏置 |
| 缺省值 | 缺失可选贴图使用明确常量，如平法线、未遮蔽 AO、零发光；必需资源缺失应报错 |

首版建议每个材质 **1–4 个启用层**，作为实现预算的初始上限，而不是已有引擎限制或性能承诺。一个层可以引用可复用的材质资产，并允许实例覆盖参数；循环引用必须拒绝。

第一阶段先支持：`constant`、`textureMask`、`vertexColor` 三类权重来源，以及普通遮罩混合和高度感知混合。世界空间高度、坡度、程序噪声和绘制遮罩应作为后续扩展；不得把尚未实现的选项显示成可用。

### 4.2 覆盖权重

- 层按明确的堆栈顺序从底到顶计算；底层作为初始表面，上层以权重覆盖已有结果。
- 遮罩通道、反相、增益和偏置需明确可见。遮罩权重统一限制在 `[0,1]`。
- 权重为 0 时输出与底层一致；权重为 1 时输出与上层一致。禁用层不采样也不影响结果。
- 运行时支持变化的遮罩贴图；不能把一张动态遮罩预先折叠成常量。
- 透明物体的整体 alpha 混合、层覆盖遮罩、物理透射是不同概念；各自保留独立字段和测试。

### 4.3 高度混合

每个相邻混合步骤以两侧高度与遮罩为输入，按明确、可复现的阈值和过渡宽度计算覆盖权重。建议先实现有定义的双层算子，再按层顺序迭代组合。

- 高度贴图及比例/偏置均为线性数据；遮罩为零时上层不能因高度运算意外出现。
- 过渡宽度有正的最小值，避免除零；相同高度、全黑/全白贴图和极端参数必须稳定。
- 对于三层及以上，文档与预览必须明确采用顺序合成：顺序改变可以改变结果，但同一配置在不同帧和平台上应保持一致。
- 高度混合算法需同时提供 CPU 参考实现与 GPU 实现，并以固定输入验证边界和误差；调整算法需要版本化。
- 通道可从独立高度贴图或明确声明的打包通道读取，不隐式把 ORM 的某个通道当作高度。

### 4.4 法线混合

- 各层先根据自身 UV 和切线基解码法线，再在同一个明确的空间内混合并归一化。
- 法线图应采用与 UV 变换、镜像 UV、法线强度及 +Y 约定一致的切线基；不同 UV 集不能假设共享切线基一定正确。
- 对图案混合采用有定义的加权法线方法；对上下叠加的细节法线可提供经验证的 RNM 等方法。两种语义和适用条件应在图与文档中区分。
- 法线 mip 生成保持重归一化；BC5 XY 重建 Z 的行为与现有路径一致。
- 模型切线缺失时明确生成切线或使用受验证的导数回退。退化 UV、负缩放/镜像及曲面接缝应有确定的处理和测试。

## 5. 数据模型与编译链

### 5.1 分层材质描述

建议新增版本化的分层材质表示，例如 `nativegpu.layered-material/1`，由下列内容组成：

```text
Material
  ├─ id、name、version、整体透明模式
  ├─ layers[]：稳定 ID、层参数、每槽贴图和 UV、权重与高度配置
  ├─ 可选顶层清漆：沿用现有清漆语义并显式注明作用范围
  └─ feature/profile：目标能力、层数和采样预算
```

该结构是字段设计草图，不是当前可加载的 JSON。实现时需要给出完整 schema、默认值、数值范围和拒绝规则，并由 JS 与原生读取器使用同一套语义。

- 旧场景中的单层材质读取为等价的一层材质；旧 MIR/材质图和导入包无需用户手工迁移。
- 旧材质保持原画面及特性；只有用户明确启用新分层功能才使用新编译路径。
- 清漆与一般 PBR 层不能混成同一种无区别的结构：清漆是当前专用反射层；未来物理闭包另有明确类型。
- 稳定哈希包括层顺序、启用状态、所有参数、贴图内容、UV/采样器、混合算法版本、编译器与 shader 版本。
- 用户覆盖、共享层引用和资产重新导入需保留场景已有修改；冲突显示差异，不静默覆盖。

### 5.2 编译与运行数据

```text
编辑器层堆栈 / 材质图 / 导入资源
  → 校验与版本迁移
  → 带类型的材质中间表示：层、贴图、UV、遮罩、混合运算
  → 预算检查、无效层删除、静态表达式折叠
  → 目标平台材质记录 + 依赖清单 + shader 变体
  → 原生加载、资源绑定、逐像素混合与光照
```

新图必须支持纹理采样、颜色/向量和逐像素混合，不再只允许常量标量进入 `lerp`。可视化节点图可以在数据和运行闭环后接入，首批编辑界面可先用层堆栈完成工作流。

编译器需拒绝循环、类型不匹配、无效通道、缺少 UV/贴图、超预算层数和不可用功能，并标出层 ID 与字段。不可静默忽略不支持的层。

### 5.3 UV 数据通路

当前静态网格和蒙皮网格携带的是有限的材质槽 UV 流。多层后不能直接假设每一层每个槽都有无限数量的独立顶点属性。

1. 编译时收集每个层/槽所使用的源 UV 集，去重并计算需要携带的流。
2. 为静态网格和蒙皮网格定义一致的、版本化 UV 集映射；约定首版支持的 UV 集数量，数值在平台预算实测后冻结。
3. 每个贴图槽保存所选 UV 集及独立二维变换；多个槽共享同一源 UV 时不重复上传顶点流。
4. 基础方盒沿用明确的对象空间平面投影；静态网格/角色默认使用自身 UV。世界投影或三平面映射应作为有明确坐标与法线规则的后续功能。
5. 输入引用了缺失或超限的 UV 集时给出诊断；不能静默切换到 UV0。保持历史资产对其已有 UV 流的兼容。

首版冻结的映射（`nativegpu.layered-material/1` 原生路径）：

| UV 集 | 顶点流 | 可用条件 |
| --- | --- | --- |
| 0 | `TEXCOORD_0`；无网格的基础几何体使用平面投影 | 始终可用 |
| 1–4 | 四个额外纹理 UV 流（`textureUvs[0..3]`，导入时的法线/ORM/自发光/AO 槽源 UV） | 网格 schema `/2` 及以上、蒙皮资产 `hasTextureUvs` |
| 5–7 | 三个额外层 UV 流（`layerUvs[0..2]`，`_NATIVEGPU_LAYERUV_0..2`） | 网格 schema `/5`、蒙皮资产 `hasLayerUvs` |

加载器拒绝 8 及以上；绘制期按每条绘制检查所选流是否存在，缺失时以 `NG-E-MAT-LAYER` 失败并指出材质，绝不回退 UV0。每个流内部仍是各槽独立的平移/缩放/旋转与采样器。

## 6. 纹理资源与导入

### 6.1 高度和遮罩语义

- 为 Height 定义独立语义、线性色彩空间、有效通道、缺省值、`.ngtex` 编码与 mip 规则；遮罩按连续权重过滤。
- 默认高度以归一化数据表示，比例与偏移定义用于混合的相对高度；不将其隐含解释为真实米制几何高度。
- 压缩格式由质量测试和预算策略决定，避免对高度/遮罩使用未验证的有损格式。
- 贴图文件名、内容寻址、缓存、纹理清单、导入预览和运行依赖使用同一个语义定义。
- 允许多层共享同一张纹理，GPU 资源去重；独立 UV/采样配置不能因资源去重而丢失。

### 6.2 导入与导出

- 现有 glTF/GLB 导入保持原材质语义，基础材质与清漆转换到等价表示。
- glTF 本身的材质扩展、多个 primitive 的材质，以及本引擎的多层配方是不同来源；只在格式真实提供相应数据时导入层关系。
- 本引擎自有材质配方采用版本化资产格式，允许将现有导入材质加入层堆栈；外部格式缺失高度或遮罩时按明确缺省值处理。
- 依赖闭包必须包含所有层、遮罩、高度和法线纹理；重新导入、附件和场景打包需校验内容哈希与路径边界。
- 首版不承诺将任意分层材质无损导出为 glTF。导出到能力不足的目标时提供具体诊断；烘焙输出属于单独流程，需要明确分辨率与质量损失。

## 7. 渲染路径和平台能力

### 7.1 第一阶段：单次 PBR 光照

1. 采样各启用层的参数与遮罩，按确定的层顺序和混合规则生成权重。
2. 在线性空间混合颜色、金属度、粗糙度、AO、发光，并按明确法线算法生成最终法线。
3. 用最终参数执行现有 PBR 直接光、环境反射和阴影路径。
4. 明确不同参数的混合规则。粗糙度混合是在感知粗糙度还是微表面参数空间进行，需固定并提供参考测试。

参数混合是实时成本较低的近似：它不能表达两种反射峰同时存在，也不能等同于真实的有厚度透射层。不能将第一阶段结果标为完整物理层叠。

### 7.2 光栅、Mesh Shader、蒙皮和透明

- 普通光栅与现有 Mesh Shader 路径必须共享层求值语义；未实现的路径应显示能力错误或明确回退，不能输出看似成功的错误结果。
- 静态网格与蒙皮网格使用相同材质层配置；蒙皮需要验证法线、切线、UV 和变形后坐标。
- 首版以不透明表面为核心，并保留现有单层 MASK/BLEND 材质行为。分层透明与透射单独列为后续能力，不默认承诺与现有透明路径自动兼容。
- 编辑预览、独立运行和构建产物使用同一编译结果；光照效果、阴影和材质资源不能只在编辑器预览有效。
- 如硬件不支持所需 bindless/SM 6.6 能力，应明确拒绝、选择可验证的有限层数实现或提供显式烘焙降级；禁止静默丢弃上层或 UV 配置。

### 7.3 预算和质量

- 编译与运行报告层数、活动采样数、去重纹理数、纹理显存、shader 变体和目标平台能力。
- 禁用层、全零常量权重和等价默认纹理可在编译时消除；动态遮罩不能因为预览某一帧为零而永久消除。
- 以场景和目标机器实测 GPU 时间、纹理开销及帧时间变化。先建立单层基线，再测 2/3/4 层；不得在未测量前承诺帧率。
- 超过预算时显示建议和受影响层，提供主动选择的降级或烘焙；画质发生变化时必须可见并可追踪。

运行报告现行字段（`capabilities.layeredMaterials`）：`materials`、`authoredLayers`、`activeLayers`、`textureSamples`、`uniqueTextures`、`textureBytes`、`maxLayers`、`sampleBudget`、`shaderVariants`。禁用层与零权重常量覆盖层在构建 GPU 层表前剔除（其纹理依赖仍在加载时校验），因此 `authoredLayers` 与 `activeLayers` 的差值可直接说明消除了多少层。共享纹理只上传一次，`textureSamples`（引用次数）与 `uniqueTextures`（去重后数量）分开报告。

### 7.4 本机实测（2026-10-27）

测量脚本：`.incrementalTesting/rendering/layered-budget.mjs`（输出 `build/layered-budget/summary.json`，不纳入 CI）。

场景：12×12 地面铺满画面，单材质；每层 albedo/normal/height 三张贴图，覆盖层另加高度感知遮罩；64×64 带完整 mip；240 帧；Mesh Shader 关闭。机器：AMD Radeon 890M（D3D12，SM 6.6，512 MB 专用显存预算）。

| 层数 | 活动层 | 采样/像素 | 去重纹理 | 纹理字节 | GPU P50 | GPU P95 | 帧间隔 P95（640×360） |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 1 | 3 | 3 | 65,532 | 0.81 ms | 1.40 ms | 16.9 ms |
| 2 | 2 | 7 | 7 | 152,908 | 17.72 ms | 25.39 ms | 34.2 ms |
| 3 | 3 | 11 | 10 | 218,440 | 33.73 ms | 42.37 ms | 56.0 ms |
| 4 | 4 | 15 | 13 | 283,972 | 51.68 ms | 60.28 ms | 84.5 ms |

（GPU 列为 1280×720。640×360 复测的 GPU P50 为 0.26 / 4.95 / 11.19 / 14.09 ms，说明开销主要随像素与层数增长。）

结论与限制：

- 该 iGPU 上每增加一层约增加 3–5 ms（640×360）或 12–18 ms（1280×720）。这是单个全屏表面的极端情况，不代表全场景预算；不得据此承诺帧率。
- 4 层仍是首版编写上限；报告已给出层数、采样与纹理开销，超限的编写配置在加载时即被拒绝。
- 高开销来源尚未逐项归因（descriptor heap 采样、mip 梯度、法线切线基与光照循环都可能贡献）。在优化或改变预算前，应先用同一脚本在同一机器上复测并记录改动前后差异。

## 8. 第二阶段：物理层叠方向

在第一阶段完整可用后，新增可组合的表面散射表示和明确操作：

- **横向混合**：以覆盖权重混合不同表面，保留多种反射响应的可能性。
- **上下层叠**：上层反射、吸收和透射影响底层，按适用的 Fresnel 与能量关系求值。
- **覆盖与透射分离**：覆盖描述某层是否存在；透射描述光穿过该层的比例和颜色。
- **可控简化**：平台预算不足时，以记录在报告中的近似方法合并闭包；用户可检查简化前后差异。

先从不透明基底＋非吸收清漆建立参考闭包，验证与现有 Clearcoat 的兼容；随后再研究带颜色吸收和厚度的薄层。需要分别定义直接光、环境光、阴影、透明排序与多次散射的近似范围，不能仅增加一个“Substrate”按钮。

暂不承诺体积材质、全量多次散射、路径追踪一致性或无限层数。实际支持范围由每个闭包的实现与验证结果决定。

## 9. 编辑器交互

### 9.1 层堆栈

- 添加/删除/复制/重排层；支持启用开关、重命名、折叠和选中。
- 每层显示独立贴图槽、权重、混合模式、高度参数、法线强度和 UV 默认值；展开后可覆盖单槽映射。
- 贴图从项目资产库选择或拖入；显示语义、颜色空间、尺寸和缺失资源提示。
- 同一贴图可分配到多个槽，但颜色/数据语义冲突必须提示。
- 提供层、遮罩、顶点色、UV 网格、法线和高度调试视图；可切换模型、方块及基础机器人预览。
- 编辑草稿即时预览，保存进入场景/材质事务；一次拖动形成一个撤销步骤，并支持重做。
- 编译失败时保留上一次成功画面和草稿，标明错误层、槽与原因。

### 9.2 模型表面绘制

第一阶段支持读取已有遮罩贴图和顶点色。直接在模型上涂绘遮罩、生成纹理和管理笔刷属于后续功能，需另行设计 UV 接缝、多对象编辑、撤销、分辨率和资源保存，不预设已包含在首版。

## 11. 验收与增量测试

### 11.1 数据与数值

- 旧材质读取与构建后结果一致；新材质保存、重开、复制、撤销/重做与版本迁移保持层 ID、顺序和参数。
- 两层遮罩 0/1 与单层结果一致；三层的顺序有可预测效果；禁用层无贡献。
- 高度相等、范围端点、遮罩为零、极小过渡宽度以及极端输入无 NaN/Inf；CPU 与 GPU 参考误差设定并记录。
- 各层和各槽使用不同 UV 集、旋转/偏移、wrap/filter 后，采样正确；缺少 UV、纹理、超预算、类型错误和循环引用清楚失败。
- 法线测试覆盖平法线、正交法线、镜像 UV、退化三角形、压缩法线与光照方向；高频细节测试 mip 过渡。
- 纹理内容或任一层参数改变后构建缓存正确失效；共享纹理不重复打包，篡改依赖被拒绝。

### 11.2 原生画面与交互

- 建立砖墙/水泥/苔藓、金属/油漆/锈蚀、木材/积水三组可复现测试场景；实际可编辑场景放 `.screen/`，临时场景放系统临时目录或 `build/` 专用目录。
- 在固定相机和灯光下分别检查基色、法线、遮罩、高度、最终结果；真实验证像素变化，不能只检查材质 JSON 或渲染报告字段。
- 对相同材质比较光栅与 Mesh Shader（若设备支持）、静态模型与蒙皮模型，以及编辑预览、运行和打包运行；容差根据参考和设备实测制定。
- 验证无 SM 6.6/绑定能力、资源缺失、编译失败、设备重建、预算超限时的反馈和回退。
- 测试至少覆盖一次完整用户操作：添加层、绑定各贴图、调 UV、高度混合、撤销、保存、重开、运行、构建。

### 11.3 测试范围与落位

- 按依赖范围运行现有 `npm run test:assets`；涉及原生资产绘制时使用 `npm run assets:verify` 或该入口中对应的专项验证，原生宿主使用独立 `build/assets-host`。
- 新增材质、shader、截图、基准和审计入口放 `.incrementalTesting/rendering/`；资产格式专项放 `.incrementalTesting/assets/`；编辑器专项放 `.incrementalTesting/editor/`。
- 新增命令时同步 `package.json`、`.github/workflows/windows.yml` 或 `.incrementalTesting/core/ci.ps1`、`.incrementalTesting/commands.json` 与 `.incrementalTesting/README.md`。
- 场景源放 `.screen/`，运行时资源放 `assets/`；报告与截图写入项目自己的 `reports/`、`build/` 或专用临时目录。引擎内创建的项目只能位于 `%USERPROFILE%/Documents/nativeEngineProject/<项目名>`。
- 不运行全量测试、`npm test`、`npm run verify` 或完整 CI，除非用户之后明确要求。

## 12. 风险与待定设计

| 风险/问题 | 应对 |
| --- | --- |
| 每层每槽独立 UV 增加顶点带宽 | 源 UV 集去重，编译期检查数量；为静态和蒙皮分别测内存与性能 |
| 不同 UV 的法线切线基不一致 | 明确切线基来源与导数回退，使用方向性测试，不只对比颜色 |
| 层数和贴图增加采样成本 | 先测 1–4 层，记录采样与 GPU 时间；静态消除和显式降级 |
| 透明、清漆和多层语义冲突 | 第一阶段限定不透明通用层；原有单层功能保持；物理叠层分阶段实现 |
| 高频编辑触发反复编译或资源泄漏 | 异步编译、合并过时请求、资源代次与 GPU 回收；失败保留上次有效画面 |
| 参数混合被误认为真实层叠 | UI、文档和运行报告明确标记混合模式与近似，物理层叠另行验收 |
| 默认层数、UV 数和预算阈值 | 本文的 4 层是建议值；具体上限与性能阈值由 L0/L6 的设备和场景实测确定 |
