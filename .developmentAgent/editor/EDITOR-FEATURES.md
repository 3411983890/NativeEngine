# 编辑器功能总表与分期建议

- 日期：2026-10-21。
- 定位：面向独立开发者的游戏制作工作台，连接 Web 编辑器、原生引擎、内容工具与 AI Agent。
- 本文是需求汇总与排序建议，不代表批准实施所有功能，也不代表对应引擎系统已经完成。
- 现状来自当前工作区的代码与文档核对；本次没有重新执行构建、GPU 验收或界面测试。工作区内正在推进的其他功能以各自实现和证据为准。
- 当前路线保持 **Web 编辑器 + 原生引擎**；实时视口接入是独立工作包，不以前置编译定制 Chromium 为条件。
- 用户补充的首版要求：**必须在真实三维视口里选择和操作物体**。原生实时视口、编辑相机、拾取、变换和临时预览提升为 P0；二维布局保留为辅助。接入方案见 [EDITOR-VIEWPORT.md](EDITOR-VIEWPORT.md)。

## 1. 编辑器应帮助用户完成什么

核心闭环：**组织项目 → 导入或生成内容 → 搭建场景 → 定义玩法与表现 → 运行验证 → 检查问题 → 修改与回退 → 构建交付**。

编辑器提供这些工作的可视化入口、上下文、预览与反馈。渲染、动画求值、碰撞和资产构建仍由对应引擎或工具系统负责；一个面板不能代替底层能力。

优先级定义：

| 优先级 | 含义 |
| --- | --- |
| P0 | 近期基础：让现有场景编辑可靠、顺手，统一数据与状态 |
| P1 | 制作闭环：让用户能完成一个包含资产、角色、玩法的小型项目 |
| P2 | 专业扩展：随引擎能力和真实制作需求逐步增加 |
| P3 | 可选研究：大规模协作、完整高级图编辑和研究功能，不作为首版前提 |

## 2. 当前能力：界面、底层与计划分开看

| 领域 | Web 界面当前已有 | 底层已有或正在接入 | 尚缺的编辑体验 |
| --- | --- | --- | --- |
| 项目与场景 | 枚举当前项目的场景、切换与刷新 | 场景 JSON 与校验器 | 新建项目/场景、另存为、最近项目、跨版本迁移 |
| 场景浏览 | 平面实体列表、名称/类型搜索、单实体选择 | UUID、8 种实体类型 | 真正父子层级、分组、多选、隐藏/锁定 |
| 空间编辑 | XZ 二维顶视图、拖动 XZ、缩放和适配 | 原生三维渲染与相机 | 三维编辑相机、对象拾取、旋转、操纵柄、吸附 |
| 属性编辑 | 名称、位置、尺寸、颜色、碰撞开关 | 基础实体、内联/命名材质读取、灯光字段 | 材质/灯光编辑、组件、批量编辑和资产引用 |
| 编辑记录 | 多实体本地草稿、差异预览、提交、撤销上次保存 | revision 冲突拒绝、最多 100 步历史、崩溃恢复 | 本地逐步撤销/重做、历史浏览、草稿恢复、冲突后的重新应用 |
| 原生画面 | 启动/停止自有原生窗口、按需 PNG 快照 | 热重载、D3D12 宿主 | 内嵌实时视口、双向选择同步、编辑态临时预览 |
| 纹理与材质 | 只读部分材质信息，不能编辑完整材质 | PNG 构建、mip、`.ngtex`、原生命名材质接入已有工作区实现 | 资产浏览、贴图槽、材质实例、预览、依赖与构建状态；完整材质编译方案仍是规划 |
| 角色与动画 | 尚无专用面板 | glTF 单 skin 子集、骨架/片段、VS 蒙皮、控制器、混合与 Notify 等基础链路已有实现 | 角色导入、骨架/片段检查、时间轴、状态与混合调试；高级动作能力仍未完成 |
| 诊断与查询 | 编辑操作日志和错误提示 | 场景 lint、可达性检查、查询 DSL | 问题列表、对象定位、空间叠加、查询结果选择 |
| 性能与回放 | 尚无专用面板 | 帧预算、GPU/CPU 报告、录制/严格回放、黑匣子、图像回归 | 帧分析、回放控制、前后图对比与报告浏览 |
| AI | 界面没有模型或任务工作台 | MCP 场景工具与事务契约 | 任务计划、上下文选择、候选结果、修改审核、取消/恢复、费用与执行记录 |
| 构建与交付 | 尚无专用面板 | 场景内容寻址构建、原生验证与 zip 打包 | 构建配置、任务进度、失败定位、产物与运行入口 |

核对入口：[编辑器](EDITOR.md)、`editor/ui/app.mjs`、`editor/service.mjs`、`engine/scene/`、[动画实现](ANIMATION.md)、`tools/textures.mjs`、`host/scene_loader.cpp`、`renderer/d3d12_renderer.h`。

### 2.1 需要持续验收的数据与界面一致性

当前原生加载器、`assets/scene.schema.json` 和 `engine/scene/index.mjs` 已有 v1/v2 与命名材质支持；Web 属性面板已接入命名材质的 `wetness` / `wear` / `roughness` / `metalness` / `uvScale` 参数编辑（走 `material_patch`），但贴图槽替换、资产选择器和材质实例仍没有完整 UI。底层能加载，不等于编辑器已经具备该类内容的完整制作体验。

增加材质、旋转、父子关系或组件前，应先统一 **Schema → JS 校验与事务 → 原生加载 → UI → MCP → 保存/撤销/恢复**，并给旧场景明确的迁移规则。不得为了让新控件可用而静默丢弃未知数据。

## 3. 按用户工作流组织功能

| 工作流 | 用户希望完成的操作 | 应得到的反馈 |
| --- | --- | --- |
| 搭建一间房或一座小镇 | 拖入物体、复制排列、对齐、设置碰撞、放灯与出生点 | 即时布局反馈、可运行场景、缺失资产与预算提示 |
| 调整一种材质 | 选中物体、替换贴图或实例、调整参数 | 实际原生画面、影响对象、资源开销、可回退修改 |
| 调试一个角色动作 | 选角色和片段、拖动时间轴、查看过渡与事件 | 当前姿态、骨架、状态/权重、问题位置 |
| 添加交互玩法 | 配置触发条件、动作和目标引用 | 可定位的事件日志、条件与完成状态、错误诊断 |
| 请 AI 完成一个任务 | 指定目标、相关对象、约束和预算 | 可检查的计划、候选差异、验证结果与提交记录 |
| 找到场景为何不对 | 检查问题、定位对象、查看画面与耗时变化 | 原因、证据、修复入口、前后对比 |
| 交付一个可玩版本 | 选择目标与质量档、验证、构建、启动产物 | 清晰的成功/失败、日志、完整产物和可复现版本 |

## 5. AI 原生编辑器必须形成的完整体验

一个聊天输入框不足以完成制作。建议采用以下任务生命周期：

**说明目标 → 绑定相关场景/对象/资产 → 明确约束 → 生成计划 → 执行工具 → 展示候选与影响 → 验证 → 采用修改 → 留下记录 → 可回退。**

需要贯穿的功能：

1. **对象上下文**：明确 AI 正在操作哪些实体、资产与 revision；支持把选中对象加入任务。
2. **任务进度**：区分等待、运行、需要输入、失败、取消与完成；长任务支持停止、超时和恢复。
3. **结果检查**：除 JSON 差异，还展示改变的对象、前后图、资产依赖、玩法影响与性能变化。
4. **候选与采用**：候选留在隔离工作区，用户能比较；有效候选通过同一事务入口采用，失败保留当前可用场景。
5. **可追溯执行**：记录工具输入/输出、内容版本、构建/验证结果；连接模型后再提供真实用量与预算信息。
6. **一致的操作能力**：鼠标、快捷键、CLI 与 AI 最终作用于同一命令和版本体系；资产事务需要新增，不能假设现有场景事务已经覆盖任意文件。

近期可先做好已有工具的选择、调用与结果审核，再加入模型客户端；自然语言生成不能替代结构化命令和验证。

## 6. 不属于某个面板、但决定编辑器是否好用的能力

| 能力 | 要求 |
| --- | --- |
| 即时反馈 | 拖动/输入改变本地预览；一次连续拖动合并成一步撤销，不能每帧写盘/重置游戏 |
| 编辑态与运行态 | 项目内容、临时草稿、已运行的 revision、运行时状态分别清楚显示；停止运行恢复编辑上下文 |
| 选择与引用同步 | 场景列表、三维对象、属性、资产引用、问题列表共用选择上下文 |
| 稳定保存 | 标准保存与撤销顺手；普通小改动不必每次审阅大段 JSON，批量/AI 修改保留明确的预览审核 |
| 数据恢复 | 外部改动、进程重启、未完成构建或异常退出后保留用户工作，并给出能执行的恢复入口 |
| 能力诚实 | 区分可用、构建中、不支持；二维布局、PNG 快照和实时 GPU 视口使用明确不同的名称 |
| 可解释错误 | 指向对象/字段/文件与失败步骤，说明如何修复；详细技术日志按需展开 |
| 性能与输入 | 大量实体使用列表虚拟化；慢任务在后台，界面持续响应；快捷键避免干扰文本与中文输入 |

## 7. 推荐实施顺序与验收

### P0：把现有原型变成可靠场景编辑器

- 统一场景版本、材质引用与命令契约，保证 UI/Agent/原生读取同一份数据。
- 明确本地草稿、已保存、正在运行的版本；解决外部修改后的保留、刷新和重新应用。
- 补齐本地撤销/重做、草稿恢复、多选/复制、基础字段编辑与查询。
- 接通 Electron 中的真实原生三维视口、编辑相机、对象拾取、移动/缩放操纵柄与临时预览；二维布局只作为辅助。
- 三维拖动与属性面板双向同步；松开鼠标形成一条可撤销命令，取消拖动恢复原值，避免每帧写盘与重置玩法。
- 将基本保存、错误定位、快捷键和面板尺寸处理好，再确定视觉方案。

**验收任务：** 在编辑器的真实三维视口中选中并移动一个物体，观察即时反馈与属性同步，取消或撤销恢复原位；复制并摆放一组物体，保存重开后位置一致。过程中外部工具修改同一场景，用户草稿不丢失且不会覆盖新版本。

### P1：形成一个小型游戏的制作闭环

- 在 P0 三维视口基础上增加更完整的吸附、旋转与专业预览模式；共用同一原生渲染路径。
- 资产浏览与导入、参数化材质/灯光、已有角色动画预览。
- 预制组合、现有玩法参数、问题列表、lint/查询、运行与回放、构建打包。
- 接入 AI 任务与候选审核；模型接入后提供真实的计划/调用/结果，沿用同一事务。

**验收任务：** 从模板建立小场景，加入道具与角色，调整材质和灯光，配置一条交互，运行与诊断，然后构建能独立启动的版本；全程不要求手改 JSON。

### P2：按内容生产需求增加专用工具

依次根据真实项目需求选择动画调试/配置、材质配方、物理导航、效果与场、音频、脚本、游戏 UI、地形和镜头序列。每个工具先交付参数、预览、诊断与事务，再判断是否需要复杂节点图。

**验收方式：** 每个专业工具绑定一条具体内容任务和一组可重复验证的结果，不以“面板已经画出来”作为完成标准。

### P3：有明确收益时再进入

完整高级节点编辑器、生产级动作匹配/重定向/面部工具、大世界协作、实时多人编辑、插件市场、复杂发布系统等。不把它们叠加成首版前置，也不把引擎研究路线全部塞进主界面。

## 8. 功能如何映射到界面

建议预留工作区切换，而不是让 26 类功能同时常驻：

| 工作区 | 主任务 | 共享部分 |
| --- | --- | --- |
| 场景 | 摆放、选择、属性、运行 | 项目/资产、选择、命令、历史、状态 |
| 资产与材质 | 导入、引用、参数与原生预览 | 同一资产身份、依赖、构建与错误体系 |
| 角色与动画 | 骨架、片段、时间轴、状态调试 | 同一资产与原生预览会话 |
| 效果与世界 | 粒子、场、地形等专用内容 | 按运行时能力逐步开放 |
| AI 与任务 | 目标、执行、候选、差异、采用 | 同一事务、项目上下文与验证 |
| 诊断与交付 | 问题、性能、回放、构建 | 同一日志、任务队列、报告与版本 |

这些是功能分组，尚不是视觉设计或固定页面结构。专业编辑器可以按需打开为文档标签；常用属性与问题定位保留在当前操作上下文中。

## 9. 对当前原型的定位与下一步

当前界面可作为事务与原生预览连接的工程原型，不应直接作为最终产品布局继续堆功能。

下一步先确定 **P0/P1 的首版范围和三条最高频制作任务**，再围绕真实资产、对象数量、编辑状态与错误状态制作视觉方案。功能清单确认前，本文件不触发新功能实施。
