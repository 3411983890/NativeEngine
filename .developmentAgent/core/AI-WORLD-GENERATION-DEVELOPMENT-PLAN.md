## 1. 产品目标与已确认需求

用户可以导入草地、树木、岩石、河流外观、道路和建筑构件，在原生场景俯视图中画区域或路径，由程序自动生成可编辑、可保存、可运行的大场景。

| 范围 | 已确认方向 |
| --- | --- |
| 大场景 | 本轮最高优先级，先实现原生地图生成与编辑 |
| 基础交互 | 选择资源或规则，用画笔画区域；道路、河流支持路径编辑 |
| 组件导入 | 允许首次导入时可视化标记尺寸、朝向、连接点 |
| 建筑 | 支持单栋和住宅区；建筑专项先实现单栋 |
| 建筑风格 | 中式、古风 |
| 建筑内部 | 多层、楼梯、完整房间，自动摆放家具与灯具 |
| 布局 | 自动布局优先，同时支持手画分区与局部锁定 |
| 示范建筑 | 两层古风客栈；一层大堂、柜台、餐区、厨房，二层默认六间客房 |

第一阶段示范世界采用山林、草地、河流、道路和小型古风聚落。地图规模、组件清单和默认数量是下文建议值，实施时允许通过性能实测调整，不改变上述需求。

### 1.1 两条生成路径

1. 参数或自然语言创建世界草案，整体生成地形、生态区、河流、道路与聚落。
2. 在已生成世界中用画笔、路径和区域逐步编辑，只重生成受影响内容。

两条路径使用同一份 World Recipe 和同一套生成器。没有模型服务或网络时，参数面板和画笔仍可完成所有核心操作。

### 1.2 第一阶段完整交付边界

必须交付：原生入口、真实俯视视口、地形与碰撞一致、草地/树林/岩石分布、道路/河流、基础聚落、局部重生成、撤销重做、保存恢复、分块加载和独立发布运行。

完整客栈内部安排在后续专项阶段。早期聚落可引用预制建筑或简化程序化建筑；编辑器必须标注其能力，不能把没有室内的外观模型称为完整建筑生成已完成。

## 3. 编辑器原生使用流程

1. 在现有编辑器工具栏提供“世界生成”，资源面板提供“世界组件库”。
2. 新建世界，设置宽高、随机种子、地形范围、生态预设及预算，显示低分辨率预览。
3. 用地形笔刷调整山地、平地和水域；画草地、树林等生态区域。
4. 用路径工具画河流和道路；拖动控制点修改宽度、走向和交叉口。
5. 画聚落区域，设置建筑密度、退界和样式；允许先固定道路再生成地块。
6. 检查原生三维结果，锁定满意区域，局部重新生成。
7. 保存，在同一引擎中运行角色，验证道路、坡面、河岸和建筑入口。
8. 发布为独立运行包，离开编辑器、断开 AI 服务仍能加载世界。

### 3.1 画笔契约

- 形状：圆形、矩形、多边形；路径工具单独处理道路和河流。
- 参数：半径（米）、强度、边缘衰减、密度、规则集、种子与擦除模式。
- 按世界距离重采样笔迹，不能按鼠标事件数量决定密度。
- 原生视口完成拾取，输入包含 viewportSession、cameraRevision 和命中位置；过期相机结果作废。
- 采样区分地形、桥面、建筑层；默认绘制到地形，不误刷到屋顶。
- 一次按下到释放构成一次编辑操作和一次撤销；Esc 丢弃本次草稿。
- 高分辨率生成异步执行，拖动期间使用低成本预览，禁止阻塞原生绘制线程。
- 视口缩放、DPI、面板尺寸变化必须换算到原生客户区像素再发射拾取射线。
- 画笔轮廓、路径控制点与选区由原生覆盖层绘制，避免 HTML 被原生 HWND 遮挡。

### 3.2 图层与手工编辑

逻辑层：基础地形 → 地形修改 → 水域 → 道路 → 地块/建筑 → 植被 → 装饰 → 手工覆盖。

顺序代表默认求解依赖，不是所有图层都简单覆盖。道路与河流交点进入桥梁/涉水决策，建筑占地会反向形成植被排除区。

支持显隐、锁定、单层重生成、区域锁定、对象锁定、烘焙为手工对象。手工删除生成物保存 tombstone；手工移动保存稳定 ID 覆盖；重生成不能静默恢复已删对象或覆盖锁定内容。

## 4. 系统架构与模块职责

```text
编辑器 UI / AI 工具
        ↓ 相同受控 API
World Service：校验、项目隔离、任务、事务、预览
        ↓ 版本化输入
原生 World Compiler：地形、路径、散布、聚落、分块编译
        ↓ 不可变分块产物 + 清单
Scene Transaction：提交世界引用与 revision
        ↓
原生 World Runtime：调度、加载、查询、碰撞、生命周期
        ↓
原生 Renderer / Physics / Vegetation / Water
```

### 4.1 原生边界

- JS 管理编辑状态、输入契约、任务调度和文件事务；不在 JS 和 C++ 各写一套独立生成算法。
- 核心几何、采样和分块编译采用可离线运行的 C++ 库，首版通过引擎配套 worker 可执行程序调用；启动方式可后续优化。
- Worker 和发布运行时共享数据定义与校验；运行时加载 cooked 世界，不调用 Node、Electron 或模型服务。
- 地形、实例、碰撞、路径查询是引擎内置模块；既有植被、水体通过明确的适配接口接入。
- 协议只发送受控命令和有界批次/文件引用，不将数十万实例逐条挤入旧命名管道文本协议。

### 4.2 建议新增模块（均待创建）

| 位置 | 职责 |
| --- | --- |
| `engine/world/` | authoring schema、规则校验、项目文件与 cooked 清单契约 |
| `engine/native/world/` | C++ 编译器、确定性采样、分块、运行时、空间查询 |
| `editor/world-service.mjs` | 世界工具 API、任务状态、事务协调 |
| `editor/ui/world/` | 面板、画笔状态、区域/路径编辑 |
| `host/world_bridge.cpp/.hpp` | 视口协议、世界快照/草稿接入与 ACK |
| `renderer/world_draw.cpp/.hpp` | 地形块与实例批次接入，复用已有材质系统 |
| `tools/world.mjs` | 生产 cook、构建、打包入口；不是测试脚本 |

同步修改既有 scene、host、renderer、AI 白名单和生产构建列表。避免把功能全部堆入 `host/main.cpp` 或 `editor/ui/app.mjs`。

## 5. 世界规模、坐标与分块

### 5.1 分级目标

| 档位 | 世界范围 | 用途 |
| --- | --- | --- |
| 调试 | 256 m × 256 m | 快速增量开发 |
| 第一交付 | 2,048 m × 2,048 m | 真实大场景完整闭环 |
| 扩展压力 | 8,192 m × 8,192 m | 验证按需加载与内存有界 |

以上为设计目标，须报告设备、资源复杂度、采样分辨率和实测结果。支持创建 8 km 世界不意味着能同时加载其全部最高精度内容。

### 5.2 基础分块

- 默认 chunk 为 128 m × 128 m；2 km 档为 16×16 块，8 km 档为 64×64 块。
- 默认近场地形步长 1 m，单块 129×129 顶点；远场使用降采样 LOD。更细局部细节另设覆盖层。
- chunk 坐标采用有符号整数；以 floor 而非向零截断计算负坐标分块。
- CPU 世界寻址采用整数 chunk + 局部米制坐标；GPU 使用相机相对坐标。
- 高度向上轴、模型朝向和导入约定须在 P0 从现有代码冻结；当前高度场以 XZ 平面工作，新模块遵循现有约定，禁止单独更换坐标系。
- 对 8 km 档先验证当前浮点物理精度；若需要物理原点迁移，列为独立能力并对刚体、角色、水体和空间索引统一迁移。

### 5.3 世界不是一个全量实例数组

每块分别包含：高度/材质权重、静态实例组、道路与河床网格、碰撞代理、地块/建筑引用、查询数据和内容哈希。

稀疏编辑遮罩按瓦片存储，不分配覆盖全部世界的多层超大纹理。清单与索引可常驻，网格、实例和碰撞分级按需加载。

## 6. 持久化数据与版本契约

### 6.1 项目目录

```text
%USERPROFILE%/Documents/nativeEngineProject/<项目名>/
  .screen/main.scene.json
  .screen/world/main.world.json
  .screen/world/layers/<layer-id>.json
  .screen/world/overrides/<region-id>.json
  assets/world-libraries/<library-id>/
  assets/world-rules/<ruleset-id>.json
  assets/world-cooked/<manifest-hash>/manifest.json
  assets/world-cooked/<manifest-hash>/chunks/...
  build/world-cache/...
  reports/world-generation/...
  outputs/<发布版本>/...
```

`.screen/` 保存可编辑源；`assets/` 保存可发布资产与 cooked 内容。所有运行项目输入、保存和证据位于项目内；引擎源码仓库只存实现、开发文档及受控样例源。工程内的开发测试编译产物可放 `build/world-host/`，不得占用 `build/assets-host/` 或其他专项产物。

### 6.2 World Recipe 示例（拟议 v1）

```json
{
  "schema": "nativegpu.world/1",
  "worldId": "ancient-valley",
  "generatorVersion": "worldgen-1",
  "seed": "947210",
  "extentMetres": [2048, 2048],
  "originMetres": [-1024, 0, -1024],
  "chunkSizeMetres": 128,
  "terrain": {"sampleStepMetres": 1, "preset": "mountain-valley"},
  "libraries": [{"id": "ancient-kit", "file": "assets/world-libraries/ancient-kit/library.json", "sha256": "<64位十六进制哈希>"}],
  "layers": [{"id": "forest-main", "file": ".screen/world/layers/forest-main.json", "sha256": "<64位十六进制哈希>"}],
  "overrides": [],
  "budgetProfile": "desktop-balanced"
}
```

这是契约示意，哈希占位符不能通过正式校验。种子采用十进制字符串，避免 JS/C++ 跨语言 64 位整数损失。范围、数量、路径长度、文件尺寸、内存预算及嵌套层级必须有显式上限。

### 6.3 scene 引用与 cooked 清单

拟议 scene 可选 `world` 字段记录 worldId、recipe 相对路径/哈希、cookedManifest 相对路径/哈希和生成器版本。必须同步 JS 严格校验、JSON Schema、原生读取、查询、依赖收集和发布；不能仅注入一个未知字段。

Cooked 清单记录格式版本、输入摘要、规则/组件哈希、chunk 坐标/包围盒/LOD、二进制文件哈希、依赖与预算统计。二进制块指定魔数、版本、小端格式、段偏移、计数、字节长度及校验；加载前验证整数溢出和完整性。

输入摘要包含种子、规范化参数、生成器版本、资产内容哈希和手工覆盖。文件时间戳不作为有效缓存依据。运行时只需要 cooked 清单及其资源闭包；编辑源可不随发布包携带。

### 6.4 确定性边界

- 随机流由 `worldSeed + generatorVersion + layerId + globalCell/featureId` 派生，不依赖线程执行顺序。
- 固定散列与 PRNG 算法/测试向量，禁止 C++ 默认随机库与 JS Math.random 各自决定输出。
- 稳定 ID 来自来源区域、特征和候选编号；密度或路径拓扑变化可能使对象失效，覆盖项需要失效提示和重绑定入口。
- 相同版本和输入在支持的构建环境输出一致的拓扑、ID 与量化后数据哈希；跨硬件浮点细节若不保证逐位相同，必须量化或明示容差。
- 生成算法升级显式迁移并预览差异；不得因引擎升级自动改写已有世界。

## 7. 组件库与资产导入

复用现有资产导入流程，先检查该流程实际支持的格式，再提供对应按钮；不承诺任意格式自动可用。

组件元数据包括：稳定资产 ID、模型与材质哈希、米制尺寸、轴向、枢轴、包围盒、类别、风格标签、LOD/碰撞引用、允许缩放范围和放置规则。

类别至少包含 ground-cover、grass、tree、rock、road-piece、bridge、building-prefab 和 building-module。地表材质与散布草模型是不同资源，画草地时可同时选择两者。

可视化标记工具支持：地面接触面、正前方、连接点、入口、可通行/不可占用区域、楼梯上下端及家具操作空间。地形贴图不能被当作现成可流动河流；河流资源库应分别记录水材质、河岸组件及水体参数。

导入单位、缺失材质、过大面数、缺少 LOD、不可用碰撞和风格冲突均显示可操作诊断。缺失资源使用诊断占位并保留引用，不静默删除生成层。

## 8. 程序化生成管线

```text
输入校验与预算预估
 → 基础地形与生态场
 → 河流图与河床约束
 → 聚落中心/道路图的联合规划
 → 道路平整、交叉口、桥梁
 → 地块与建筑占地
 → 最终地形/禁入区
 → 植被与装饰
 → 碰撞/连通性/预算校验
 → chunk cook 与预览
```

每步有显式输入、输出和依赖版本。地形先提供基础高程，河流和道路形成修改层，最终合成后再供散布与碰撞采样，避免不同模块读取不同地面。

### 8.1 地形

第一版支持有界噪声/山脊与谷地预设，以及升降、平滑、平整画笔。地形是高度场，洞穴、悬崖倒扣和立体地洞另用网格，不承诺由二维高度场生成。

最终高度同时驱动渲染和碰撞；材质表面微细节不能替代真实几何碰撞。chunk 边界从全局坐标函数采样并共享约束，法线计算带邻域 halo，LOD 使用接缝索引或裙边并验证碰撞无裂缝。

### 8.2 草地、森林与岩石

- 使用坡度、高度、湿度、生态区权重、地表材质和排除区约束。
- 树和大石采用最小距离/蓝噪声式候选筛选；草使用固定世界网格候选与密度阈值。
- 密度修改对已有候选做确定性增减，避免整个区域随机洗牌。
- 允许沿坡对齐并设置最大倾斜；树木通常保持接近竖直。
- 密度定义为单位面积的期望数量，超预算时显示削减原因，不能无限生成。
- 道路、河床、建筑退界、入口与玩家出生点形成排除区。
- 候选在全局网格定义，以核心区归属和 halo 比较处理跨块间距，禁止每块独立散布造成接缝。

### 8.3 河流

输入为路径、宽度曲线、河床深度、岸坡和水材质；全局自动生成可依据地形降坡寻找路径，允许用户修正。

阶段一生成连续河床、水面和河岸分布，并验证水面与河床关系、连接点高差及自交；路径上坡时给出冲突或分段落差方案，不静默画一条穿山的水带。

河流视觉与水动力分级：远景采用有流向的静态/低成本水面；近场在预算内接入现有水体。全世界高分辨率流体模拟不属于首版交付。现有水体适配器若暂不支持河网，应先提供真实水面与明确功能状态，不能假称已接入完整河流物理。

### 8.4 道路

输入为路径图、宽度、坡度限制、路面/路肩和节点类型。路径图保存语义节点，网格为派生产物。

生成中心线、横断面、地形平整与过渡区、弯道和路口。修复急弯、短段、自交及重复节点；无法满足坡度限制时返回诊断，不以拉伸模型掩盖问题。

道路与河流相交进入桥梁或涉水规则；第一版至少支持一种有碰撞的简桥模板。道路不能直接覆满水面充当桥。跨块路口按稳定 junctionId 统一求解，再裁切网格到块。

### 8.5 聚落与建筑占地

先选可建设地带/聚落中心，规划干路，再沿路划分地块与支路；允许有限次数协调迭代，禁止道路与建筑相互重算形成无穷循环。

地块受坡度、洪泛/水域排除、道路退界、建筑间距与入口连通约束。输出可建设地块及建筑请求，早期引用预制房屋并完成地基/碰撞/门前通道；失败地块显示原因而不是强行放置。

## 9. 跨块依赖与局部重生成

每次编辑产生 dirty bounds、变更类型和输入版本。调度器根据依赖图计算受影响节点、chunk 与 halo。

| 修改 | 典型影响 |
| --- | --- |
| 草地密度 | 本层候选与材质权重，不重建道路 |
| 局部地形 | 地形/法线/碰撞及该区植被、道路坡度、水岸检查 |
| 道路控制点 | 相邻路段、路口、平整区、关联地块和排除区 |
| 河流上游/出口 | 可能影响下游河段；不能假设仅影响画笔包围盒 |
| 建筑占地 | 地基、入口、植被排除和相关道路连接 |
| 材质参数 | 材质/资源依赖，通常不重做几何布局 |

道路/河网先在低成本世界级语义图求解，再局部编译几何。影响传播按依赖闭包求到稳定状态；超过预算时提示实际范围并分批执行。不能为了宣称“局部”而保留错误下游结果。

## 10. 异步任务、事务与撤销

### 10.1 任务状态

`queued → validating → generating → cooking → ready → committing → committed`；可进入 failed、cancelled 或 stale。

任务标识含 projectId、worldId、taskId、baseRevision、inputHash、epoch 和 generatorVersion。进度按阶段/处理块数报告；缺少总量时不伪造百分比。

用户持续绘制时合并尚未开始的任务，取消过时任务；旧任务晚到结果不得覆盖新预览。项目关闭、切换、视口重建时提升 epoch，清理草稿与任务订阅。

### 10.2 提交流程

1. 从指定 revision 获取不可变输入快照。
2. 在项目 `build/world-cache/<taskId>/` 生成并校验候选块。
3. 将校验通过的内容写入按哈希命名的不可变资产目录，发布完整清单。
4. 比较 expectedRevision 与输入摘要，通过现有事务边界原子切换 scene 中的世界引用。
5. 宿主加载候选，确认资源可用后在帧边界切换可见集合；ACK 返回实际 revision/manifestHash。
6. 记录撤销所需旧引用、输入差异与覆盖状态，之后清理无引用缓存。

文件系统多文件写入不宣称天然原子；以不可变内容 + 最终引用切换实现逻辑原子性。中途失败可以留下可回收的无引用文件，但不能留下半个已提交世界。

预览使用独立 draftToken，不改正式 revision。发生冲突返回 REVISION_CONFLICT 并保留草稿；重新生成或基于最新输入重放，不能静默覆盖。

撤销/重做切换配方与清单引用，不要求复制全世界。历史引用固定其资源，垃圾回收必须识别当前世界、撤销/重做历史、运行快照和发布任务的引用。

## 11. 原生运行时与性能设计

### 11.1 分块状态机

`unloaded → requested → reading → validated → cpuReady → uploading → resident → retiring → unloaded`。

I/O、解码和 CPU 校验在后台执行；D3D12 上传遵守渲染线程/命令队列规则。资源释放等待 GPU fence，禁止旧块仍在绘制时复用内存。失效任务在每阶段检查 epoch。

以相机和玩家作为加载源；碰撞预加载范围按角色最大速度、最坏加载延迟和制动距离计算。未准备好的地面阻止角色进入或暂缓传送，不能让玩家落入空世界。

### 11.2 LOD 与预算

- 近场：高精度地形、实例、碰撞及有限交互。
- 中场：简化地形、模型 LOD、无细草或降低密度。
- 远场：低精度地形/聚落代理，不生成完整室内与动态碰撞。
- 分别限制 resident chunk、CPU 内存、GPU 资源、上传字节/帧、提交时间、实例量、碰撞代理和活动灯数量。
- 同网格/材质/绘制状态合批；透明物、蒙皮物遵守现有批处理限制。
- 不为每一株草创建普通实体、独立刚体或独立 draw call。
- 存储分块实例并按需更新，不在相机移动时重新生成世界或重传全部实例。
- 细节降级应有计数和 UI 状态；编辑源信息保持完整。

### 11.3 性能验收目标（不是现有成绩）

| 场景 | 初始目标 |
| --- | --- |
| 2 km 世界 | 约 10 万棵树/岩石候选，约 100 万草候选；分块存储，按需驻留 |
| 显示设置 | 1080p、平衡档；记录视距、阴影、LOD 和实际驻留数量 |
| 连续漫游 | 指定验收机上帧时间 p95 ≤ 33.3 ms；统计至少 60 秒 |
| 画笔反馈 | 轻量预览目标 ≤ 100 ms；正式重生成异步 |
| 局部编辑 | 单个草木块重生成目标 ≤ 1 s；道路/河流另报实际依赖范围 |
| 流式预算 | 主线程世界更新初始预算 2 ms/帧；上传初始预算 8 MiB/帧 |
| 8 km 压力档 | 长距离漫游内存随驻留预算有界；不要求与 2 km 同等首次 cook 时间 |

P0 先选定设备与内存预算；P5 对目标实测和调整。需要同时报告平均值、p95、最大停顿、冷/热缓存、内存峰值和任务耗时。降分辨率、隐藏对象或跳过碰撞必须披露，不能用空场景达标。

## 12. 碰撞、可通行性与查询

世界运行时提供高度、法线、地表类型、水域、道路、建筑占地和静态碰撞查询，返回数据版本与是否就绪。

地形渲染 LOD 可以降级，近场碰撞误差需单独约束。道路路面、桥面和楼梯是独立表面，不能只靠查询最高地形高度处理。

第一阶段提供道路图/地块入口的连通性验证和角色实走证据；不把该图称为完整导航网格。NPC 自动寻路若纳入后续范围，应另加分块导航数据、动态阻挡和跨块链接。

世界修改提交时成组交换地形、静态碰撞和查询索引。运行中结构性编辑首版可限制为暂停/编辑态；无需在第一阶段承诺角色站立处地形随意实时改动后仍保持全部模拟状态。

## 13. AI 接入与工具协议

AI 将自然语言转为受约束的世界参数/编辑计划，复用 UI 的预览、校验和提交路径。确定性几何与布局不依赖模型逐实例输出。

拟议工具（当前尚未注册）：

| 工具 | 职责 |
| --- | --- |
| `world_capabilities` | 当前支持的生成器、资源、预算与原生状态 |
| `world_create` | 创建项目内世界草案 |
| `world_library_inspect` | 组件适配性与缺失标记 |
| `world_preview` | 参数/笔迹/路径变更预览，返回 taskId |
| `world_job_status` / `world_cancel` | 查询、订阅和取消任务 |
| `world_apply` | expectedRevision + taskId + inputHash 提交 |
| `world_query` | 选区、块、路径、错误与预算查询 |
| `world_regenerate` | 指定区域/图层/规则重生成 |
| `world_lock` | 锁定对象或区域，写入编辑覆盖 |
| `world_undo` / `world_redo` | 接入统一历史，不另建孤立撤销栈 |
| `world_build` | 生成独立发布所需资源闭包 |

预览回复包含：任务身份、输入版本、受影响块、预计数量/资源、警告、不可满足约束及生成状态。原生 ACK 另含实际 manifestHash 与加载状态；服务端完成 cook 不等于原生画面已切换。

示例意图：“生成两公里山谷，东侧树林，中间一条河，道路沿河连接三个古风聚落。”AI 生成可编辑参数与区域建议；用户可以用同一画笔继续调整。没有合适桥梁或建筑资源时必须报告缺口，不臆造已存在资产。

## 14. 后续完整建筑专项

世界基础稳定后接入 Building Generator，采用建筑请求 → 柱网/占地 → 各层房间图 → 楼梯与通行 → 构件拼装 → 屋顶 → 家具/灯具的流程。

### 14.1 两层古风客栈基准

- 一层：大堂、柜台、用餐区、厨房、楼梯；二层：默认六间客房和公共走廊。
- 基于开间、进深、柱网约束尺寸；不允许无限拉伸门窗和柱子。
- 楼梯检查占地、净空、层高、上下入口与楼板开洞。
- 家具按房间类型与可用空间摆放，保留门扇、床边、柜前和主要通道空间。
- 装饰灯模型与实际灯光分离；受活动灯预算限制，远景不保留每盏独立动态灯。
- 自动布局和手画分区共享房间/连接图；锁定楼梯后只重解其余可变区域。
- 房间装不下时提供扩大占地、减少房间或调整层数的方案，不输出无法进入的房间。

完整室内不是早期世界生成的前置条件，但世界数据从第一版就应保存 buildingId、占地、入口和模板引用，避免日后全量迁移。远景建筑代理、近景外壳与室内分级加载，并保证切换时入口和碰撞一致。

## 15. 分阶段实施与完成门槛

### P0：契约、设备与最小原生骨架

任务：冻结坐标、ID、格式、库接口和预算；核实植被、水体、材质适配；建立原生编译器/运行库；256 m 世界空块保存加载。

完成：旧场景仍可加载；新 world 引用跨 JS、schema、C++ 和打包闭环；真实视口可显示一个生成块；确定性测试向量一致。

### P1：地形、俯视笔刷与保存闭环

任务：高度场分块、渲染/碰撞同源、拾取、升降/平滑/平整、预览、一次笔迹事务、撤销重做。

完成：画笔命中和原生画面一致；跨块无裂缝；角色可以跨块行走；保存重开与撤销恢复一致。

### P2：生态区与组件散布

任务：资源库标记、草地材质、草/树/岩石散布、约束/排除区、批处理、局部失效、锁定覆盖。

完成：同种子可复现；边界间距正确；重生成保留手工删除/移动；十万级候选不进入普通实体表。

### P3：河流、道路与基础聚落

任务：路径编辑、河床与水面、道路平整、交叉口、桥梁、地块与预制建筑，跨块依赖传播。

完成：河流/道路连续；桥梁可通行；建筑入口接路；失败约束可定位；道路编辑不全量重生成无关森林。

### P4：原生分块加载与 2 km 世界

任务：后台 I/O、上传、资源共享、LOD、碰撞预加载、fence 释放、任务取消与异常恢复。

完成：2 km 世界可持续漫游；内存和上传受预算约束；高速移动、传送、快速切项目不崩溃或踩空。

### P5：发布、AI 和大场景验收

任务：cook 资源闭包、独立包、AI 工具、8 km 压力档、性能实测、缓存失效和故障注入。

完成：无编辑器/Node/模型服务也能运行已发布世界；实测证据支持性能声明；原生视口、保存与发布世界一致。

### P6：完整客栈与住宅区深化

任务：模块化建筑库、柱网、多层布局、楼梯、室内陈设、分层编辑和建筑 LOD；验证单栋后用于区域生成。

完成：两层古风客栈各房间从入口可达、楼梯可走、家具不堵门；布局可编辑并可局部重生成；聚落按预算加载建筑与室内。

执行顺序 P0 → P1 → P2 → P3 → P4 → P5 → P6。P0 就建立分块接口，P4 完成运行时规模化，避免到最后再重写单体架构。

## 17. 诊断、故障恢复与安全边界

建议错误码：WORLD_SCHEMA_INVALID、WORLD_BUDGET_EXCEEDED、WORLD_ASSET_MISSING、WORLD_CONSTRAINT_UNSATISFIED、WORLD_CHUNK_CORRUPT、WORLD_TASK_STALE、WORLD_NATIVE_UNAVAILABLE；版本冲突复用既有 REVISION_CONFLICT。

诊断包含 taskId、layerId、featureId、chunk、阶段、输入版本、原因和建议操作；可以从错误定位到地图区域。

所有输入路径解析后必须落在当前项目允许目录；拒绝绝对外部路径、路径穿越及符号链接/目录联接逃逸。导入外部资源通过已有导入流程复制/转换到项目，再记录项目内引用。

worker 崩溃或块校验失败保持上一份完整世界可用。设备丢失后按当前清单重建 GPU 资源，不能重新随机生成布局。磁盘空间不足时拒绝提交并保留旧引用。缓存回收不得删除用户源资产。

## 18. 风险与落地决策

| 风险 | 实施规则 |
| --- | --- |
| 实体爆炸 | 静态生成物走分块实例，普通实体保留交互语义 |
